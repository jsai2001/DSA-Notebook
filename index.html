1. Two Sum Easy Array Hash Map
Key idea: For each number, look up its complement target - num in a hash map of values already seen. One pass, O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target.

  • Exactly one valid answer exists.
  • You can't use the same element twice.
  • Return the answer in any order.

Approach 1: Brute Force

Check every possible pair (i, j) with j > i and return the first pair whose sum equals the target.

Time O(n²) Space O(1)

Outer loop runs n times, inner loop about n/2 on average, so it's quadratic and can hit Time Limit Exceeded on large inputs. No extra data structures.

Approach 2: One-Pass Hash Map Optimal

Instead of rescanning earlier elements, remember them in a hash map of {value: index}. At each index i, compute complement = target - nums[i].

  • If the complement is already in the map, return [map[complement], i].
  • Otherwise, store nums[i] → i and keep going.
Time O(n) Space O(n)

Single pass, and hash map lookups and inserts are O(1) on average. In the worst case (pair at the very end) the map holds up to n elements.

Comparison

Approach Technique Time Space Notes
Brute Force Nested loops over all pairs O(n²) O(1) TLE risk on large inputs
One-Pass Hash Map Complement lookup in hash map O(n) O(n) Expected answer in interviews
2. Add Two Numbers Medium Linked List Math Recursion
Key idea: Digits are stored in reverse order, so the heads are the ones place. Walk both lists together like column addition: sum = a + b + carry, keep sum % 10, carry sum // 10. Use a dummy head node and keep looping while either list or the carry is left.

Problem View on LeetCode (opens in a new tab) ↗

You are given two non-empty linked lists representing two non-negative integers. The digits are stored in reverse order, and each node holds a single digit. Add the two numbers and return the sum as a linked list in the same format.

  • Each list has between 1 and 100 nodes.
  • Each node value is between 0 and 9.
  • No leading zeros, except for the number 0 itself.

Example: [2,4,3] + [5,6,4] is 342 + 465 = 807, so the answer is [7,0,8].

Approach 1: Three Loops with Trailing Node

Handle the lists in three phases, writing the result digit by digit into a pre-allocated node.

  • Loop 1: while both lists have nodes, add l1.val + l2.val + carry.
  • Loop 2 and 3: whichever list is longer, keep going with val + carry.
  • If a carry of 1 is left, write it into one more node.
  • After every digit a new empty node is created, so the list ends with one extra node. Track prev and set prev.next = None at the end to cut it off.
Time O(max(m, n)) Space O(max(m, n))

Each node is visited once. The space is the output list itself, so there are no extra data structures. The downside is the repeated code across the three loops and the extra trailing node that has to be trimmed.

Approach 2: Single Loop with Dummy Head Optimal

Same column addition, but merge the three loops into one. Keep looping while l1, l2 or carry is still present, and treat a missing node as the digit 0.

  • Start with a dummy node and a tail pointer. Return dummy.next.
  • Each step: total = carry + (l1 digit) + (l2 digit), append a node with total % 10, set carry = total // 10.
  • Including carry in the loop condition handles the final carry (like 5 + 5 = 10) without a special case.
  • Nodes are only created when needed, so there's no trailing node to trim.
Time O(max(m, n)) Space O(max(m, n))

Same complexity as Approach 1 (the output list is the only space used, extra space is O(1)), but shorter, with no duplicated loops and no prev bookkeeping.

Comparison

Approach Technique Time Space Notes
Three Loops with Trailing Node Both lists, then leftovers, then carry O(max(m, n)) O(max(m, n)) Works, but repeated code and a trailing node to trim
Single Loop with Dummy Head One loop; missing node or carry counts as 0 O(max(m, n)) O(max(m, n)) Cleaner, handles the final carry naturally
3. Longest Substring Without Repeating Characters Medium String Hash Map Sliding Window
Key idea: Sliding window. Move right one step at a time, and remember the last index of every character. If s[right] was seen inside the window, jump left to just past that index. The answer is the largest right - left + 1. One pass, O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given a string s, find the length of the longest substring that has no repeating characters.

  • 0 <= s.length <= 5 * 10^4
  • s is made of English letters, digits, symbols and spaces.
  • A substring is contiguous. In "pwwkew" the answer is 3 ("wke"), not 4 ("pwke" is a subsequence, not a substring).

Examples: "abcabcbb" → 3 ("abc"), "bbbbb" → 1, "" → 0.

Approach 1: Brute Force from Every Start

Try every starting index j. From there, extend i to the right while each new character hasn't been seen in this run, and stop at the first repeat.

  • A fresh hash map per start tracks characters in the current run.
  • tracker[i][j] holds the length of the run starting at j and ending at i, built from tracker[i-1][j] + 1. When i == j that cell is still 0, so it correctly starts at 1.
  • Keep the largest value seen in max_sub_len.
Time O(n²) Space O(n²)

The loops break at the first repeat, so each start only scans at most (charset size + 1) characters. But creating the n × n tracker table already costs O(n²) time and memory: for n = 5 × 10^4 that's 2.5 billion cells, which can hit Memory or Time Limit Exceeded. tracker[i][j] is always just i - j + 1, so the table can be dropped and replaced by that expression for O(1) extra memory. Also, naming a variable hash shadows Python's built-in hash().

Approach 2: Sliding Window with a Set

Restarting from every index throws away work. Instead, keep one window s[left..right] with no repeats and a set of its characters.

  • Move right forward one character at a time.
  • While s[right] is already in the set, remove s[left] and move left forward.
  • Add s[right] and update the best length right - left + 1.
Time O(n) Space O(min(n, m))

Each character enters and leaves the window at most once, so it's at most 2n steps. m is the charset size (the set never holds more distinct characters than that).

Approach 3: Sliding Window with Last-Seen Index Optimal

Rather than shrinking the window one step at a time, jump straight past the duplicate. Store {char: last index}.

  • If s[right] was last seen at index k >= left, set left = k + 1.
  • The k >= left check matters: an index from before the window is stale and must not move left backwards (for example "abba").
  • Record last[s[right]] = right and update the best length.
Time O(n) Space O(min(n, m))

Exactly one pass with O(1) work per character. In C++ and Java a fixed array of 128 slots works as the map, since the input is ASCII.

Comparison

Approach Technique Time Space Notes
Brute Force from Every Start Extend from each start until a repeat O(n²) O(n²) n × n table can exceed memory limits
Sliding Window with a Set Shrink from the left until no duplicate O(n) O(min(n, m)) Up to 2n steps; easy to reason about
Sliding Window with Last-Seen Index Jump left past the duplicate O(n) O(min(n, m)) Single pass; expected answer in interviews
