Execution role vs resource-based policy AWS Lambda

AWS Lambda › 5. Security and permissions › Execution role vs resource-based policy

Q43. What is the execution role, and what is a resource-based policy?

  • Execution role (identity-based, the IAM role the function assumes): defines what the function's code may do to other AWS services (read a DynamoDB table, write to S3). This is outbound permission.
  • Resource-based policy (attached to the function): defines who may invoke the function (for example "allow S3 bucket X to invoke me"). This is inbound permission.

Q44. How do you give a function access to an S3 bucket? Attach an IAM policy to the function's execution role that grants the needed S3 actions on the specific bucket or prefix (least privilege).

Q54. What is least privilege for Lambda IAM roles? Grant the execution role only the exact actions on the exact resources the function needs. No Action: "*" or Resource: "*". Scope to specific ARNs and prefixes and use conditions. This limits the blast radius if the function or its credentials are compromised.
