3.1 Hierarchical and DBSCAN ML Algorithms

ML Algorithms › 3. Other Clustering Algorithms & the Titanic Pipeline › 3.1 Hierarchical and DBSCAN

Because of the consistent interface, you can swap the class and keep the fit/predict/label code. Process for any algorithm: choose it, determine K (if needed), evaluate and explain. The source gives no code for these two.

Hierarchical clustering: start with every point as its own cluster, repeatedly merge the two closest, and record the merge distance. The dendrogram shows those distances; cut at a height to pick the number of clusters.

  • Pro: no K upfront; the dendrogram shows structure.
  • Con: slow, since it starts with one cluster per point, so it scales poorly.

DBSCAN (density-based): like moving a flashlight around the data. Nearby points keep extending the same cluster; when no more nearby points are found, the cluster ends. Points near nothing are noise/outliers.

  • Pro: arbitrary shapes (including clusters that wrap around others), robust to outliers.
  • Con: you must tune eps (neighbourhood radius) and min_samples.
