Protecting downstream systems and costs AWS Lambda

AWS Lambda › 7. Concurrency, scaling and limits › Protecting downstream systems and costs

Q65. How does Reserved Concurrency protect downstream resources such as databases? Capping a function's maximum concurrency limits how many simultaneous connections it can open to a fragile downstream, such as an RDS instance with few connections. This stops Lambda's rapid scaling from overwhelming the database. Pair it with RDS Proxy for pooling.

Q69. What if one function monopolizes all unreserved concurrency? Other functions get throttled because they compete for the same shared pool. Set reserved concurrency on high-traffic functions (to cap them) and reserve concurrency for critical functions so they always have headroom. For example, with a 1,000 pool: a critical function reserved 200 (guaranteed and capped), a batch function reserved 100, and the remaining 700 unreserved are shared by everything else.

Q70. How do you prevent runaway cost from recursive loops? Lambda has built-in recursive loop detection (for example Lambda to SQS/SNS to the same Lambda) that stops the loop and notifies you. Also set reserved concurrency to cap the blast radius, add CloudWatch billing and concurrency alarms, avoid a function writing to its own trigger source, and use idempotency plus circuit breakers.
