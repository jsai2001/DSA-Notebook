Q77. How does Lambda integrate with DynamoDB Streams for change data capture? Enable a stream on the table. An event source mapping polls it and invokes Lambda with ordered batches of change records (INSERT/MODIFY/REMOVE, with old and new images). Use it for CDC, replication, aggregations, notifications and materialized views.

Q78. What is Lambda@Edge, and how does it differ from standard Lambda? Lambda@Edge runs functions at CloudFront edge locations, close to users, on CloudFront events (viewer or origin request and response). It customizes or inspects HTTP at the edge (redirects, header changes, A/B tests, auth). Compared with standard Lambda it is replicated globally to the edge, has tighter limits (size, timeout, no VPC or env vars) and supports only Node.js and Python.

Q79. What are CloudFront Functions, and how do they compare with Lambda@Edge? CloudFront Functions are very lightweight JavaScript functions that run at the edge on viewer request and response, with sub-millisecond startup, massive scale and very low cost, but tight constraints (very short runtime, tiny memory, no network or file access). Use them for simple high-volume tasks (header rewrites, redirects, token checks). Use Lambda@Edge when you need more compute, longer execution, network calls or origin-event access.
