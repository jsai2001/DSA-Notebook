Model Context Protocol › 6. Testing with MCP Inspector and Troubleshooting › Logs and debugging workflow

  • Settings -> Developer shows each server's status ("Failed"/"Disconnected"). Open Logs Folder has one file per server, such as mcp-server-weather.log.
  • Log example for this error: [ERROR] UV returns error no entity, [ERROR] spawn uv ENOENT, [ERROR] Unable to start MCP server.
  • Workflow: check status, open the log, find [ERROR] lines, check claude_desktop_config.json (command path, args, env), run the command manually in a terminal (/path/to/uv run server.py; if it works, the config is the problem), then restart and verify.
  • Other tools: Chrome DevTools (client interactions), server-side logging, Claude Desktop logs, and modelcontextprotocol.io/docs/debugging.

Config best practice: absolute paths for command, --directory for the project, and env for secrets (full example in section 7). Checklist when a server fails: status, logs, absolute command path, manual run, venv/dependencies, API keys, restart, Inspector first.
