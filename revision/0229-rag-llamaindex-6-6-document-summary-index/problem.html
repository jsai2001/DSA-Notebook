6.6 Document Summary Index RAG with LlamaIndex

RAG with LlamaIndex › 6. Advanced RAG: Pre-Retrieval & Indexing › 6.6 Document Summary Index

Embed document summaries and link them to their chunks. Limits of chunk-only retrieval: chunks lack global context, similarity thresholds need tuning, embeddings may miss relevance, keyword filtering has its own problems. The index stores an LLM summary per document, the document's text chunks, and a mapping between them. Retrieval operates at the document level first, then synthesizes over the linked chunks (different optimal representations for retrieval vs synthesis).

The high-level as_query_engine() route uses embedding-based retrieval by default. The low-level retrievers allow either mode:

LLM-based (DocumentSummaryIndexLLMRetriever)Embedding-based (DocumentSummaryIndexEmbeddingRetriever)
Selects byLLM scores summaries in batches (choice_batch_size, default 10; choice_top_k, default 1)Cosine similarity of query vs summary embeddings (similarity_top_k)
Speed / costSlower, more expensiveFaster, cheaper
QualityHigher via LLM reasoningDepends on embedding quality
Custom hookschoice_select_prompt, format_node_batch_fn, parse_choice_select_answer_fnsimilarity_top_k

The retrievers also support adding/deleting documents from the index.
