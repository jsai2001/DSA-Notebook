9. Gotchas & Version Notes LangGraph

LangGraph › 9. Gotchas & Version Notes

  • Versions matter. The notebooks pin langgraph==0.2.59, langchain==0.3.12. create_react_agent(..., state_modifier=...) is the argument name in that version; newer LangGraph releases renamed it to prompt. Match the pinned versions when running the course code.
  • Tool docstrings are the tool's API for the LLM. Vague docstrings give wrong tool choices. Retriever tool description plays the same role.
  • Tool return conventions: the course uses -1 for "not found" so the LLM can tell the user clearly.
  • Annotated[list, operator.add] is what makes state updates append. Without a reducer a node's return value replaces the field.
  • Thread ID = conversation. MemorySaver is in-process and lost on restart. Reuse the same thread_id for follow-ups, use a new one per user conversation. The router graph has no checkpointer and forwards the thread ID to inner agents.
  • Agent state vs conversation memory (section 2.4): per-prompt, internal, discarded vs session-long, owned by the chatbot, persisted.
  • Cap loops. ReAct and reflection both loop; use an iteration limit (max_iterations, message-count check) to avoid infinite cycles.
  • Router prompt/key coupling. A router that returns the raw LLM text as the edge key breaks on any wording drift. Constrain the output to one word, or normalize in find_route.
  • Streaming vs invoke. stream(..., stream_mode="values") shows each step as it happens; invoke returns only the final state.
  • Notebook quirks: call_tools returns inside its for loop (handles only the first tool call); chunk settings differ between lesson (overlap=100, k=3) and notebook (overlap=256, k=1); the notebooks contain a hard-coded Azure key, so use your own environment variables.
