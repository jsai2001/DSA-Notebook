4. Batch Pipeline: Warehouse Stock Aggregation Apache Spark

Apache Spark › 4. Batch Pipeline: Warehouse Stock Aggregation

Use case: An enterprise has warehouses worldwide, each with its own stock app and local MariaDB (warehouse_stock.item_stock: opening stock, receipts, issues per item per day). Goal: a consolidated central stock database, collected daily, scalable to hundreds of warehouses.

Architecture:

  • Each warehouse runs a Stock Upload Job daily on its local Spark cluster. It reads the local MariaDB and writes Parquet to the central file system (HDFS/S3; local raw_data/ is the proxy).
  • Parquet is columnar and efficient for parallel reads. The folder structure is partitioned by STOCK_DATE then WAREHOUSE_ID.
  • After uploads complete, the Stock Aggregator Job on the central Spark cluster reads all Parquet, aggregates with Spark SQL, and writes to the global_stock MariaDB.
  • Flow: Acquire (local MariaDB) -> Transport (Parquet to central FS) -> Consolidate (Spark SQL GROUP BY) -> Persist (global MariaDB). Prune raw_data/ after processing.

Notebook: code_03_XX_Spark_BDE_Batch_Data_Engg.ipynb.
