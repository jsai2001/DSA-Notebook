Collection schema Vector Databases

Vector Databases › 5. Milvus objects › Collection schema

A collection has a schema of scalar + vector fields, exactly one primary key, optional dynamic fields.

  • FieldSchema parts: name, dtype, is_primary, max_length (required for VARCHAR), dim (vector).
  • Vector dim must equal the embedding model's output and cannot change later. Check with len(embeddings_model.embed_query("test")).
  • shard_num: DML parallelism (small data 1-4, large 4-16).

Primary key: one scalar field, unique, can be auto-generated.

Dynamic fields: extra ad hoc fields supplied at insert time with enable_dynamic_field=True (flexible, may cost performance; enable only if needed).

Collection operations

Schema modification restrictions: you cannot change field types, names, the primary key, vector dimension, or remove fields. Workaround: create a new collection with the new schema, migrate data, drop the old one. (You can add dynamic fields at insert and edit the description.)
