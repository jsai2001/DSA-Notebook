Challenge: Maven test report and JAR artifact Jenkins

Jenkins › 10. Artifacts, Fingerprints and Test Reports › Challenge: Maven test report and JAR artifact

Goal: for a Java app, run tests and publish a JUnit report, build a JAR and archive it only when tests pass, without failing the build when results or artifacts are absent. Configure Maven under Global Tool Configuration (for example Maven 384), confirm the JUnit plugin is installed, and use the Declarative Directive Generator (Tools) and the snippet generator (junit, archiveArtifacts) to produce the pieces.

How the post block works:

  • always runs regardless of success, failure or unstable.
  • junit testResults takes an Ant-style pattern; **/ searches all directories. allowEmptyResults: true keeps a missing report from failing the build.
  • archiveArtifacts with allowEmptyArchive: true does not fail when no JAR exists; onlyIfSuccessful: true archives only from successful runs; fingerprint: true stores an MD5 so the artifact can be tracked across jobs (see See Fingerprints).

The first run is slow because Maven is installed. A successful build shows an artifact icon for the JAR, and repeated builds extend the test trend graph.
