Q. What is the difference between matrix-based security and Role-Based Access Control (Role Strategy plugin)?

  • Matrix-based: a global grid mapping users and groups to permissions. Simple, but it does not scale because every user needs a row.
  • Role Strategy (RBAC): define reusable roles (global plus per-project or folder patterns) and assign users or groups to them; far more scalable for many users and teams.

Configure matrix security:

  1. Manage Jenkins, Manage Users: create users (username, password, name, email).
  2. Manage Jenkins, Configure Global Security: switch from "Logged-in users can do anything" to Matrix-based security.
  3. Add your admin account and tick Administer. Add other users with specific permissions such as Overall Read (interact with the UI) and Job Build, Cancel, Read.
  4. Save, then log in as the restricted user and confirm there is no management menu and only limited job actions.

Best practice: limit admin access to one or two users on a shared system and give everyone else role-based permissions. Always grant your own account Administer before saving, because locking yourself out is common (the Jenkins docs explain how to disable access control to recover).
