Angular › 12. Change Detection and Lifecycle Hooks › Change detection

How Angular checks application state and updates the UI. Two strategies set through changeDetection:

StrategyBehavior
Defaultruns on data mutation inside objects and arrays, property redefinition, and events (API calls, click handlers). Starts at the root component, compares the new state tree to the old with strict equality, and reruns only what changed. Works everywhere, but checks all components, so it is slower with many components
OnPushskips the component and its sub-tree unless a property is redefined, an event fires, or change detection is called manually. Faster, but requires immutable data (never mutate in place)

Use OnPush for components with many children, immutable data, and where performance matters.

HighScoresComponent in section 6 is a working OnPush example: players$ is declared once, set once in ngOnInit, never mutated.

OnPush + async pipe is the best pairing: the observable emits a new reference and the async pipe triggers detection, so no manual change detection is needed.
