Logs, metrics and X-Ray AWS Lambda

AWS Lambda › 9. Monitoring, logging and testing › Logs, metrics and X-Ray

Q81. Where are Lambda execution logs stored by default? In Amazon CloudWatch Logs, in a log group named /aws/lambda/<function-name>, split into log streams per execution environment. Anything printed (console.log, print, stdout and stderr) plus the automatic START/END/REPORT lines land there. The execution role needs logs:CreateLogGroup, logs:CreateLogStream and logs:PutLogEvents.

Q82. Which CloudWatch metrics does Lambda publish automatically? Invocations, Errors, Duration, Throttles, ConcurrentExecutions, DeadLetterErrors, IteratorAge (streams), ProvisionedConcurrency* metrics and Async* event metrics. From them you derive error rate, latency percentiles and concurrency headroom.

Q83. What is AWS X-Ray, and how do you trace a function? X-Ray is a distributed tracing service. Enable Active Tracing on the function. Lambda emits a trace segment per invocation, and the X-Ray SDK auto-instruments downstream calls (DynamoDB, HTTP and so on) as subsegments. You see the end-to-end request path and latency bottlenecks and errors on a service map.
