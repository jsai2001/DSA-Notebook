Logging and metrics FastAPI

FastAPI › 6. Production-Ready Code › Logging and metrics

  • Metrics answer "what is happening now?" (request count, error rate, query latency). Tools: Prometheus, OpenTelemetry, Datadog.
  • Logging answers "how did we get here?" (incidents, debugging). Use Python's built-in logging.
  • If logs don't help in development, they won't help during a 4 a.m. incident.
  • Configure logging as early as possible (ideally from config). In code review ask: should we log here, at what level, with what info? Log enough to reproduce (e.g. query parameters). Format fields: see the LogRecord attributes.

Middleware runs around every HTTP request; call_next invokes the next middleware or the handler. Prefix metric lines ([metric:call.duration]) so a collector can parse and forward them.
