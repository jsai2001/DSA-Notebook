Executors, labels and agent protocols Jenkins

Jenkins › 1. Jenkins Fundamentals and Architecture › Executors, labels and agent protocols

Q. What is a Jenkins executor, and how many per agent? An executor is a slot on a node that runs one build at a time; a node with N executors runs N concurrent builds. Rule of thumb: about one executor per CPU core, fewer for memory-heavy or I/O-heavy builds. Too many causes contention or OOM; too few wastes capacity. Keep the controller's executors at 0.

Q. What are Jenkins labels? Tags assigned to agents (for example linux, docker, maven). A pipeline requests a label so the build runs only on matching agents. Labels support expressions such as linux && docker.

Q. How does Jenkins authenticate agents, and which protocols are used?

  • SSH: the controller connects out to the agent using SSH credentials (controller-initiated).
  • Inbound (JNLP): the agent connects in to the controller using a secret or agent token (agent-initiated; good behind NAT or firewalls).

Agents are validated through these secrets and keys, and you can also lock down which agent commands the controller trusts.

Q. What are the default ports? Web UI: 8080 (HTTP). The inbound (JNLP) agent port is configured separately (often 50000) under Manage Jenkins, Security; it can be fixed or random.
