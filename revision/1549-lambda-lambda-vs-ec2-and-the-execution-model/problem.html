Lambda vs EC2 and the execution model AWS Lambda

AWS Lambda › 1. What Lambda is › Lambda vs EC2 and the execution model

Q1. What is AWS Lambda, and how does serverless compute differ from EC2? Lambda is a serverless, event-driven compute service that runs your code in response to events without you provisioning or managing servers. You upload code, define a trigger, and AWS handles the servers, scaling, patching and availability. With EC2 you rent and manage a server (OS, scaling, patching) and pay while it runs. With Lambda you pay only per request and per ms of execution, it scales to zero when idle, and it scales out automatically per request.

Q3. Explain the concept of event-driven execution in Lambda. Lambda runs only when an event occurs: an HTTP call via API Gateway, an object uploaded to S3, a message in SQS, a DynamoDB stream record or a scheduled EventBridge rule. Each event reaches the handler as the event object. No event means no execution and no cost.

Q4. What is the execution model of AWS Lambda (stateless compute)? Each invocation is stateless. Do not rely on in-memory data persisting across requests, because AWS may create a fresh execution environment at any time. Keep state in external stores (DynamoDB, S3, RDS, ElastiCache). The environment can be reused for warm invocations, so anything outside the handler (SDK clients, connections) can be cached opportunistically.
