Concurrency limits and throttling AWS Lambda

AWS Lambda › 7. Concurrency, scaling and limits › Concurrency limits and throttling

Q59. What is the default regional concurrency limit in a new account? 1,000 concurrent executions per region (a soft limit, raised through a Service Quotas request), shared across all functions in that region and account.

Q60. Reserved Concurrency vs Provisioned Concurrency?

  • Reserved Concurrency carves out a guaranteed slice of the account limit for one function and also caps that function at that number. It manages how much concurrency a function can use, at no extra cost.
  • Provisioned Concurrency pre-warms N environments so invocations skip cold starts. It manages latency and readiness, and you pay for the pre-warmed capacity.

Q61. What happens when a function exceeds its concurrency limit? Lambda throttles: it rejects extra concurrent invocations with a 429 TooManyRequestsException (ThrottleReason). What happens next depends on the invocation type.

Q62. How do sync calls react to throttling vs async calls?

  • Synchronous: the caller immediately gets a 429 and must handle or retry it (API Gateway surfaces a 5xx or 429 to the client).
  • Asynchronous: Lambda keeps the event in its internal queue and retries for up to about 6 hours with backoff. If it never succeeds, the event goes to the DLQ or on-failure destination. Async throttling is largely absorbed, while sync throttling is felt by the caller.

Q66. What status code does a throttled synchronous API Gateway request return? Lambda returns 429 TooManyRequestsException. Depending on integration config, API Gateway may show the client a 429, or a 502/500 if not mapped. The Lambda-level reason is a throttle.
