Q. What is the difference between launch methods?

  • Launch agent via SSH: the controller SSHes out to start the agent. Simple for Linux hosts the controller can reach.
  • Launch agent by connecting it to the controller (Inbound/JNLP): the agent runs agent.jar and initiates the connection. Good behind NAT or firewalls, and for Windows.
  • Cloud plugins: Kubernetes, EC2 or Docker create agents on demand.

The choice depends on network reachability, OS and whether agents are static or dynamic.

Q. How do you set retention strategies for dynamic agents? They control the agent lifecycle: Always (keep up), Demand (start when needed), Idle timeout (terminate after N idle minutes), or plugin-specific strategies. Short idle timeouts minimize cloud cost, and a small warm pool reduces cold-start latency.

Q. What does Node Offline mean, and what causes disconnects? The controller lost contact with a node and cannot schedule builds there. Common causes: network or firewall issues, agent process crash or OOM, disk full on the agent, Java version mismatch, an expired credential or secret, or the node being taken offline for maintenance.
