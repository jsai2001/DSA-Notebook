Reusing state across warm invocations AWS Lambda

AWS Lambda › 3. Execution lifecycle, cold starts and performance › Reusing state across warm invocations

Q20. How does global variable initialization work between warm invocations? Variables initialized outside the handler live in the execution environment and persist across warm invocations. That is how you cache SDK clients, DB connections and config. Do not rely on it for correctness (environments are transient), but use it for performance.

Q21. Why instantiate DB connections or SDK clients outside the handler? Init runs once per environment and the objects are then reused across warm invocations. Creating a connection or client inside the handler rebuilds it on every request, adding latency and risking connection exhaustion.

Q28. How do you reuse HTTP connection pools across invocations? Create the HTTP client or agent outside the handler so keep-alive pools survive warm invocations. For the AWS SDK, keep-alive is the default in SDK v3 and is enabled by AWS_NODEJS_CONNECTION_REUSE_ENABLED=1 in v2.
