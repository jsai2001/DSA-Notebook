Q6. How does Lambda scale under the hood when traffic spikes? Lambda creates a new execution environment per concurrent request. When requests arrive faster than existing environments free up, it adds more, up to your concurrency limit. Scaling starts with an initial burst capacity, then continues at a controlled rate (for example 500 additional environments per function per minute in supported regions) until it reaches the account or function limit.

Q7. What is Firecracker, and how does AWS use microVMs for Lambda? Firecracker is AWS's open-source virtualization technology that launches lightweight microVMs in milliseconds. Lambda uses microVMs to give each execution environment strong VM-level isolation between functions and accounts while keeping startup fast and memory overhead tiny. It combines container-like speed with VM-like security.

Q8. What is the difference between an event source mapping and a direct trigger? A direct trigger is a service invoking Lambda by calling the Lambda API (push model), for example API Gateway, S3 or SNS. An event source mapping (ESM) is a Lambda-managed poller that pulls records from a source (SQS, Kinesis, DynamoDB Streams, Kafka), batches them and invokes your function. With an ESM, Lambda owns the polling loop. With a direct trigger, the source pushes.
