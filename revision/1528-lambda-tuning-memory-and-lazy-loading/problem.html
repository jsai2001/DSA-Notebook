Tuning memory and lazy loading AWS Lambda

AWS Lambda › 3. Execution lifecycle, cold starts and performance › Tuning memory and lazy loading

Q22. How does memory affect CPU, network bandwidth and cost? Memory is the one dial that also scales CPU and network proportionally. More memory means more vCPU and bandwidth and often faster execution. Cost per ms rises with memory, but faster completion can lower total GB-seconds, so tuning memory can reduce both latency and cost.

Q23. What tool tunes a function's memory (for example AWS Lambda Power Tuning)? AWS Lambda Power Tuning is a Step Functions state machine that runs the function at several memory settings and charts cost against speed so you pick the sweet spot. You can also compare CloudWatch REPORT logs (Max Memory Used, Duration) across settings.

Q27. How does lazy vs eager loading of libraries affect execution time? Eager loading (importing everything at Init) lengthens cold starts but makes every invoke fast. Lazy loading (importing a heavy module only when a code path needs it) shortens cold starts and avoids paying for libraries you rarely use, at the cost of a one-time hit on the first invoke that needs them. Choose by how often each path runs.
