Backup, migration and restarts Jenkins

Jenkins › 1. Jenkins Fundamentals and Architecture › Backup, migration and restarts

Q. How do you back up and restore a Jenkins instance? Manual: stop or quiesce Jenkins and archive JENKINS_HOME (at minimum config.xml, jobs/, users/, secrets/, credentials.xml, plugins/). To restore, put it back and restart. With plugins: ThinBackup (scheduled full or incremental), or keep config in JCasC plus jobs as code so the instance is reproducible.

Q. How do you move jobs from one Jenkins instance to another? Copy the job folder under jobs/<name>/ (with config.xml) to the new controller and reload; use the Jenkins CLI (get-job / create-job); use the Job Import plugin; or, best, keep jobs as Jenkinsfile and JCasC so migration is just pointing the new controller at the repos.

Q. What is the difference between soft reload (/reload) and safe restart (/safeRestart)?

  • /reload re-reads config from disk into memory without restarting the JVM (fast; use after editing config on disk).
  • /safeRestart waits for running builds to finish, then restarts the JVM, so no builds are killed.
  • /restart restarts immediately.

Q. What is the System Log for, and where do you configure custom log recorders? The System Log surfaces controller and plugin logging for diagnostics. Under Manage Jenkins, System Log you can add custom Log Recorders that capture specific loggers (by package or class) at chosen levels, which helps debug one plugin without drowning in global logs.
