Running scripts from a pipeline Jenkins

Jenkins › 5. Triggers and SCM Integration › Running scripts from a pipeline

Keep complex build logic in scripts stored in the repo so the pipeline stays clear and easy to debug.

  • sh: run commands or scripts with the default shell on Linux, Unix or macOS.
  • bat: the Windows equivalent.
  • dir: change the working directory for the steps inside it, with a path relative to the workspace or absolute. ${WORKSPACE} gives the checkout directory.
  • Use relative paths for scripts inside the repo and absolute paths for scripts outside the workspace, in the format the agent OS expects.

Run the job once so Jenkins registers the parameter, then use Build with Parameters (for example 60). If a stage fails, check that the script is executable and the path matches the agent's OS. All stages should print identical output.
