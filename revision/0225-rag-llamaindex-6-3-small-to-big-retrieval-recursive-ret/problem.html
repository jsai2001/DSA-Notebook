6.3 Small-to-big retrieval (recursive retrieval) (1/2) RAG with LlamaIndex

RAG with LlamaIndex › 6. Advanced RAG: Pre-Retrieval & Indexing › 6.3 Small-to-big retrieval (recursive retrieval)

Retrieve small, query-specific chunks, then follow references to larger parent chunks (or inject surrounding context) so the LLM gets both precision and context. Three parts: recursive retrieval, node post-processing, response synthesis.

Option A: sentence window. SentenceWindowNodeParser makes one node per sentence and stores a window of surrounding sentences in metadata (window_size sentences each side; the sentence itself under original_text). Both are excluded from what the embedding model and LLM see by default, so only the single sentence is embedded. Splitting uses NLTK Punkt. At query time MetadataReplacementPostProcessor swaps the sentence for its window before the LLM sees it.

Note: the notebook sets window_metadata_key="window_size" while the post-processor targets "window" (the parser's default key); keep the keys consistent when you write your own.

Option B: parent-child chunks. Smaller child chunks (several sizes) point to a bigger parent via IndexNode. Retrieval matches a small child, then follows the reference to the parent.
