Three components of RAG data preprocessing:

ComponentWhat it is
ChunkingBreaking big text into smaller blocks
EmbeddingsVectors from embedding models; semantic meaning in quantifiable form
MetadataData stored alongside embeddings; critical for customizable RAG apps

Why chunk: humans read one coherent sentence or paragraph at a time, and LLMs work the same way. The context window (max tokens an LLM handles at once; GPT-4 Turbo ~128k) is a cap, not the ideal amount.

Dense vs sparse embeddings (RAG mostly uses dense):

TypeDescriptionCreated by
DenseFew values are zeroML models
SparseMany values (>50%) are zeroAlgorithms (TF-IDF, BM25)

Metadata basics: it must include the original text, because vector DBs retrieve by similarity and an LLM cannot turn embeddings back into text. Its main use is filtering searches before similarity comparison.

TypeExamples
Processing metadataSection title, paragraph number, chunk location
Data metadataEmbedded text itself, publication date, author
