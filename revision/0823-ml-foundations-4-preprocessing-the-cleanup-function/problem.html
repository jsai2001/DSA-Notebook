ML Foundations › 4. Preprocessing: the Cleanup Function

Why preprocess: most algorithms need numeric input, features should be on a similar scale, and raw data has wrong types, placeholder values, or useless columns.

Two phases: (1) a cleanup function (fix types, bad values, select columns); (2) sklearn pipelines (scale, impute, encode), covered next.

StepWhy
zipcode: int to String to CategoricalZipcode is an identifier. Left numeric, algorithms infer a false ordering (higher/lower)
date: combine year/month/dayOne proper date column. Models can't use raw dates, so extract features (month, weekday) later if needed
yr_renovated: replace 0 with None0 means "never renovated," not "year 0." Null lets imputation handle it properly
explicit .select([...]) at the endReadable, maintainable, shows exactly which features are in play

Practices:

  • Keep raw data so predictions can be traced back for explainability.
  • Build the function incrementally, then move it to the top of the notebook (load raw, run cleanup, ready).
  • Preprocessing's job is to get data into a correct, honest state. Scaling and encoding happen in the pipeline.
