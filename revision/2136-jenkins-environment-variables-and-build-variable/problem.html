Q. How do you define environment variables globally and at stage level? Use an environment block at pipeline level (all stages) or inside a stage (that stage only). Reference with ${VAR} or env.VAR.

  • Name variables in capitals (MAX_SIZE) to tell them apart from lowercase keywords.
  • In strings prefix with $ ($VAR or ${VAR}), and stay consistent in the style you pick.
  • A stage-level definition overrides the global one for that stage only.

The first stage prints 10 and 1, the second prints 100 and 10. The Pipeline Steps view shows each step's output clearly.

Current build variables are properties of the currentBuild object, accessed as currentBuild.PROPERTY (case-sensitive CamelCase): currentBuild.startTime, currentBuild.duration, currentBuild.currentResult. Use them for decisions based on build state, for example echo "Build duration: ${currentBuild.duration}". The full list of default environment and currentBuild variables is under Pipeline Syntax, Global Variables Reference.
