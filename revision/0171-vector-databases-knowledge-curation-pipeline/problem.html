Vector Databases › 10. Use case 2: RAG concepts › Knowledge curation pipeline

Data sources -> acquisition and filtering -> standardization -> chunking -> embedding -> store in knowledge base.

  1. Sources: websites (HTML), ticketing systems, databases, document hubs (SharePoint, Drive), PDFs/DOCX. Structures differ widely.
  2. Acquisition module: fetch, filter relevant data, cleanse noise, handle incremental updates (initial load, then monitor source changes and fetch only new/updated).
  3. Standardization: uniform structure; segregate structured data into scalar fields, unstructured text into vector fields, metadata into filter fields.
  1. Chunking: vector fields have size limits, and retrieving only relevant portions improves precision. Use overlap to keep context across chunks; preserve sentence boundaries; keep metadata (e.g. doc_id) with each chunk.

  1. Embedding: same model for curation and inference; consistent dimensions; batch for efficiency.
  2. Store: insert (or upsert to avoid duplicates and handle document updates), then flush.
  • Entity per chunk: {id, chunk, embedding, doc_id}.
  • Advanced / ensemble knowledge base: vector DB (semantic) + RDBMS (structured) + knowledge graph (relationships, e.g. Neo4j).
  • Curate: include accurate, current, relevant, structured content; exclude outdated, irrelevant, duplicate, low-quality sources.
