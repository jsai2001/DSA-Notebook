AWS Lambda › 9. Monitoring, logging and testing › Testing locally and handling crashes

Q87. How do you unit test Lambda functions without calling AWS? Keep business logic separate from the handler and test it directly. Mock AWS SDK calls with moto (Python) or aws-sdk-client-mock (JS), and pass a fake event and context. This runs fast in CI with no real AWS calls.

Q88. What local emulation tools exist (SAM CLI, LocalStack)?

  • AWS SAM CLI: sam local invoke and sam local start-api run the function or API in a Docker container that emulates the Lambda runtime.
  • LocalStack: emulates many AWS services (S3, DynamoDB, SQS, Lambda) locally for integration tests.
  • Also serverless-offline and direct handler calls in unit tests.

Q89. How do you handle unhandled exceptions or crashes? Unhandled exceptions are logged to CloudWatch with the stack trace and increment the Errors metric. For sync calls the error returns to the caller. For async calls it triggers retries, then the DLQ or destination. Best practice: wrap handler logic in try/except, log structured errors, and let genuinely retryable failures throw so Lambda's retry and DLQ machinery engages.

Q90. How do CloudWatch Logs Insights queries help diagnose latency or failures? Logs Insights queries log groups with a purpose-built language to filter, aggregate and sort: find the slowest invocations, count errors or extract fields from JSON logs, far faster than scrolling streams.
