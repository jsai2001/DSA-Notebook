Angular › 12. Change Detection and Lifecycle Hooks › Lifecycle hooks

Run code at specific moments of a component or directive lifecycle. Implement the matching interface from @angular/core (autocomplete, type safety, compile checks; optional but recommended) and add the public method.

HookWhen
ngOnChangesinput properties change
ngOnInitonce, after construction, with injected dependencies and inputs available
ngDoCheckevery change detection run
ngAfterContentInitafter projected content is initialized
ngAfterContentCheckedafter content is checked
ngAfterViewInitafter the view is initialized
ngAfterViewCheckedafter the view is checked
ngOnDestroyjust before destruction

Order: constructor, ngOnChanges (if inputs), ngOnInit, ngDoCheck, ngAfterContentInit, ngAfterContentChecked, ngAfterViewInit, ngAfterViewChecked. On updates: ngOnChanges, ngDoCheck, ngAfterContentChecked, ngAfterViewChecked. Finally ngOnDestroy.

  • ngOnInit (most common): initialization and API calls. Prefer it over the constructor, which should only inject dependencies and do trivial assignments, because ngOnInit is guaranteed access to the injector and inputs. Example in section 4.
  • ngOnDestroy (second most common): clean up by unsubscribing, stopping timers, unregistering callbacks.

Several hooks: implements OnInit, OnDestroy, AfterViewInit, then add each method.
