Ways to trigger a job Jenkins

Jenkins › 5. Triggers and SCM Integration › Ways to trigger a job

Q. What are the ways to trigger a Jenkins job?

  • Webhooks: the SCM pushes an event and the build starts instantly (best).
  • Poll SCM: Jenkins periodically checks the repo for changes.
  • Scheduled (cron): build on a time schedule regardless of changes.
  • Remote API or token: trigger over HTTP (buildWithParameters).
  • Upstream: build after another project completes.

Q. What is the difference between pollSCM and cron? pollSCM('schedule') checks SCM on that schedule and builds only if there are changes. cron('schedule') builds unconditionally on the schedule (nightly jobs). Use H (hash) to spread load and avoid every job firing on the hour.

Q. How do GitHub or GitLab webhooks trigger builds instantly? The SCM sends an HTTP POST to Jenkins (/github-webhook/ or the GitLab hook URL) on push or PR events. Jenkins matches it to jobs watching that repo and builds immediately, which is faster and cheaper than polling.
