A slow third-party API AWS Lambda

AWS Lambda › 12. Scenario-based questions › A slow third-party API

Q100. A third-party API called by Lambda takes 30 seconds and causes timeouts. How do you make it asynchronous? Decouple the slow call from the caller. Accept the request, enqueue it (SQS, EventBridge or Step Functions) and return 202 Accepted with a job id. A worker Lambda calls the third-party API. Use Step Functions with a WaitForTaskToken callback or polling pattern for long waits. Store the result (DynamoDB or S3) and notify through a webhook or SNS, or let the client poll a status endpoint. This removes the synchronous 30 s wait and its timeout risk.

Flow: client calls API Gateway, a Lambda enqueues the job and returns 202 with a job id, SQS feeds a worker Lambda that calls the slow API and writes the result to DynamoDB, and the client polls GET /status/{jobId} (or receives an SNS or webhook callback).
