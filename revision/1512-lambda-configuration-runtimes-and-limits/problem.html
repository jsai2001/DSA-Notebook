Configuration, runtimes and limits AWS Lambda

AWS Lambda › 1. What Lambda is › Configuration, runtimes and limits

Q2. What are the core components of an AWS Lambda function configuration? Handler (entry point), runtime (execution environment), execution role (IAM permissions), memory (128 MB to 10,240 MB, which also sets CPU), timeout (up to 15 min), the deployment package (zip or container image), environment variables, trigger or event source config, concurrency settings, layers, ephemeral /tmp storage size and optional VPC config.

Q5. Which native runtimes does Lambda support out of the box? Node.js, Python, Java, .NET (C#), Ruby and Go (via the provided runtime family). Anything else runs through Custom Runtimes using the Runtime API, or by packaging an OCI container image.

Q9. What is the max execution timeout for a single invocation? 900 seconds (15 minutes).

Q10. What is the maximum payload size for synchronous vs asynchronous calls? Synchronous: 6 MB request/response. Asynchronous: 256 KB event payload.

Q11. How does the pricing model work? You pay for (a) the number of requests and (b) GB-seconds = allocated memory (GB) x execution duration (billed per 1 ms). More memory costs more per ms but can finish faster. There is a monthly free tier. Provisioned Concurrency and ephemeral storage above the default are billed separately.

Q12. What is the default /tmp storage and its maximum? Default 512 MB, configurable up to 10,240 MB (10 GB). It is scratch space that may persist across warm invocations but is not durable.
