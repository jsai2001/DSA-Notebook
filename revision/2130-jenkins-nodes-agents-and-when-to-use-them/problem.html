Nodes, agents and when to use them Jenkins

Jenkins › 8. Agents and Distributed Builds › Nodes, agents and when to use them

The controller provides the web UI for managing the server. Keep jobs off it to free CPU, memory and disk for scheduling and management. A node is a server connected to Jenkins; the agent is the process on it that runs job commands and reports status back. The two terms are often used interchangeably.

Types of agents:

  • SSH node: connects with a user and SSH key. Secure and good for nodes outside the controller's network. Needs SSH access, a user and key for Jenkins, and a recent Java (the agent is a Java app). Works on any OS with SSH and Java.
  • Docker agent: each build runs in a new container, giving a fresh isolated environment. Needs Docker on the node.
