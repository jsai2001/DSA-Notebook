Batch vs real-time: choosing Apache Spark

Apache Spark › 6. Best Practices › Batch vs real-time: choosing

Real-time challenges:

  • Unbounded datasets make it hard to size memory and clusters.
  • Windowing and watermarks can cause missed events and wrong aggregations.
  • State must be maintained correctly across the cluster.
  • Reprocessing is not a rerun: checkpoints, state and offsets must be reset.
Choose real-time whenChoose batch when
Responses/actions are required within secondsLatency of minutes/hours is acceptable
Input is a continuous stream of eventsHeavy aggregation and analytics
Minimal aggregation (more steps add watermark/state complexity)Simpler to implement, debug and reprocess
Compute resources are sufficient

Hybrid pipelines (part batch, part real-time) are possible. Use real-time only when the use case demands it.
