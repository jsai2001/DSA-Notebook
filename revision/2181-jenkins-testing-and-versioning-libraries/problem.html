Q. How do you unit test shared libraries? JenkinsPipelineUnit mocks the pipeline runtime so library code runs in plain JUnit or Spock tests, asserting which steps were called and with which arguments, without a live Jenkins. Register mock steps, load the library, execute and verify the call stack.

Q. How do you version and test library changes without breaking pipelines? Keep the library in Git and pin versions in @Library('lib@v1.3') so consumers do not auto-adopt breaking changes. Develop on a branch, test with @Library('lib@feature-x') in a sandbox job (and JenkinsPipelineUnit), then release a tag and bump consumers deliberately. Semantic versioning and a changelog keep upgrades safe.
