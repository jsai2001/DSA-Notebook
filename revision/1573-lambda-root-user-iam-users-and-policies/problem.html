AWS Lambda › 5. Security and permissions › Root user, IAM users and policies

  • The root user is created with the account and has full access to everything. Keep its credentials in a secure place (password manager or safe) and use it only for tasks that require it. If root credentials are stolen, an attacker can lock you out and run up charges.
  • Create an IAM admin user for daily work and limited IAM users for other tasks. If the admin user is compromised, sign in as root, delete that user and create a new one.
  • Groups organize users: attach permissions to the group and every member inherits them.
  • Policies are JSON documents with Effect (Allow or Deny), Action (API actions, for example dynamodb:GetItem) and Resource (the ARN). Users and groups have no permissions until a policy is attached.
  • Use fine-grained permissions (least privilege). Specific access to one table limits damage from stolen credentials, while Action: "*" on Resource: "*" should be avoided. Rotate access keys regularly.
