Jenkins › 3. Declarative Pipeline Basics › Scripted vs Declarative and the required sections

Scripted pipelines start with node and use the Groovy DSL. Declarative pipelines start with pipeline and evolved from the scripted DSL to make configuration as code easier. The course focuses on declarative.

Q. What are the key differences between Declarative and Scripted Pipeline syntax?

  • Declarative: opinionated and structured (pipeline { ... }), easier to read, with built-in post, when and options, validated up front. Preferred for most cases.
  • Scripted: full Groovy (node { ... }), imperative, maximum flexibility but more complex and error-prone.

You can drop into scripted logic inside declarative with a script {} block.

Q. Explain the core sections of a Declarative Pipeline.

  • pipeline: the root block.
  • agent: where it runs. any (any available executor), label '...' (a specific agent for an OS or tool), docker (inside a container for consistent environments), none (defer agent choice to individual stages).
  • stages: container for one or more stages (at least one required), such as Build, Test, Deploy.
  • stage: a named phase.
  • steps: the commands that do the work inside a stage (sh, echo); several commands are allowed per step block.
