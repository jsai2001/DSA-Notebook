2. Core Features and Concepts Amazon Bedrock

Amazon Bedrock › 2. Core Features and Concepts

FeatureKey points
Foundation modelsPre-trained, ready to use. Text, image, embeddings, analysis. Each model needs explicit access authorization before use
Inference and promptsInference = generating outputs from inputs. A prompt is structured input. A token is the basic unit of text
ParametersModel parameters control core behavior. Inference parameters control how output is generated
EmbeddingsVector representations of text or images that capture meaning. Stored in a vector DB (knowledge base) and queried via RAG
RAGGrounds answers on your own data to reduce hallucinations: query processing, knowledge retrieval, response generation
Orchestration and agentsCoordinate a model with databases, APIs and enterprise systems (CI/CD, build systems). Run tasks, retry, make decisions in loops
Customization and evaluationFine-tuning, pre-training, hyperparameter optimization, custom evaluation metrics, provisioned throughput (dedicated token I/O capacity, similar to EBS for disk I/O)

Inference parameters:

ParameterEffect
TemperatureRandomness. Low = deterministic, high = creative
Top PNucleus sampling, diversity of token selection
Top KLimits choices to the top K candidates per token
Max length / max tokensCaps response length (50 = concise, 2048 = detailed)
Without RAGWith RAG
Relies on training data onlyReferences your specific data
Higher hallucination riskGrounded, more accurate
Generic answersDomain-specific answers

RAG suits organizations with rich, high-quality data (for example, a publisher grounding answers on its catalog). Good first uses for agents: improving build systems and automating parts of the SDLC and CI/CD.
