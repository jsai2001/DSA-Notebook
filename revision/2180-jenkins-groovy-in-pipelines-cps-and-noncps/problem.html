Jenkins › 9. Shared Libraries and Groovy › Groovy in pipelines: CPS and NonCPS

Q. Which Groovy concepts matter for robust pipelines (CPS, @NonCPS)? Pipeline Groovy is CPS-transformed (continuation-passing style) so builds can pause, resume and survive controller restarts. That means program state must be serializable and some Groovy features behave oddly. Mark methods @NonCPS when they do complex non-pausing work (iterating collections with closures, using non-serializable objects), and keep pipeline steps out of them.

Q. What causes NotSerializableException, and how do you fix it? CPS serializes pipeline state at every step, so holding a non-serializable object (a JsonSlurper result type, a Matcher, streams) across a step boundary throws it. Fix by confining such objects to a @NonCPS method, nulling them before a step, or copying into serializable types (HashMap, String) before continuing.
