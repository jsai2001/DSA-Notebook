Speeding up a Docker agent build with a workspace cache Jenkins

Jenkins › 8. Agents and Distributed Builds › Speeding up a Docker agent build with a workspace cache

Problem: a Hugo (Go) build with a golang image takes about 4 minutes every run because the Go cache sits in /tmp inside the container, which is destroyed after each build. Jenkins mounts the workspace as a volume, so moving the cache there persists it.

The first run builds the cache (about 4 minutes); the second reuses it and drops to about 17 seconds. The workspace path may vary, so use the path shown in the pipeline configuration or logs.
