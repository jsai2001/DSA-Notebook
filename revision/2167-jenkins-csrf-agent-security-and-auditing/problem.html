CSRF, agent security and auditing Jenkins

Jenkins › 7. Security, Credentials and Access Control › CSRF, agent security and auditing

Q. How do you protect the controller against CSRF? Enable CSRF protection with the crumb issuer (on by default in modern Jenkins). State-changing requests must carry a valid crumb, which blocks forged cross-site requests. API clients fetch a crumb first, or use API tokens, which are crumb-exempt for scripted calls.

Q. What is Agent-to-Controller security? Agents (possibly less trusted) can ask the controller to run commands or read files. Agent-to-Controller security restricts this with a configurable allow and deny list of commands and file access, which limits the blast radius if an agent is compromised.

Q. How do you disable anonymous read access? In the authorization strategy (matrix or role), remove all permissions from the Anonymous user (do not grant Overall Read). Then only authenticated users can view Jenkins. Create a real admin account first so you do not lock yourself out.

Q. How do you audit user actions and job changes? Install the Audit Trail plugin to log who did what (config changes, triggers, deletions) to a file, syslog or console. Combine it with Job Configuration History to track and diff config changes over time.

Q. What security considerations apply to untrusted code from GitHub PRs? PRs from forks can carry a malicious Jenkinsfile or build scripts. Require approval to build fork PRs (use the trusted strategy under "Discover PRs from forks"), never expose production credentials to PR builds, run PR builds on isolated ephemeral agents, use least-privilege scoped credentials, and avoid sandbox bypass. Treat PR code as hostile.
