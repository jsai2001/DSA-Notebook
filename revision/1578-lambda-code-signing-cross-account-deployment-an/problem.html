Code signing, cross-account deployment and multi-tenancy AWS Lambda

AWS Lambda › 5. Security and permissions › Code signing, cross-account deployment and multi-tenancy

Q56. How do code signing and AWS Signer prevent unauthorized code? With Code Signing for Lambda you attach a signing profile (AWS Signer). Lambda verifies the package signature against trusted publishers before accepting it, and rejects unsigned, tampered or expired packages. Only trusted, unmodified code gets deployed.

Q57. What is cross-account deployment for Lambda? Deploying or updating a function's code or infrastructure from another account, for example a central CI/CD account deploying into dev and prod accounts. It is usually done with cross-account IAM roles (the pipeline assumes a role in the target account), shared artifact buckets or ECR with cross-account policies, and CloudFormation/SAM StackSets.

Q58. How do you isolate tenants in a multi-tenant serverless system? Along a spectrum: a separate AWS account per tenant (strongest isolation), or shared functions with per-tenant IAM scoping using session tags or dynamic policies (sts:AssumeRole with tenant context, ABAC conditions on ${aws:PrincipalTag/tenant}), per-tenant resource prefixes or partition keys, and reserved concurrency per tenant to prevent noisy neighbors. Choose by isolation against cost and operational overhead.
