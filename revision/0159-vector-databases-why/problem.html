Why Vector Databases

Vector Databases › 9. Use case 1: LLM semantic cache › Why

  • LLMs are costly (per-token API pricing, heavy compute) and slow (decoder generates one token at a time, so long answers mean high latency).
  • Users send similar prompts (same questions across users, common org queries, paraphrases), so responses overlap.
  • An exact-match cache misses paraphrases ("What is ML?" vs "What is machine learning?"); a vector-DB cache matches by meaning, so more hits.
  • Benefits: lower API cost, lower latency (~50-100 ms vs 2-5 s, quoted as 20-50x), less LLM load, better UX.
