Jenkins › 7. Security, Credentials and Access Control › Default security, realms and authorization

Jenkins is locked by default: the first launch needs an admin password, and user accounts with usernames and passwords control access.

  • Security Realm (authentication, who you are): defaults to Jenkins' built-in user database; other options are LDAP, Active Directory, Unix users and groups, or SAML/OIDC SSO (for example Okta).
  • Authorization Strategy (authorization, what you can do): by default "Logged-in users can do anything", which is poor for shared systems. Alternatives are matrix-based, project-based matrix, Role Strategy and others.

They are configured independently. Q. What is the difference between Security Realm and Authorization Strategy? The realm authenticates; the strategy authorizes.

Q. How do you integrate Jenkins with LDAP, Active Directory or SAML/Okta for SSO? Set the Security Realm to LDAP, Active Directory, or a SAML/OIDC plugin. Jenkins delegates authentication to the identity provider, and group memberships flow in and map to authorization roles or the matrix. This centralizes identity and enables SSO.
