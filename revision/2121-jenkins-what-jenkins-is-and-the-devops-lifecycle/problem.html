Q. What is Jenkins, and what role does it play in a CI/CD pipeline? Jenkins is an open-source automation server written in Java. In CI/CD it is the orchestrator: it watches source control, builds and tests code on every change (CI), and automates packaging, artifact publishing and deployment through stages to various environments (CD). It ties together compilers, test runners, scanners and deploy tools via plugins and pipelines.

The DevOps lifecycle is drawn as an infinity symbol: a continuous loop until the system is decommissioned. It has two groups of stages:

  • Development: Plan, Code, Build, Test.
  • Operational: Release, Deploy, Operate, Monitor.

Jenkins automates the Build, Test, Release and Deploy stages.

  • Continuous Integration ties to Build and Test. The goal is to find and fix issues early. Jenkins builds the code into an artifact (container image, Java archive, Windows executable), runs automated tests, and lets the artifact move on only when the tests pass.
  • Continuous Delivery/Deployment ties to Release and Deploy. Release means uploading artifacts (push a container image to a repository, publish a JAR). Deploy can be manual or fully automated (Continuous Deployment), where Jenkins executes the deployment instructions with little or no human interaction.
