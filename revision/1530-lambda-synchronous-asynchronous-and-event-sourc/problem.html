Synchronous, asynchronous and event source mapping AWS Lambda

AWS Lambda › 4. Invocation models and event sources › Synchronous, asynchronous and event source mapping

Q29. What are the three invocation models?

  • Synchronous: the caller invokes and waits for the response (RequestResponse). Errors return to the caller.
  • Asynchronous: the caller hands the event to Lambda's internal queue and gets an immediate acknowledgment (Event). Lambda invokes and handles retries.
  • Event Source Mapping (ESM): Lambda polls a source (SQS, Kinesis, DynamoDB Streams, Kafka), batches records and invokes the function.

Q30. Three services that invoke Lambda synchronously? API Gateway, Application Load Balancer (ALB) and a direct Invoke call from the SDK or CLI. Also Cognito, Lex and Step Functions optimized Task states.

Q31. Three services that invoke Lambda asynchronously? S3 event notifications, SNS and EventBridge (scheduled or rule-based). Also CloudWatch Logs, SES and CodeCommit.

Q33. What is an ESM, and which services use it? An ESM is a Lambda-managed resource that polls a stream or queue and invokes your function with batches. It is used by SQS, Kinesis Data Streams, DynamoDB Streams, Amazon MSK or self-managed Kafka, and Amazon MQ. Lambda owns the polling, batching, checkpointing and scaling of pollers.
