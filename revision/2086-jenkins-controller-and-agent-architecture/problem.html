Jenkins › 1. Jenkins Fundamentals and Architecture › Controller and agent architecture

Q. Explain the controller-agent architecture in Jenkins. The controller hosts the UI, schedules builds, stores config and job history, and manages plugins. Agents (nodes) are separate machines or containers that run the build workloads. The controller dispatches jobs to agents based on labels and available executors. Best practice: run no builds on the controller; keep it for orchestration only.

Q. Why should you avoid running build workloads on the controller? The controller holds all state, credentials and orchestration. Running builds there risks resource exhaustion (OOM/CPU), lets build scripts read sensitive controller files and secrets, and can crash the whole instance. Set controller executors to 0 and run all builds on agents.
