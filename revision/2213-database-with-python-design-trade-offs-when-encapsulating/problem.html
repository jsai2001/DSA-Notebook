Design trade-offs when encapsulating Database with Python

Database with Python › 4. MySQL with Python › Design trade-offs when encapsulating

  • Passing the cursor is simple but ties the schema to application code. A schema change (adding or removing a column) means updating the functions.
  • Connection options: pass the connection, open and close a connection per operation (no idle connections but extra latency), or commit inside the function.
  • Passing the cursor and committing outside suits small apps. Larger apps need connection pooling or an ORM.
  • Encapsulating too much starts to re-implement an ORM, so an ORM such as SQLAlchemy is the better choice for complex apps. A UI (Flask, Tkinter) could collect projects and tasks.
