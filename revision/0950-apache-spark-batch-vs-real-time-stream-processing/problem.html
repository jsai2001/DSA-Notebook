Batch vs real-time (stream) processing Apache Spark

Apache Spark › 1. Data Engineering Concepts › Batch vs real-time (stream) processing

AspectBatchReal-time
InputComplete batch (bounded), by record count or date/time rangeRecords as created (unbounded), one at a time
Input changesDoes not change during processingMay change during processing
LatencyHigher, waits for batchLow, seconds
ResultsAt end (intermediate possible)Continuous
ComplexitySimplerMore complex (state management, change data capture)
ReprocessingSame input gives same outputMust account for changes
StateGenerally statelessState management critical (entity states, running summaries)

Not every use case needs real-time. Choose on latency requirement versus complexity.
