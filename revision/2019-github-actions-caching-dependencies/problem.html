GitHub Actions › 5. Caching, artifacts and performance › Caching dependencies

Q. How does GitHub Actions support caching, and what are the steps to cache npm or pip? actions/cache stores files or directories under a unique key and restores them when the key matches. If there is no match, a new cache is saved for future runs. The cache is scoped to the repository and branch, with optional restore from parent branches.

  • path: files or directories to cache (~/.m2/repository, node_modules, ~/.npm, ~/.cache/pip).
  • key: unique identifier, usually including a file hash so the cache is invalidated when dependencies change.
  • restore-keys: fallback keys used when the primary key does not match.

Use cases: build tools (Maven, Gradle), package managers (npm, Yarn, pip), compiled artifacts and intermediate build outputs. Use hashFiles on dependency files (pom.xml, package-lock.json) and specify multiple paths for complex projects.
