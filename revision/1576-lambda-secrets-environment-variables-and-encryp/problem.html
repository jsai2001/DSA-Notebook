Secrets, environment variables and encryption AWS Lambda

AWS Lambda › 5. Security and permissions › Secrets, environment variables and encryption

Q49. How should sensitive credentials or API keys reach a function? Never hard-code them. Store them in AWS Secrets Manager or SSM Parameter Store (SecureString), grant the execution role read access, and fetch at Init (cache in a global). The Secrets/Parameter Store Lambda extension can cache values and reduce API calls.

Q50. Environment variables vs Secrets Manager / SSM Parameter Store? Env vars are simple key/values stored with the function config. They suit non-secret config (table names, flags) and are encrypted at rest with KMS. Secrets Manager and SSM are built for secrets: centralized, access-controlled, auditable and they support rotation. Sensitive values belong there, not in env vars, which are visible to anyone with GetFunctionConfiguration.

Q51. How do you encrypt env vars at rest and in transit? At rest Lambda encrypts them with a KMS key (AWS-managed by default; use a customer-managed CMK for tighter control and audit). For transit and console protection, enable encryption helpers so values are encrypted client-side with your CMK and decrypted in code at runtime via KMS.
