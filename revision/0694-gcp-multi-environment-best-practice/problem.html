Multi-environment best practice Google Cloud (GCP)

Google Cloud (GCP) › 4. App Engine Components, Versions, Traffic Splitting › Multi-environment best practice

  • Use separate projects for test and production, not just separate services. Services in one project share data (Firestore, Cloud Storage), which risks cross-contamination.
  • Version naming: <timestamp>-<git-commit-hash>. Timestamp gives deployment order; the hash identifies the exact commit, which makes rollback precise.
  • Test project: default version = latest production version; each feature branch is its own version (feature-x, feature-y), so QA can test them in parallel via unique version URLs.
  • Production project: versions by timestamp + commit, used for migrations and rollbacks. Feature versions can be tried on real users via traffic splitting.
  • Natural next step: automate with CI/CD.
