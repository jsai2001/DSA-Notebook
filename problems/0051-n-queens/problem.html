51. N-Queens Hard Array Backtracking
Key idea: One queen per row, so place them row by row and backtrack. A square (r, c) is attacked when its column, its r − c (the down-right diagonal) or its r + c (the down-left diagonal) is already taken. Keep those three in sets, so every check is O(1), and give up on a row as soon as it has no safe square.

Problem View on LeetCode (opens in a new tab) ↗

Place n queens on an n × n chessboard so that no two attack each other (no two share a row, a column or a diagonal). Return every distinct solution, each as a list of strings where 'Q' is a queen and '.' an empty square, in any order.

  • 1 <= n <= 9.

Examples: n = 4 → [[".Q..","...Q","Q...","..Q."],["..Q.","Q...","...Q",".Q.."]]; n = 1 → [["Q"]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
n = 1 [["Q"]] The smallest board: one queen, one solution.
n = 2 / n = 3 [] / [] No solution at all: return an empty list, not None or a partial board.
n = 4 2 boards Leaving out the r + c check (one of the two diagonals) gives 7 boards here, and 2,113 instead of 92 for n = 8.
n = 5 / n = 6 10 / 4 boards The count isn't monotonic: n = 6 has fewer solutions than n = 5. Don't sanity-check by "more for bigger n".
n = 8 92 boards The classic eight queens. In C++ and Java, indexing the diagonal array with r − c without adding n − 1 reads index −1: out of bounds (Java throws ArrayIndexOutOfBoundsException).
n = 9 352 boards The largest input. Trying every column order without early checks means 9! = 362,880 full boards.
Python board [['.'] * n] * n Separate rows That makes n references to one row: placing queens at columns 1, 3, 0, 2 turns every row into "QQQQ". Build each row on its own.

Approach 1: Every Column Order, Check at the End

One queen per row and one per column means a solution is a permutation of the columns. Try all n! of them, and keep the ones where no two queens share a diagonal.

  • Two queens in rows i and j share a diagonal when |cols[i] − cols[j]| == j − i.
  • The check runs only on full boards, so hopeless boards are built all the way down.
Time O(n! · n²) Space O(n) besides the answer

Passes for n ≤ 9 (0.43 s in Python here at n = 9), but it checks every one of the 362,880 full boards, even those that went wrong in row 1.

Approach 2: Backtracking with Column and Diagonal Sets Optimal

Check while placing instead of at the end. Every square on a down-right diagonal has the same r − c, and every square on a down-left diagonal the same r + c. So three sets say in O(1) whether a square is attacked.

  • Skip attacked squares; if a row has no safe square, that branch dies right there.
  • After the recursive call, remove the queen and its three entries: that's the backtrack.
  • In C++ and Java, use arrays of size 2n − 1 and store r − c at index r − c + n − 1, since it can be negative. (A Python list happens to work without the offset: the negative indices wrap into the other half of the list. Sets avoid the question.)
Time O(n!) upper bound Space O(n) besides the answer

Far fewer squares are visited: 0.01 s in Python at n = 9 here, and 0.92 s even at n = 12 (14,200 solutions). The same "choose, recurse, undo" shape as Permutations and Sudoku Solver.

Approach 3: Backtracking with Bitmasks

The same search, with the three sets packed into three n-bit numbers for the current row: bit c is set if column c is attacked. The safe columns are ~(cols | diag | anti) in one step.

  • free & −free gives the lowest safe column; subtract it to move on.
  • Going one row down, a down-right attack moves one column right (<< 1, then & full to drop what falls off the board) and a down-left attack one column left (>> 1).
Time O(n!) upper bound Space O(n) besides the answer

No per-square checks at all: about 3× faster than the sets here (0.27 s vs 0.92 s at n = 12). Worth knowing; Approach 2 is easier to explain in an interview.

In practice No shortcut

No library solves N-Queens. Python's itertools.permutations and C++'s std::next_permutation can list the column orders, but that's Approach 1: every order is built in full before it's checked.

Write Approach 2. The three things to remember: one queen per row, r − c and r + c for the diagonals, and undo after the recursive call.
