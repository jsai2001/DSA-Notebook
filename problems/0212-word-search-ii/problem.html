212. Word Search II Hard Trie Backtracking Matrix
Key idea: Don't search the board once per word. Put all the words in a trie and run one DFS from every cell, walking the board and the trie together: a path stops as soon as no word continues with its letters. Clear each found word, and cut trie branches that have nothing left.

Problem View on LeetCode (opens in a new tab) ↗

Given a board of letters and a list of words, return every word that can be spelled by a path of cells joined up, down, left or right, using each cell at most once per word. Any order.

  • 1 <= m, n <= 12, lowercase letters
  • 1 <= words.length <= 3 × 10⁴, each 1 to 10 letters, all different

Example: board ["oaan","etae","ihkr","iflv"], words ["oath","pea","eat","rain"] → ["eat","oath"]. Board ["ab","cd"], words ["abcb"] → [].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
board ["a","a"], words ["aa"] ["aa"] Two paths spell it. Not clearing a found word from the trie reported it twice; wrong on 1204 of 1505 tests.
board ["a","b"], words ["ab","ba"] both Forgetting to unmark a cell on the way back blocks it for later paths: only "ab" was found.
board ["ab","cd"], words ["abcb"] [] The second b would reuse a cell.
12 × 12 of a, words a…aaaaaaaaaa and aaaaaaaaa + each other letter the 10 all-a words Every path of as matches a prefix. Searching per word took 23 s in Python; the pruned trie, 0.56 s.

Approach 1: Word Search for Each Word

Reuse Word Search (79): for each word, try every cell as the start and DFS letter by letter, marking cells on the path and unmarking them on the way back. Keep the words that are found.

  • Correct, and fine for a handful of words.
  • Words that share a prefix redo the same walks, and the board is scanned once per word.
Time O(W · m·n · 3ᴸ) Space O(L) call stack

All-a board, 35 words: Python 23 s, Java 268 ms, C++ 174 ms. A random 12 × 12 board with 3000 words: Python 75 ms.

Approach 2: Trie + DFS From Every Cell

Build a trie of all the words. From each cell, DFS while following the trie: a step is only taken if the trie has a child for that cell's letter. When a node holds a word, add it to the answer and clear it.

  • One walk checks all words with that prefix at once.
  • Marking the cell with "#" also stops the DFS, because no trie node has a "#" child.
Time O(m·n · 3ᴸ) Space O(total letters in words)

All-a board: Python 1.4 s, Java 24 ms, C++ 22 ms, 17 times faster than Approach 1 in Python. Random board, 3000 words: Python 6.1 ms.

Approach 3: Trie + DFS + Pruning Optimal

Same as Approach 2, plus one step on the way back: if the child node now has no word and no children, delete it from its parent. Branches whose words are all found disappear, and later paths stop earlier.

  • C++ and Java keep a child count per node, so the "empty?" check is O(1).
  • The more words are found, the smaller the trie gets.
Time O(m·n · 3ᴸ) at worst, much less in practice Space O(total letters in words)

All-a board: Python 0.56 s, Java 9.3 ms, C++ 8.9 ms, 2.5 times faster than Approach 2. Random board: the same as Approach 2 (few words are found, so little is cut).

In practice No shortcut

No library walks a board for you, and none has a trie. Approach 3 is what you'd write.
