21. Merge Two Sorted Lists Easy Linked List Recursion
Key idea: Put a dummy node in front of the answer and keep a tail pointer. While both lists have nodes, attach the smaller head to tail and move on. When one list runs out, attach the rest of the other in one step. Return dummy.next. O(m + n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

You're given the heads of two sorted linked lists, list1 and list2. Merge them into one sorted list made by splicing together the nodes of the two lists, and return its head.

  • Each list has between 0 and 50 nodes.
  • -100 <= Node.val <= 100.
  • Both lists are sorted in non-decreasing order.

Examples: [1,2,4], [1,3,4] → [1,1,2,3,4,4]; [], [] → []; [], [0] → [0].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[], [] [] Both heads are null: return null / None without reading .val.
[], [0] [0] Only list1 is empty: the answer is just list2.
[1], [] [1] The mirror case: list2 is empty. Code that checks only one side breaks here.
[1,2,4], [1,3,4] [1,1,2,3,4,4] Ties at both ends: equal values must both be kept, not merged into one.
[5], [1,2,3] [1,2,3,5] The head of the answer comes from list2, so returning list1 is wrong. A dummy node avoids deciding the head up front.
[1,2,3], [4,5,6] [1,2,3,4,5,6] list1 runs out first, and all of list2 is still left: the leftover must be attached, not dropped.
[-100,0,100], [-100,100] [-100,-100,0,100,100] The extreme values, and negatives: don't start a "smallest so far" at 0.
[2,2,2], [2,2] [2,2,2,2,2] Every value equal: the comparison is always a tie, so <= vs < decides which list goes first, and both must still finish.
50 nodes and 50 nodes 100 nodes The largest input. The recursive version goes about 100 calls deep, which is fine at this size.

Approach 1: Collect, Sort, Relink

Forget that the lists are sorted: put every node in one array, sort the array by value, and link the nodes in that order.

  • It moves the same nodes rather than making new ones, which is what "splicing together the nodes" asks for (and in C++ nothing is leaked).
  • A stable sort keeps list1's node first on a tie. The values come out the same either way.
  • Remember to set the last node's next to null.
Time O((m + n) log(m + n)) Space O(m + n)

Easy to get right, but it throws away the fact that both lists are already sorted. That's exactly what the next two approaches use.

Approach 2: Recursion

The smaller of the two heads must be the first node. What comes after it? The merge of everything that's left, which is the same problem on smaller lists.

  • Base case: if one list is empty, the answer is the other list.
  • Otherwise, if list1.val <= list2.val, set list1.next = merge(list1.next, list2) and return list1; else do the same with list2.
Time O(m + n) Space O(m + n) call stack

Short and clear. Each call handles one node, so the stack grows to m + n frames. Fine for 100 nodes; for very long lists it would overflow the stack (Python's default limit is 1,000 calls).

Approach 3: Iterative with a Dummy Node Optimal

The same choice as the recursion, done in a loop: keep a tail on the last node of the answer and keep attaching the smaller head to it.

  • The dummy node means the first node isn't a special case: the head of the answer is simply dummy.next.
  • When one list runs out, the other is already sorted and every value in it is at least the tail's, so attach all of it at once: tail.next = list1 or list2.
  • Using <= takes list1's node on a tie, which keeps the merge stable.
Time O(m + n) Space O(1)

Each node is looked at once and only pointers change. This merge step is the core of merge sort, and it's reused in Merge k Sorted Lists and Sort List.

In practice No shortcut

LeetCode's ListNode is a bare class, so the standard library can't merge it. C++ has std::list::merge and std::merge, and Python has heapq.merge, but they work on std::list, iterators and iterables, not on these nodes. Copying the values out, merging, and building new nodes works, but it makes new nodes instead of splicing the old ones.

Write Approach 3. The dummy node plus tail pointer is the standard way to build any linked list as you go.
