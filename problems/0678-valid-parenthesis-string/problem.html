678. Valid Parenthesis String Medium String Greedy Stack
Key idea: Don't decide what each * is. Track the range of how many ( could be open: lo (every * as )) and hi (every * as (). Fail if hi < 0; never let lo go below 0. At the end, valid if lo == 0. O(n), O(1).

s has only (, ) and *. Each * can stand for (, ) or nothing. Return true if some choice makes the brackets balanced: every ( closed by a later ), and no ) without an earlier (.

Edge cases

Approach 1: Try Every Meaning of Each Star

Recursively walk the string with a count of open (. A ( adds one, a ) removes one; a * tries all three. A path dies when the count goes negative; it succeeds if the count is 0 at the end.

  • Correct, and shows exactly what the problem asks.
  • Exponential in the number of stars. Adding a memo on (i, open) brings it down to O(n²), the DP version.
Time O(3ᵏ) for k stars Space O(n) call stack

About 8× slower for every 2 more stars. Python: 0.3 s at 14 stars, 2.6 s at 16, 22 s at 18. C++: 3 s at 20, 40 s at 22.

Approach 2: Two Stacks of Indexes

Push the index of every ( and every * on two stacks. A ) closes the latest (, or else the latest *, or fails. At the end, pair each leftover ( with a leftover * that comes after it.

  • Prefer a real ( for each ), and keep stars for later.
  • Popping both stacks pairs the latest ( with the latest star; if the star is earlier, it fails.
Time O(n) Space O(n)

About 6–7 µs per call in Python for 100 characters. Easier to explain than the range trick, and it shows which characters match.

Approach 3: Range of Open Counts Optimal

lo and hi are the fewest and the most ( that could be open after each character, over every way of reading the stars. (: both +1. ): both −1. *: lo − 1, hi + 1.

  • hi < 0 means even the most generous reading has too many ): fail now.
  • lo = max(lo, 0): readings that go negative are already invalid, so drop them. Every count between lo and hi stays reachable.
  • Valid if 0 is in the final range, that is, lo == 0.
Time O(n) Space O(1)

About 8–9 µs per call in Python for 100 characters. The expected answer; the "why lo can be clamped" point is the usual follow-up.

In practice No shortcut

No standard library checks brackets with wildcards. Counting characters with s.count isn't enough: ")(" has balanced counts but isn't valid.

Approach 3 is what you'd write: one loop and two numbers.
