53. Maximum Subarray Medium Array Divide and Conquer Dynamic Programming
Key idea: Kadane's algorithm. Keep cur, the best sum of a subarray that ends here: cur = max(nums[i], cur + nums[i]). A run with a negative sum only drags the next number down, so start again. The answer is the largest cur seen. Start both at nums[0], not 0. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given an integer array nums, find the subarray (a non-empty run of consecutive numbers) with the largest sum, and return that sum.

  • 1 <= nums.length <= 10⁵ and -10⁴ <= nums[i] <= 10⁴.
  • Follow-up: after the O(n) solution, try divide and conquer.

Examples: [-2,1,-3,4,-1,2,1,-5,4] → 6 ([4,-1,2,1]); [1] → 1; [5,4,-1,7,8] → 23.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[-1] -1 The subarray can't be empty, so the answer can be negative. Starting best at 0 returns 0.
[-2,-1] -1 All negative: the answer is the largest single number. The popular "add, and reset to 0 when negative" version returns 0 here (it was wrong on 1,104 of the small test arrays).
[5,4,-1,7,8] 23 The whole array: keeping the −1 is worth it, because what follows makes up for it.
[2,-1,2] / [3,-4,3] 3 / 3 Crossing a negative number pays off only if the run before it is bigger than the drop.
[0,-3,0] 0 A zero on its own is the best: the answer is 0 without anything being empty.
10⁵ copies of 10⁴ 1000000000 The largest possible sum. It fits in a 32-bit int (limit 2,147,483,647).
10⁵ random numbers — Trying every subarray means 5 × 10⁹ additions: about 3 s in C++ and Java here, and minutes in Python.

Approach 1: Brute Force (Every Subarray)

For every start i, extend the end j one step at a time, keeping a running sum, so each subarray's sum costs O(1).

  • Start best at nums[0]: every number may be negative.
Time O(n²) Space O(1)

Correct, but n(n + 1) / 2 subarrays is 5 × 10⁹ at n = 10⁵: about 3 s in optimised C++ and in Java here, and around 5 minutes in Python (estimated from 5,000 numbers).

Approach 2: Divide and Conquer

Split the array at mid. The best subarray lies entirely in the left half, entirely in the right half, or crosses the middle. The first two are the same problem on half the array; the crossing one is the best run ending at mid plus the best run starting at mid + 1.

  • The crossing runs must each hold at least one number, so start them at −∞, not 0. Starting at 0 lets an empty run win: [-1,-2] gives 0 (wrong on 1,097 of the small test arrays).
  • Each level of the recursion scans every number once for the crossing runs.
Time O(n log n) Space O(log n) call stack

The follow-up's answer: 0.16 s in Python at n = 10⁵ here. Slower than Kadane, but the same "left, right, or crossing" idea solves harder problems, such as answering many range queries with a segment tree.

Approach 3: Kadane's Algorithm Optimal

Every subarray ends somewhere. The best one ending at i is either nums[i] alone, or the best one ending at i − 1 extended by nums[i]. That's a one-step DP that only needs the previous value.

  • cur = max(nums[i], cur + nums[i]), then best = max(best, cur).
  • Starting again happens exactly when the run so far is negative.
  • Both start at nums[0], which keeps all-negative arrays right.
Time O(n) Space O(1)

One pass: 0.02 s in Python at n = 10⁵ here. The same "best ending here" idea solves Maximum Product Subarray (keep the smallest too) and Best Time to Buy and Sell Stock.

In practice Built-ins

Kadane is a running fold, so it fits library scans: Python's itertools.accumulate with a max step, then max; C++'s std::partial_sum with the same step, then std::max_element. Java has no running-fold helper for arrays, so write the loop.

Time O(n) Space O(1) in Python, O(n) in C++

Both pass and match Approach 3's speed here. The C++ version stores every running value in a vector; the plain loop needs no extra memory.
