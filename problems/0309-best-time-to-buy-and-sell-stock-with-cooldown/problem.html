309. Best Time to Buy and Sell Stock with Cooldown Medium Dynamic Programming Array
Key idea: Each day you're in one of three states: hold (you own a share), sold (you sold today, so tomorrow is a cooldown), or rest (free to buy). Track the best money for each: hold = max(hold, rest − p), sold = hold + p, rest = max(rest, sold), all from yesterday's values. Buying only from rest is what enforces the cooldown. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

prices[i] is the stock price on day i. Buy and sell as many times as you like, holding at most one share at a time. After a sale you can't buy on the next day (cooldown). Return the most profit.

  • 1 <= prices.length <= 5000, 0 <= prices[i] <= 1000

Example: [1,2,3,0,2] → 3 (buy 1, sell 2, cool down, buy 0, sell 2). [1] → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1,63,5,416] 415 Taking every rise (Stock II) needs a buy right after a sale: it said 473. Updating the three states in place, so the buy reads today's rest, gives the same wrong answer. Both were wrong on 1375 of 3007 tests.
[2,1] 0 Prices only fall: never buy.
[1] 0 One day: nothing to sell.

Approach 1: Recursion with Memo

best(i, holding) = the most profit from day i on. Not holding: buy today or wait. Holding: sell today and jump to i + 2 (the cooldown), or keep the share.

  • The cooldown is just "skip a day after selling".
  • One call per day can stack up 5000 deep: Python raises its recursion limit.
Time O(n) Space O(n)

5000 days: Python 5.4 ms, Java 0.17 ms, C++ 0.14 ms.

Approach 2: Three State Arrays

Fill hold[i], sold[i] and rest[i] day by day. You can only buy from yesterday's rest, and today's rest comes from yesterday's sold, so a sale is always followed by a day off.

  • Draw the three states with arrows between them; the formulas fall out.
Time O(n) Space O(n)

5000 days: Python 1.0 ms, Java 0.05 ms, C++ 0.009 ms.

Approach 3: Three Variables Optimal

Day i only uses day i − 1, so keep three numbers. Compute all three new values from the old ones before assigning any (one tuple assignment in Python, temporaries in C++ and Java).

  • Updating one in place before the others are computed is the classic bug here.
Time O(n) Space O(1)

5000 days: Python 0.50 ms, Java 0.004 ms, C++ 0.007 ms, the fastest in every language.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write.
