1584. Min Cost to Connect All Points Medium Graph Union Find Minimum Spanning Tree
Key idea: This is a minimum spanning tree on a complete graph: every pair of points is an edge, weighted by Manhattan distance. With n² edges, Prim's algorithm with a plain dist array (no heap, no edge list) is the best fit: n rounds, each picks the closest point outside the tree and updates the others. O(n²) time, O(n) memory.

Problem View on LeetCode (opens in a new tab) ↗

Connecting two points costs their Manhattan distance, |x1 − x2| + |y1 − y2|. Return the minimum total cost so that every point is connected to every other, directly or through other points.

  • 1 <= points.length <= 1000, all different
  • -10⁶ <= x, y <= 10⁶

Example: [[0,0],[2,2],[3,10],[5,2],[7,0]] → 20. [[3,12],[-2,5],[-4,1]] → 18.

Approach 1: Kruskal (Sort Every Edge)

Build all n(n − 1) / 2 edges and sort them by distance. Go from the cheapest: if the two points are in different groups (union-find), take the edge and join the groups; if they're already in the same group, skip it. Stop after n − 1 edges.

  • The cheapest edge between two separate groups is always safe to take.
  • Stores every edge: O(n²) memory.
Time O(n² log n) Space O(n²)

At 1000 points: Python 0.2–0.46 s, Java 24–58 ms, C++ 25–38 ms. Fine here; Kruskal shines when there are few edges.

Approach 2: Prim With a Heap

Grow one tree from point 0. A heap holds (cost, point) offers. Pop the cheapest: if that point is already in the tree, skip it; otherwise add it and push an offer from it to every point still outside.

  • The heap may hold several offers for the same point; only the first one popped counts.
  • On a complete graph almost every pair gets pushed: the heap peaked at 496,185 entries for 1000 points.
Time O(n² log n) Space O(n²)

At 1000 points: Python 160–190 ms, Java 22–33 ms, C++ 2.6–9 ms. The usual Prim; better suited to graphs with fewer edges.

Approach 3: Prim With an Array Optimal

Keep dist[v], the cheapest edge from the tree to each outside point. Each round, scan for the outside point with the smallest dist, add it, then lower dist for every point that's closer to it.

  • A scan of n points replaces the heap: O(n) per round, n rounds, and no log.
  • Distances are computed on the fly, so nothing of size n² is stored.
Time O(n²) Space O(n)

At 1000 points: Python 100–106 ms, Java 9 ms, C++ 1.1–1.7 ms, the fastest here in every language. The best answer for a dense graph.

In practice No shortcut

The standard libraries have no minimum spanning tree. Outside LeetCode, scipy.sparse.csgraph.minimum_spanning_tree or networkx.minimum_spanning_tree would do it, but each still needs all n² distances first.

Approach 3 is what you'd write: about 15 lines, no extra data structures.
