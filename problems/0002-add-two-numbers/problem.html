2. Add Two Numbers Medium Linked List Math Recursion
Key idea: Digits are stored in reverse order, so the heads are the ones place. Walk both lists together like column addition: sum = a + b + carry, keep sum % 10, carry sum // 10. Use a dummy head node and keep looping while either list or the carry is left.

Problem View on LeetCode (opens in a new tab) ↗

You are given two non-empty linked lists representing two non-negative integers. The digits are stored in reverse order, and each node holds a single digit. Add the two numbers and return the sum as a linked list in the same format.

  • Each list has between 1 and 100 nodes.
  • Each node value is between 0 and 9.
  • No leading zeros, except for the number 0 itself.

Example: [2,4,3] + [5,6,4] is 342 + 465 = 807, so the answer is [7,0,8].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
l1 = [0], l2 = [0] [0] Both numbers are 0: the answer is one node, [0], not an empty list.
l1 = [5], l2 = [5] [0, 1] 5 + 5 = 10: the last carry needs a new node at the end.
l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9] [8, 9, 9, 9, 0, 0, 0, 1] Different lengths, a carry on every digit, and a final carry.
l1 = [9, 9], l2 = [1] [0, 0, 1] The shorter list ends but the carry keeps going through the longer one.
l1 = [1, 8], l2 = [0] [1, 8] Adding 0: the result is just the longer list.
l1 = 99 zeros then 1 (10⁹⁹), l2 = [1] [1, then 98 zeros, then 1] 100 digits: too big for int or long. Converting to a number only works with Python ints or Java's BigInteger.

Approach 1: Three Loops with Trailing Node

Handle the lists in three phases, writing the result digit by digit into a pre-allocated node.

  • Loop 1: while both lists have nodes, add l1.val + l2.val + carry.
  • Loop 2 and 3: whichever list is longer, keep going with val + carry.
  • If a carry of 1 is left, write it into one more node.
  • After every digit a new empty node is created, so the list ends with one extra node. Track prev and set prev.next = None at the end to cut it off.
Time O(max(m, n)) Space O(max(m, n))

Each node is visited once. The space is the output list itself, so there are no extra data structures. The downside is the repeated code across the three loops and the extra trailing node that has to be trimmed.

Approach 2: Single Loop with Dummy Head Optimal

Same column addition, but merge the three loops into one. Keep looping while l1, l2 or carry is still present, and treat a missing node as the digit 0.

  • Start with a dummy node and a tail pointer. Return dummy.next.
  • Each step: total = carry + (l1 digit) + (l2 digit), append a node with total % 10, set carry = total // 10.
  • Including carry in the loop condition handles the final carry (like 5 + 5 = 10) without a special case.
  • Nodes are only created when needed, so there's no trailing node to trim.
Time O(max(m, n)) Space O(max(m, n))

Same complexity as Approach 1 (the output list is the only space used, extra space is O(1)), but shorter, with no duplicated loops and no prev bookkeeping.

In practice Built-ins

Skip the column addition: turn each list into a real number, add them, and turn the sum back into a list. Python's int and Java's BigInteger handle numbers of any size, so 100-digit inputs are fine.

Time O(m + n) Space O(m + n)

Should pass on LeetCode. C++ has no built-in big integer (a long long overflows past 19 digits), so use Approach 2 there. The hidden cost is the string ↔ number conversions, which is fine at this size.
