297. Serialize and Deserialize Binary Tree Hard Tree Design Depth-First Search
Key idea: Write the values in pre-order (node, left subtree, right subtree) and mark every empty spot with "#". The markers tell exactly where each subtree ends, so reading the tokens back in the same order rebuilds the same tree. O(n) both ways. Use a stack instead of recursion so a 10⁴-deep tree is fine.

Problem View on LeetCode (opens in a new tab) ↗

Build a Codec whose serialize(root) turns a binary tree into a string, and whose deserialize(data) turns that string back into the same tree. Any format works, as long as the round trip is exact.

  • The number of nodes is in [0, 10⁴]
  • -1000 <= Node.val <= 1000

Example: [1,2,3,null,null,4,5] → (any string) → the same tree. [] → the empty tree.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1,2] and [1,null,2] two different strings Writing only the values, level by level, gives 1,2 for both: you can't tell left from right. Empty spots must be written too.
10⁴ nodes in one chain - The recursive version hit RecursionError in Python at the default limit of 1000, so it raises the limit. The stack version needs nothing.
[] [] An empty tree must survive the round trip too.
[-1000,1000] the same Negative values: separate tokens with commas instead of relying on fixed widths.

Approach 1: Level Order With "null"

Write the tree level by level, with "null" for each missing child, and drop trailing nulls (this is LeetCode's own format). To rebuild, keep a queue of parents: each parent takes the next two tokens as its left and right child.

  • The string is easy to read and matches how LeetCode shows trees.
  • No recursion either way.
Time O(n) Space O(n)

10⁴ random nodes, round trip: Python 7.2 ms, Java 3.0 ms, C++ 1.6 ms. 93,856 characters: "null" is longer than "#".

Approach 2: Recursive Pre-order With "#"

walk(node) writes "#" for None, or the value followed by walk(left) and walk(right). To rebuild, build() reads one token: "#" means None; otherwise make the node, then build() its left and its right.

  • The two functions mirror each other, which makes it easy to get right.
  • One call per node and per "#": Python needs a higher recursion limit for deep trees.
Time O(n) Space O(height) call stack

10⁴ random nodes, round trip: Python 6.2 ms, Java 1.9 ms, C++ 1.3 ms, the fastest in Python and Java. 63,863 characters, a third shorter than Approach 1.

Approach 3: Pre-order With a Stack Optimal

The same string as Approach 2, made with a stack (push right, then left). To rebuild, keep a stack of nodes still missing a child, with a count of children given. Each token becomes the top node's next child; a node with both children set is popped, and a real new node is pushed.

  • No recursion, so a 10⁴-node chain needs no special setup in any language.
  • The stack holds at most one root-to-leaf path.
Time O(n) Space O(height)

10⁴ random nodes, round trip: Python 9.2 ms, Java 2.9 ms, C++ 1.3 ms (the fastest in C++). A little slower than Approach 2 in Python and Java, in exchange for not depending on the recursion limit.

In practice No shortcut

Outside LeetCode you'd usually pick an existing format such as JSON. Here you write the format yourself; Approach 2 or 3 is what you'd write.
