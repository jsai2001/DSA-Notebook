57. Insert Interval Medium Array
Key idea: The list is already sorted with no overlaps, so it splits into three runs: intervals that end before the new one starts (copy them), intervals that start before it ends (absorb them: min of starts, max of ends), and the rest (copy them). One pass, O(n), no sort.

Problem View on LeetCode (opens in a new tab) ↗

intervals is sorted by start and has no overlapping intervals. Insert newInterval so that the list is still sorted with no overlaps, merging where needed, and return the new list.

  • 0 <= intervals.length <= 10⁴: the list can be empty.
  • 0 <= start <= end <= 10⁵ for every interval, including newInterval.
  • Touching intervals, like [1,3] and [3,4], count as overlapping.

Examples: [[1,3],[6,9]] + [2,5] → [[1,5],[6,9]]; [[1,2],[3,5],[6,7],[8,10],[12,16]] + [4,8] → [[1,2],[3,10],[12,16]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[] + [5,7] [[5,7]] An empty list: none of the loops run, but the new interval must still be added.
[[3,5]] + [1,2] [[1,2],[3,5]] It goes first, before everything.
[[1,2]] + [3,4] [[1,2],[3,4]] It goes last: every interval ends before it starts, so the first run copies them all and nothing is left to overlap.
[[1,2],[6,7]] + [3,4] [[1,2],[3,4],[6,7]] It fits in a gap without touching anything.
[[1,3]] + [3,4] [[1,4]] Touching on the left. Copying intervals while end <= start (instead of <) keeps [1,3] apart: [[1,3],[3,4]].
[[4,5]] + [1,4] [[1,5]] Touching on the right. Absorbing only while start < end (instead of <=) gives [[1,4],[4,5]].
[[1,2],[5,6]] + [2,5] [[1,6]] It touches both neighbours and joins them into one.
[[1,10]] + [3,4] [[1,10]] Already covered. Without min on the start you get [[3,10]]; without max on the end, [[1,4]].
[[2,3],[4,5]] + [1,9] [[1,9]] It swallows everything. Setting end = interval.end instead of the max shrinks it to 3, so [4,5] no longer overlaps: [[1,3],[4,5]].

Approach 1: Add It, Sort, Merge

Reuse Merge Intervals (56): append newInterval, sort by start, and merge in one pass. It doesn't use the fact that the list was already sorted.

  • Merge as usual: extend the last merged interval when start <= last.end, otherwise start a new one.
Time O(n log n) Space O(n)

A fine answer if you just solved 56. In practice it's quick: Python's sort is fast on a nearly sorted list (1.3 ms for 10⁴ intervals here, against 1.0 ms for Approach 2). But an interviewer will ask for O(n).

Approach 2: One Pass in Three Phases Optimal

Walk the sorted list once. Because nothing overlaps and everything is sorted, the intervals come in three runs, in this order, relative to [start, end].

  • Before: while interval.end < start, copy it.
  • Overlap: while interval.start <= end, absorb it: start = min(...), end = max(...).
  • Add [start, end], then copy everything that's left.
Time O(n) Space O(n) for the answer

The expected answer. The two conditions mirror each other: < for "ends before", <= for "starts before it ends", so touching intervals land in the overlap run. The result copies each interval, so it doesn't share lists with the input.

Approach 3: Binary Search the Overlap

The intervals that overlap the new one form one block, intervals[left..right − 1]. Both ends of it can be found by binary search, since starts and ends are both increasing.

  • left: the first interval with end >= start.
  • right: the first interval with start > end; search from left.
  • Only the block's first start and last end matter for the merge. Then the answer is before + [start, end] + after.
Time O(n): O(log n) to search, O(n) to copy Space O(n)

Only O(log n) comparisons, but the answer is a new list, so copying it still costs O(n). The search alone is worth knowing when you only need to ask which intervals overlap, without building a new list.

In practice Built-ins

Approach 3 with the standard binary searches. Python's bisect_left / bisect_right take a key since 3.10, and C++ has std::lower_bound / std::upper_bound with a comparator. Java's Arrays.binarySearch can't search on one field of an int[][] as simply, so write the loop there.

Time O(n) Space O(n)

Both pass every test here. The Python version slices intervals, so the result shares the untouched inner lists with the input: changing result[0][1] afterwards changes intervals[0][1] too.
