45. Jump Game II Medium Array Greedy Dynamic Programming
Key idea: The indices reachable with k jumps form a contiguous window. Scan it and track farthest = max(i + nums[i]): that's where the window for k + 1 jumps ends. When i reaches the current window's end, count a jump and set end = farthest. Loop only up to n − 2. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

You start at index 0 of nums. From index i you can jump to any index from i + 1 up to i + nums[i]. Return the minimum number of jumps to reach the last index.

  • 1 <= nums.length <= 10⁴ and 0 <= nums[i] <= 1000.
  • The last index is always reachable.

Examples: [2,3,1,1,4] → 2 (0 → 1 → 4); [2,3,0,1,4] → 2.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[0] 0 You start on the last index. A greedy loop that also visits the last index counts a jump here and returns 1.
[2,3,1,1,4] 2 Always taking the longest jump (to index 2) gives 3. The best first jump is the one that leads furthest next.
[2,3,0,1,4] 2 A 0 in the middle is a dead end; the path has to jump over it.
[3,2,1] 1 The first jump can go past the end: you only need to reach the last index, not land exactly on it.
[1,1,1,1] 3 Every jump is forced: n − 1 jumps.
[1,2] / [2,1] 1 / 1 Two elements: one jump, whatever the values.
[1,2,1,1,1] 3 The bigger value isn't at the start: 0 → 1 → 3 → 4.
10⁴ ones 9999 The most jumps possible. Also: 10⁴ values of 1000 make the DP do about 10⁷ updates.

Approach 1: Dynamic Programming

dp[i] is the fewest jumps to reach index i. Going left to right, every index i can be reached in dp[i] jumps, so everything it can jump to can be reached in dp[i] + 1.

  • Start with dp[0] = 0 and "infinity" everywhere else (n works: no answer is that large).
  • For each j in i + 1 … i + nums[i]: dp[j] = min(dp[j], dp[i] + 1).
Time O(n · k), k = max(nums) Space O(n)

Correct and easy to reason about, but it updates the same indices again and again. With 10⁴ values of 1000 it took 0.5 s in Python here (27 ms in C++).

Approach 2: BFS

Fewest jumps is a shortest path where every jump costs 1, which is what BFS finds: indices come out of the queue in order of jumps used, so the first time the last index comes out, that's the answer.

  • From i you can reach a whole range, and everything up to reached is already queued, so only push reached + 1 … i + nums[i]. Each index is queued once.
  • That keeps it O(n) instead of O(n · k).
Time O(n) Space O(n)

The queue holds the indices one jump at a time: all the 1-jump indices, then all the 2-jump ones. Those groups are exactly the windows the greedy approach tracks without a queue.

Approach 3: Greedy by Levels Optimal

BFS without the queue. The indices reachable with k jumps are a window [start, end]. While scanning it, keep farthest, the furthest any of them can jump: the next window ends there.

  • When i == end, the window is done: jumps += 1, end = farthest.
  • Loop to n − 2, not n − 1: once you can stand on the last index you don't jump again. Including it gives one jump too many (wrong on [0], [1,1], …).
  • It never picks a specific landing spot; it just counts how many windows it takes.
Time O(n) Space O(1)

One pass and three variables: 0.7 ms in Python here for 10⁴ values. The expected answer, and the same "how far can this level reach" idea as Jump Game (55).

In practice No shortcut

No standard library function solves this. A graph library's shortest path would work on the jump graph, but building that graph takes up to n × 1000 edges, more work than the DP.

Write Approach 3. Remember the two details: count a jump when i == end, and stop the loop before the last index.
