338. Counting Bits Easy Bit Manipulation Dynamic Programming
Key idea: i >> 1 is i without its last bit. It's smaller, so its count is already known: ans[i] = ans[i >> 1] + (i & 1). One step per number, O(n).

Problem View on LeetCode (opens in a new tab) ↗

Return an array ans of length n + 1 where ans[i] is the number of 1 bits in i.

  • 0 <= n <= 10⁵
  • Follow-up: do it in O(n) without a built-in popcount.

Example: n = 2 → [0,1,1]. n = 5 → [0,1,1,2,1,2].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
n = 0 [0] The array still has one entry.
n = 3 [0,1,1,2] ans[i >> 1] + i & 1 without brackets means (ans[i >> 1] + i) & 1, because + comes before &. It gave [0,1,1,0], and was wrong for 297 of the 300 values of n tried.

Approach 1: Count Each Number

For every i, clear its lowest 1 with x & (x − 1) until it's 0, counting the rounds (as in 191. Number of 1 Bits).

  • Nothing is reused between numbers.
Time O(n log n) Space O(1) besides the answer

n = 10⁵, average of 60 runs: Python 40 ms, Java 0.44 ms, C++ 0.063 ms.

Approach 2: DP on the Lowest 1

i & (i − 1) is i with its lowest 1 cleared. It's smaller, so its count is known, and it has exactly one 1 less: ans[i] = ans[i & (i − 1)] + 1.

  • O(n) and short.
Time O(n) Space O(1) besides the answer

n = 10⁵: Python 5.2 ms, Java 0.087 ms, C++ 0.23 ms. In C++ that's slower than Approach 1. Probably because for every odd i, i & (i − 1) is i − 1: each step waits for the value the step before just wrote.

Approach 3: DP on the Last Bit Optimal

i >> 1 drops the last bit, so ans[i] = ans[i >> 1] + (i & 1). Odd numbers have one more 1 than half of them; even numbers have the same.

  • It reads ans[i / 2], written long ago, so steps don't wait on each other.
Time O(n) Space O(1) besides the answer

n = 10⁵: Python 5.4 ms, Java 0.069 ms, C++ 0.039 ms. Fastest in C++ (5.8 times Approach 2) and Java; in Python, 5% behind Approach 2.

In practice Built-ins

Call a popcount on each number: i.bit_count() (Python 3.10+), __builtin_popcount or C++20's std::popcount, Java's Integer.bitCount. It doesn't meet the follow-up, but it's what you'd write.

Time O(n) Space O(1) besides the answer

n = 10⁵: Python 2.3 ms (2.3 times faster than Approach 3), C++ 0.018 ms (2.2 times faster). Java 0.21 ms, 3 times slower than Approach 3 here.
