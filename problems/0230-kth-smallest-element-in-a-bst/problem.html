230. Kth Smallest Element in a BST Medium Binary Search Tree Depth-First Search Stack
Key idea: An in-order walk of a BST (left subtree, node, right subtree) visits the values in sorted order. Walk it with a stack and stop at the k-th node you pop: O(h + k) time, O(h) space, where h is the tree's height.

Problem View on LeetCode (opens in a new tab) ↗

Given the root of a binary search tree and k, return the k-th smallest value in it (counting from 1).

  • 1 <= k <= n <= 10⁴
  • 0 <= Node.val <= 10⁴

Example: [3,1,4,null,2], k = 1 → 1. [5,3,6,2,4,null,null,1], k = 3 → 3.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2,1], k = 2 2 Pre-order (node first) isn't sorted: it said 1. Reading the level-order list as if it were sorted fails the same way; wrong on 2400 of 3105 tests.
10⁴ nodes, each the left child of the last - The tree is one long chain. The recursive Python versions hit RecursionError at the default limit of 1000, so they raise it.
[1], k = 1 1 One node.
10⁴ nodes, k = n the largest No early stop helps: every node is visited.

Approach 1: List Every Value In Order

Do a full in-order walk, appending each value. The list comes out sorted, so the answer is vals[k − 1].

  • Simple, but it visits all n nodes even when k is 1.
Time O(n) Space O(n)

10⁴ random values, k = 1: Python 1.2 ms, Java 0.13 ms, C++ 0.08 ms; about the same for any k.

Approach 2: Recursive In-Order, Stop Early

Same walk, but count down from k as each value is visited. At 0, save the value and make every remaining call return straight away.

  • No list of values; the work is about h + k nodes.
  • The early-stop flag must be checked after the left call, or the walk keeps going.
Time O(h + k) Space O(h) call stack

10⁴ random values, k = 1: Python 2.4 µs, Java 0.5 µs, C++ 0.1 µs, 500 times faster than Approach 1 in Python. With k = n it's no faster.

Approach 3: Iterative In-Order With a Stack Optimal

Push nodes while going left. Pop: that's the next smallest value. If it's the k-th pop, return it; otherwise move to its right child and repeat.

  • No recursion, so a 10⁴-node chain is fine in every language.
  • The stack holds at most one root-to-leaf path.
Time O(h + k) Space O(h)

10⁴ random values, k = n: Python 1.0 ms (the fastest in Python), Java 0.10 ms, C++ 0.06 ms (about the same as Approach 2). A 10⁴ chain with k = 1: Python 0.36 ms, against 1.7 ms for Approach 2.

In practice No shortcut

LeetCode's TreeNode has no methods. A sorted structure like Java's TreeSet or C++'s std::set doesn't give the k-th element directly either.

Follow-up (many inserts and queries): store each node's subtree size, then pick the side by comparing k with the left size, O(h) per query.
