322. Coin Change Medium Dynamic Programming Breadth-First Search
Key idea: The last coin you use is one of coins, so dp[a] = 1 + min(dp[a − c]) over every coin that fits. Fill dp from 0 up to amount, with "impossible" as a value bigger than any real answer. O(amount × coins). Greedy (biggest coin first) doesn't work.

Problem View on LeetCode (opens in a new tab) ↗

Return the fewest coins that add up to amount, using any number of each coin value, or -1 if it can't be done.

  • 1 <= coins.length <= 12, 1 <= coins[i] <= 2³¹ − 1
  • 0 <= amount <= 10⁴

Example: [1,2,5], 11 → 3 (5 + 5 + 1). [2], 3 → -1. [1], 0 → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[3,4], 6 2 Greedy takes a 4 and gets stuck with 2 left: it said -1. Wrong on 472 of 3007 tests.
[2147483647], 2 -1 A huge coin. In C++ and Java, a + coin overflows an int; the BFS adds in 64 bits.
[1], 10⁴ 10000 The recursion goes 10⁴ calls deep. On Python 3.14, writing the inner loop as min(1 + fewest(a − c) for …) crashed with a stack overflow even with a raised recursion limit; a plain for loop worked.
[1], 0 0 Nothing to pay: zero coins, not −1.

Approach 1: Recursion with Memo

fewest(a) = 0 for a = 0, otherwise 1 + fewest(a − c) for the best coin c ≤ a. Remember each result, with "impossible" as infinity (or −1).

  • The calls can go amount deep when there's a 1-coin.
Time O(amount · coins) Space O(amount)

12 coins, amount 10⁴: Python 22 ms, Java 0.31 ms, C++ 0.23 ms.

Approach 2: BFS Over Amounts

Level k of a BFS from 0 holds every amount you can make with k coins. Add each coin to each amount in the level. The first level that reaches amount is the answer: BFS finds the fewest steps.

  • Stops as soon as the amount is reached, so it often does less work than the DP.
  • Each amount is queued at most once.
Time O(amount · coins) Space O(amount)

12 coins, amount 10⁴: Python 5.9 ms, C++ 0.10 ms, the fastest in both. Java 0.30 ms.

Approach 3: Bottom-Up DP Optimal

dp[0] = 0, everything else amount + 1 (more than any real answer). For each amount from 1 up, try every coin as the last one. dp[amount] is the answer if it's still ≤ amount.

  • No recursion and no queue: two loops and one array.
  • Using amount + 1 instead of infinity means no overflow when you add 1.
Time O(amount · coins) Space O(amount)

12 coins, amount 10⁴: Python 6.7 ms, Java 0.10 ms (the fastest in Java), C++ 0.30 ms. The expected answer, and the base for Coin Change II.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write.
