239. Sliding Window Maximum Hard Sliding Window Monotonic Queue Heap (Priority Queue)
Key idea: Keep a deque of indexes whose values go down from front to back. When a new value comes in, pop every smaller (or equal) value from the back: they're older and smaller, so they can never be a max again. Drop the front when it slides out. The front is always the window's max. Each index goes in and out once: O(n).

Problem View on LeetCode (opens in a new tab) ↗

A window of size k slides from the left of nums to the right, one step at a time. Return the largest value in each window.

  • 1 <= k <= nums.length <= 10⁵
  • -10⁴ <= nums[i] <= 10⁴

Example: [1,3,-1,-3,5,3,6,7], k = 3 → [3,3,5,5,6,7]. [1], k = 1 → [1].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[9,11], k = 2 [11] A deque that never pops smaller values from the back keeps 9 at the front: it said [9]. Wrong on 2165 of 3006 tests.
[7,7,7], k = 2 [7,7] Equal values. Popping only strictly smaller ones is also correct (all 3006 tests passed); popping equal ones keeps the deque shorter.
[1], k = 1 [1] Every window is one value.
10⁵ rising values, k = 5·10⁴ - The heap never pops anything until it reaches the top: it grows to 10⁵ entries.

Approach 1: Scan Every Window

For each of the n − k + 1 windows, look at all k values and take the biggest.

  • Fine when k is small; at k ≈ n / 2 it's about n² / 4 steps.
Time O(n·k) Space O(1) besides the answer

Just 10⁴ values with k = 5000: Python 0.31 s, Java 23 ms, C++ 16 ms. At 10⁵ it's 100 times more: too slow.

Approach 2: Max-Heap, Lazy Removal

Push (value, index) for each value. Before reading the top, pop it while its index is outside the window. Values that slid out but aren't on top can stay: they're not in the way yet.

  • Removing from the middle of a heap is hard; waiting until an old value reaches the top avoids it.
  • The heap can hold up to n entries.
Time O(n log n) Space O(n)

10⁵ rising values, k = 5·10⁴: Python 55 ms, Java 6.6 ms, C++ 1.1 ms.

Approach 3: Monotonic Deque Optimal

For each index i: pop from the back while the value there is ≤ nums[i]; push i; drop the front if it's out of the window; once the first window is full, record the front's value.

  • Store indexes, not values, so you can tell when the front slides out.
  • The Java version uses an array with two pointers as the deque, so no index is boxed into an Integer.
Time O(n) Space O(k)

10⁵ rising values, k = 5·10⁴: Python 15 ms, Java 0.29 ms, C++ 0.32 ms, the fastest in every language and on every input tried.

In practice No shortcut

No standard library has a sliding max. Outside LeetCode, NumPy's sliding_window_view(nums, k).max(axis=1) works, but it's still O(n·k) inside.

Approach 3 is what you'd write.
