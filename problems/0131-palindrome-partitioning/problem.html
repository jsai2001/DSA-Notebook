131. Palindrome Partitioning Medium String Backtracking Dynamic Programming
Key idea: Backtracking. Choose the next piece s[start..end] only if it's a palindrome, split the rest the same way, then undo and try a longer piece. Build a table pal[i][j] first, so each "is this a palindrome?" is one lookup instead of a scan.

Problem View on LeetCode (opens in a new tab) ↗

Split s into pieces so that every piece is a palindrome (reads the same backwards). Return every possible split, in any order.

  • 1 <= s.length <= 16
  • s is lowercase English letters

Example: "aab" → [["a","a","b"], ["aa","b"]]. "a" → [["a"]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"aab" [["a","a","b"], ["aa","b"]] Saving path itself instead of a copy said [[], []]: both entries are the same list, emptied by the undos.
"aab" (same) Forgetting the undo (path.pop()) said [["a","a","b"], ["a","a","b","aa","b"]]: old pieces stay in the path.
"a" [["a"]] One letter is always a palindrome.
"abcdefghijklmnop" 1 split All different: only single letters work.
"abba" 3 splits a|b|b|a, a|bb|a and abba: a whole-word piece counts too.
"a" × 16 32,768 splits Every one of the 2¹⁵ ways to cut works. The answer itself is the cost: all three approaches took 3–21 ms here, mostly building the output.

Approach 1: Backtracking, Checking Each Piece

From position start, try every end. If s[start..end] is a palindrome (two pointers moving inward), add it to path, split the rest from end + 1, then remove it and try the next end. When start reaches the end of s, save a copy of path.

  • Choose, explore, undo: the same pattern as Subsets and Permutations.
  • The same piece is checked again every time the search reaches it: on "a" × 16, the checks compared 43,682 letter pairs.
Time O(n² · 2ⁿ) Space O(n) besides the output

Up to 2ⁿ calls, each trying up to n ends, each check O(n). On "a" × 16 here: Python 21 ms, Java 10 ms, C++ 3.4 ms. At n ≤ 16 the extra checking barely shows; the output dominates.

Approach 2: Backtracking With a Palindrome Table Optimal

Fill pal[i][j] before searching: s[i..j] is a palindrome when s[i] == s[j] and the inside s[i+1..j-1] is one too (or is 0–1 letters long). Fill i from the end backwards, so the inside is always ready. Then backtrack as before with O(1) checks.

  • The table has n(n + 1) / 2 useful entries: 136 for n = 16, filled once.
  • Same idea as Longest Palindromic Substring (5), reused here.
Time O(n · 2ⁿ) Space O(n²) for the table

The work left is building the output: up to 2ⁿ⁻¹ splits, each copied in O(n), so no approach can do better. On "a" × 16: Python 18 ms, Java 8 ms, C++ 3.9 ms. The answer to give in an interview.

Approach 3: Build Splits of Every Suffix (DP)

Let parts[i] be every split of the suffix s[i:]. The empty suffix has one split, with no pieces. Going from the end backwards, each split of s[i:] is a palindrome s[i..end] followed by a split from parts[end + 1]. No recursion and no undo.

  • Each suffix's splits are built once and reused.
  • The cost is memory: it keeps the splits of every suffix, not just the answer. On "a" × 16 it stored 65,536 lists to return 32,768.
Time O(n · 2ⁿ) Space O(n · 2ⁿ)

On "a" × 16: Python 12 ms (fastest in Python here, since there are no recursive calls), Java 13 ms, C++ 8 ms (slowest in C++: more lists to build). A good way to show the DP view of the same problem.

In practice No shortcut

No standard library function splits a string into palindromes. The built-in that helps is the check itself: in Python, piece == piece[::-1] is shorter than a two-pointer loop and runs in C.

Approach 2 is what you'd write. With n ≤ 16, Approach 1 is also fine in practice, since the output size, not the checks, sets the time.
