207. Course Schedule Medium Graph Topological Sort
Key idea: The courses can all be taken unless the prerequisites form a cycle. Kahn's algorithm finds out: keep a count of untaken prerequisites per course, take any course whose count is 0, and lower the counts of the courses after it. If every course gets taken, there's no cycle. O(n + p).

Problem View on LeetCode (opens in a new tab) ↗

There are numCourses courses, 0 to numCourses − 1. prerequisites[i] = [a, b] means you must take b before a. Return whether you can finish all of them.

  • 1 <= numCourses <= 2000, 0 <= prerequisites.length <= 5000
  • All pairs are different; a != b

Example: 2, [[1,0]] → true. 2, [[1,0],[0,1]] → false (each waits on the other).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
2, [[0,1]] true A DFS with one visited set that calls any visited course a cycle said false: reaching a finished course isn't a cycle. Wrong on 1551 of 3049 tests.
2, [[1,0],[0,1]] false The opposite mistake, "visited means fine", misses real cycles: it said true. Wrong on 587 tests. You need a third state, "on the current path".
2000 courses in one chain true The round-by-round approach needs 2000 rounds: 245 ms in Python. The DFS goes 2000 calls deep.
1, [] true No prerequisites at all.

Approach 1: Take Courses in Rounds

Each round, scan every pair and count how many unfinished prerequisites each course has. Take every course with a count of 0. If courses are left but none is ready, they wait on each other: a cycle.

  • The same idea as Approach 3, but it recounts everything every round.
  • A chain needs one round per course.
Time O(n·(n + p)) Space O(n)

A 2000-course chain: Python 245 ms, Java 8.3 ms, C++ 5.9 ms. About 400 times slower than Approach 3 in Python.

Approach 2: DFS With Three States

Mark a course 1 when the DFS enters it and 2 when every course after it is checked. Meeting a course that's still 1 means you came back around to the current path: a cycle. A course that's 2 is safe and is never searched again.

  • Two states aren't enough (see the edge cases): "finished" and "on the path" mean different things.
  • The calls can go n deep: Python needs a higher recursion limit for 2000.
Time O(n + p) Space O(n + p)

A 2000-course chain: Python 0.84 ms. Slowest over 3049 tests: Python 7.8 ms, Java 0.36 ms, C++ 0.31 ms.

Approach 3: Kahn's Algorithm (BFS) Optimal

Count each course's prerequisites once (need). Queue the courses with need 0. Each time you take one, lower need for the courses after it and queue any that hit 0. At the end, compare how many you took with numCourses.

  • Courses on a cycle never reach 0, so they're never taken.
  • No recursion, and the order you take them in is a valid schedule (that's Course Schedule II).
Time O(n + p) Space O(n + p)

A 2000-course chain: Python 0.62 ms. Slowest over 3049 tests: Python 4.1 ms, Java 0.48 ms, C++ 0.29 ms.

In practice No shortcut

Python's graphlib.TopologicalSorter (3.9+) raises CycleError when there's a cycle, so it can answer this outside LeetCode. C++ and Java have nothing built in.

On LeetCode, Approach 3 is what you'd write.
