211. Design Add and Search Words Data Structure Medium Trie Design Depth-First Search
Key idea: Store the words in a trie. Search with a DFS over the pattern: a letter follows its one child, a "." tries every child, and a match must end on a node marked as a word end. Words that don't share the pattern's letters are never looked at.

Problem View on LeetCode (opens in a new tab) ↗

Build WordDictionary with addWord(word) and search(word). In search, each "." matches any one letter. Return whether some added word matches.

  • 1 <= word.length <= 25; added words are lowercase letters
  • A search has at most 2 dots; at most 10⁴ calls in total

Example: add bad, dad, mad. search("pad") → false, search("bad") → true, search(".ad") → true, search("b..") → true.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
add ab, cd; search(".d") true A "." must try every child. Returning the result of the first child only said false; wrong on 414 of 2001 tests.
add bad; search("ba") false The letters match but "ba" isn't a word: check the end flag.
add a; search(".") true A pattern that's only a dot.
5000 words of length 25, then 5000 searches starting with ".." all false The list and the length groups compare every word: 11 s+ in Python. The trie takes 0.94 s.

Approach 1: List of Words

Keep every word in a list. To search, compare the pattern with each word of the same length, letter by letter, letting "." match anything.

  • The simplest to write, and addWord is O(1).
  • Every search can touch every word.
Time O(N·L) per search Space O(total letters)

5000 words of length 25, then 5000 ".." searches: Python 11.3 s, Java 93 ms, C++ 87 ms. Even exact searches took 1.2 s in Python.

Approach 2: Group by Length

Only words of the same length can match, so keep a set per length. A search without "." is one hash lookup. A search with dots scans just its length group.

  • The fastest for exact searches: 2.8 ms for 5000 in Python.
  • But if all words have the same length, a dotted search still checks them all.
Time O(L) exact, O(N·L) with dots Space O(total letters)

The ".." test above: Python 11.8 s, Java 226 ms, C++ 120 ms, no better than Approach 1, because every word has length 25.

Approach 3: Trie With DFS Optimal

addWord is a normal trie insert. dfs(node, i) asks whether word[i:] can be spelled from node: at the end, check the end flag; on a letter, follow that one child; on ".", try every child and stop at the first success.

  • Shared prefixes are walked once, and wrong letters cut whole branches.
  • With at most 2 dots, a search visits at most 26² branches.
  • The Python version uses dict children: in Implement Trie, dicts were faster than 26-slot lists in Python.
Time O(L) letters, up to O(26ᵈ·L) with d dots Space O(total letters)

The ".." test: Python 0.94 s, Java 37 ms, C++ 27 ms, 12 times faster than Approach 1 in Python. For exact searches, Approach 2 was faster (2.8 ms vs 15 ms in Python).

In practice No shortcut

re.fullmatch(pattern, word) treats "." the same way, but it still has to be run on every word. No standard library has a trie.

Approach 3 is what you'd write.
