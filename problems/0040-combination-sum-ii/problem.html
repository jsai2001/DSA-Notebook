40. Combination Sum II Medium Array Backtracking
Key idea: Combination Sum with two changes. Each number is used once, so recurse with i + 1. The input has duplicates, so sort it and, in the loop, skip a value equal to the previous one at the same level: if i > start and nums[i] == nums[i - 1]: continue. Equal numbers can still be used together, just not started from twice.

Problem View on LeetCode (opens in a new tab) ↗

Given a list of numbers candidates (which may contain duplicates) and a target, return every unique combination that adds up to target. Each number in the list may be used only once in a combination, and the answer must not contain the same combination twice.

  • 1 <= candidates.length <= 100 and 1 <= candidates[i] <= 50.
  • 1 <= target <= 30.

Examples: [10,1,2,7,6,1,5], target 8 → [[1,1,6],[1,2,5],[1,7],[2,6]]; [2,5,2,1,2], target 5 → [[1,2,2],[5]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1,1], target 1 [[1]] The duplicate trap: either 1 makes [1], but it should be listed once.
[1,1], target 2 [[1,1]] Over-skipping: equal numbers may be used together. Skipping with i > 0 instead of i > start returns [].
[1,2,1], target 3 [[1,2]] Unsorted input. Without sorting, a set sees [1,2] and [2,1] as different.
[2], target 4 [] Each number only once: unlike Combination Sum, [2,2] isn't allowed. Recursing with i gives it.
[2], target 1 [] Nothing fits.
[10,1,2,7,6,1,5], target 8 [[1,1,6],[1,2,5],[1,7],[2,6]] The usual case: [1,7] must appear once even though there are two 1s.
[2,5,2,1,2], target 5 [[1,2,2],[5]] Three 2s, two used together.
[50], target 30 [] The only candidate is bigger than the target.
100 ones, target 30 [[1, …, 1]] (thirty 1s) One answer, but take-or-skip with a set tries every way to choose 30 of the 100 ones.

Approach 1: Take or Skip, Then Drop Repeats with a Set

For each number, take it or skip it, and collect every path that adds up to the target in a set. Sorting first makes equal combinations come out in the same order, so the set can recognise repeats.

  • Recurse with i + 1 after taking: each copy is used at most once.
  • A set of tuples (C++ std::set, Java HashSet<List>) keeps one of each.
Time O(2ⁿ · n) Space O(n) recursion, plus the set

It finds every repeat and then throws it away. With many equal numbers that's hopeless: on 22 ones with target 11 it made 4.9 million calls here, against 12 for Approach 2, and 100 ones would never finish.

Approach 2: Sort and Skip Repeats at the Same Level Optimal

Build each combination in sorted order. At one level of the recursion (one position in the combination), trying the value 1 a second time would just repeat everything the first 1 already built, so skip it.

  • if i > start and nums[i] == nums[i - 1]: continue. It's i > start, not i > 0: the first copy at this level is always allowed, which is how [1,1,6] uses two 1s.
  • Recurse with i + 1: each copy is used at most once.
  • Break as soon as a number is bigger than what's left (it's sorted).
Time O(2ⁿ · n) worst case Space O(n) recursion

Every combination is built exactly once, so no set is needed. All 503 large tests here (up to 100 candidates) took about 1 s in Python together. The "skip equal values at the same level" line is the same one used in 3Sum, Subsets II and Permutations II.

Approach 3: Count Each Value, Choose How Many Copies

Equal numbers are interchangeable, so treat them as one choice: for each distinct value, use 0, 1, 2, … copies, up to how many exist and how many fit.

  • Count the values (Counter, std::map, TreeMap) and sort them.
  • At value k, try using none, then add one copy at a time and recurse to k + 1. Afterwards take the copies off again.
  • Stop when the value is bigger than what's left: all later values are bigger too.
Time O(2ⁿ · n) worst case Space O(n) recursion

Same speed as Approach 2, and duplicates are impossible by design instead of skipped. The recursion depth is the number of distinct values, which helps when there are many repeats.

In practice No shortcut

Python's itertools.combinations tries every subset of a given size, but repeated values produce repeated combinations, and going through every size of up to 100 numbers is far too slow. C++ and Java have nothing built in.

Write Approach 2. Three things change from Combination Sum: sort, recurse with i + 1, and skip a value that equals the previous one when i > start.
