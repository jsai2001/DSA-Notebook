39. Combination Sum Medium Array Backtracking
Key idea: Backtrack with a start index. From start on, try each candidate, recurse with the same index i (so it can be reused) and never go back to smaller indices (so [2,3] and [3,2] aren't both built). Sort first, and break as soon as a candidate is bigger than what's left.

Problem View on LeetCode (opens in a new tab) ↗

Given an array of distinct integers candidates and a target, return every unique combination of candidates that adds up to target. The same number may be chosen any number of times. Two combinations are different if some number is used a different number of times. Any order is fine.

  • 1 <= candidates.length <= 30 and 2 <= candidates[i] <= 40, all different.
  • 1 <= target <= 40.
  • The tests have fewer than 150 combinations for each input.

Examples: [2,3,6,7], target 7 → [[2,2,3],[7]]; [2,3,5], target 8 → [[2,2,2,2],[2,3,3],[3,5]]; [2], target 1 → [].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2], target 1 [] Every candidate is bigger than the target: return an empty list, not [[]].
[2], target 2 [[2]] The smallest case with an answer: one candidate used once.
[3,5], target 4 [] Smaller than one candidate, but no mix of them hits it exactly.
[2,3], target 5 [[2,3]] The duplicate trap: [3,2] is the same combination. Looping over all candidates at every level builds both.
[2,3,6,7], target 7 [[2,2,3],[7]] Reuse: 2 appears twice. Recursing with i + 1 instead of i misses [2,2,3].
[3,2], target 2 [[2]] Unsorted input. Breaking at the first candidate that's too big (3) only works after sorting; without it this returns [].
[2,3,5], target 8 [[2,2,2,2],[2,3,3],[3,5]] Several answers of different lengths.
[2], target 40 Twenty 2s The deepest path: 20 levels of recursion.
[40], target 40 [[40]] The largest values allowed.

Approach 1: Take or Skip

Look at the candidates one at a time. For the current one, there are only two choices: take it (and stay on it, since it can be taken again), or skip it and never use it again on this path.

  • Reaching remaining == 0 means the path is an answer.
  • Running out of candidates or going below 0 is a dead end. Because "skip" always moves forward, each combination is built in exactly one way: no duplicates.
Time O(2^(T/M + n)) roughly Space O(T/M + n) recursion

Here T is the target, M the smallest candidate and n the number of candidates. It's correct and simple, but it only notices an overshoot after making the call, and it spends a level on every skip.

Approach 2: Backtracking with a Start Index Optimal

Build each combination in non-decreasing order. At every level, loop over the candidates from start on, take one, and recurse with start = i.

  • backtrack(i, …), not i + 1: the same number can be used again.
  • Never looking before start is what stops [3,2] after [2,3].
  • After sorting, the first candidate bigger than remaining ends the loop: all later ones are bigger too.
  • Add a copy of path to the result; the list itself keeps changing.
Time O(n^(T/M + 1)) worst case Space O(T/M) recursion

Exponential in the worst case, like any method that lists every answer, but the pruning keeps it fast in practice. With 30 candidates and target 40 (6,131 answers, far beyond LeetCode's tests) it took 0.01 s in Python here. The same pattern solves Combination Sum II, Subsets and Permutations.

Approach 3: Dynamic Programming by Amount

This is Coin Change II (518) with the combinations kept instead of just counted. dp[t] holds every combination that adds up to t; each candidate c extends dp[t - c] into dp[t].

  • dp[0] = [[]]: one way to make 0, taking nothing.
  • Candidates in the outer loop, amounts in the inner loop: then all of one candidate is added before the next, so each combination is built in one order. Swapping the loops counts [2,3] and [3,2] separately.
Time total size of all dp lists Space answers for every t ≤ target

No recursion, but it builds and stores answers for every smaller amount, which are thrown away at the end. Worth knowing for the link to 518; in an interview, write Approach 2.

In practice No shortcut

Python's itertools.combinations_with_replacement can list multisets of a fixed size, but you'd have to try every size up to target / min(candidates) and filter by sum, which builds far more than it keeps. C++ and Java have nothing similar.

Write Approach 2. Remember the three details: sort, recurse with i, and append a copy of the path.
