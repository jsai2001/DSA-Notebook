424. Longest Repeating Character Replacement Medium Sliding Window String
Key idea: A window works when length − (count of its most common letter) <= k. Slide one window and keep top, the biggest letter count seen. When the window breaks the rule, slide it one step instead of growing. The window never shrinks, so top never needs to go down, and the final size is the answer. O(n).

Problem View on LeetCode (opens in a new tab) ↗

You may change at most k letters of s into any other uppercase letter. Return the length of the longest substring of one repeated letter you can get.

  • 1 <= s.length <= 10⁵, uppercase English letters, 0 <= k <= s.length

Example: s = "ABAB", k = 2 → 4. s = "AABABBA", k = 1 → 4 ("AABA" → "AAAA").

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
s = "A", k = 0 1 Zero changes needed is allowed. Sliding when changes >= k instead of > k gave 0, and was wrong on 1,754 of 3,008 tests.
s = "ABCDE", k = 5 5 k can cover the whole string.
10⁴ "A"s, k = 0 10000 The window never breaks, so "every start, grow until it breaks" checks all n²/2 windows.

Approach 1: Every Start, Grow Until It Breaks

For each start i, extend the end j, keeping letter counts and the biggest count. Once more than k letters would need changing, longer windows from i only need more, so move to the next start.

  • Correct, but nothing carries over from one start to the next.
Time O(n²) Space O(26)

10⁴ "A"s, k = 0: Python 9.5 s, Java 106 ms, C++ 108 ms.

Approach 2: One Window per Letter

Guess the letter c the run is made of. Then it's a plain sliding window: allow at most k letters that aren't c, shrinking from the left when there are more. Try each letter that appears in s.

  • Each window keeps one counter instead of 26.
Time O(26 · n) Space O(26)

10⁵ random letters, k = 100: Python 358 ms, Java 8.2 ms, C++ 5.5 ms. With only one letter in s it's a single pass (Python 9.8 ms on 10⁵ "A"s, faster than Approach 3).

Approach 3: One Window, Never Shrinking Optimal

Add s[hi] and update top. If length − top > k, drop s[lo] and move lo once, so the size stays the same. A bigger answer needs a bigger top, so a top that's too big for the current window never causes a wrong answer: it only holds the size.

  • No need to recount the most common letter after a slide.
  • The answer is n − lo, the window's final size.
Time O(n) Space O(26)

10⁵ random letters, k = 100: Python 18 ms, Java 1.6 ms, C++ 0.20 ms: 5 (Java) to 28 (C++) times faster than Approach 2.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write.
