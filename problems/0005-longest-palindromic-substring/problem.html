5. Longest Palindromic Substring Medium String Dynamic Programming Two Pointers
Key idea: Every palindrome mirrors around a center, and there are only 2n - 1 centers: each character (odd length) and each gap between two characters (even length). Expand outward from each one while both ends match. O(n²) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given a string s, return the longest substring of s that reads the same forwards and backwards.

  • 1 <= s.length <= 1000
  • s is made of digits and English letters.
  • If several have the same longest length, any one is accepted.

Examples: "babad" → "bab" ("aba" is also fine); "cbbd" → "bb".

Approach 1: Brute Force by Length

Try every length from 1 to n. For each length, slide a window across the string and check it with s == s[::-1]. The first hit is recorded and the scan moves on to the next length, so the last length that had any palindrome wins.

  • It has to keep going after a length with no palindrome: in "aba" there's none of length 2 but there is one of length 3.
  • The break means a length stops at its first palindrome, so strings with lots of palindromes finish quickly.
Time O(n³) Space O(n)

Worst case (few palindromes) checks every window of every length: about n³/6 character comparisons, ~1.7 × 10⁸ at n = 1000. It still passes because slicing and reversing run in C; a random 1000-character string took about 0.2 s in Python here. Two small notes: min_len never limits the loop (it's always <= str_len), so it can be dropped, and despite its name it holds the longest length found. Scanning lengths from longest to shortest and returning the first hit would stop much sooner.

Approach 2: Dynamic Programming Table

A substring is a palindrome when its two ends match and the part inside is a palindrome. Store that in a table so the inside is never checked twice.

  • dp[i][j] = s[i] == s[j] and (j - i < 2 or dp[i + 1][j - 1]).
  • Fill by increasing length, so dp[i + 1][j - 1] is always ready. Track the longest true cell.
Time O(n²) Space O(n²)

About n²/2 cells, each O(1). The table is 10⁶ booleans at n = 1000, which is fine, but it's memory that Approach 3 doesn't need.

Approach 3: Expand Around Center

Instead of checking substrings, grow palindromes from their middle. Try each of the 2n - 1 centers and expand left and right while s[left] == s[right].

  • Odd lengths center on a character (left = right = i); even lengths center on a gap (left = i, right = i + 1).
  • When it stops, the palindrome is s[left + 1 .. right - 1], length right - left - 1.
Time O(n²) Space O(1)

Same time as the table, no extra memory, and short to write. This is the answer most interviews expect.

Approach 4: Manacher's Algorithm Optimal

Expand around center, but reuse work. Inside a palindrome, the right side mirrors the left side, so a center's radius is at least its mirror's (up to the palindrome's edge).

  • Put # between characters (and sentinels ^, $ at the ends) so every palindrome has odd length. p[i] is the radius at t[i], which equals the palindrome's length in s.
  • Keep the palindrome reaching furthest right (center, right). For i < right, start from min(right - i, p[2 * center - i]), then expand.
Time O(n) Space O(n)

right only moves forward, so all the expansions together take O(n). It's the fastest, but it's rarely asked for: knowing the idea is usually enough.

In practice No shortcut

The standard libraries can check a palindrome (s == s[::-1] in Python, std::equal(s.begin(), s.end(), s.rbegin()) in C++, new StringBuilder(s).reverse() in Java), but none can find the longest one. Using that check on every substring is Approach 1.

Expand around center (Approach 3) is what you'd write in real code: short, O(n²), and no extra memory.

Comparison

Approach Technique Time Space Notes
Brute Force by Length Check every window of every length O(n³) O(n) Passes thanks to fast slicing, but slowest
Dynamic Programming Table Ends match + inside is a palindrome O(n²) O(n²) Classic DP; uses an n × n table
Expand Around Center Grow from each of 2n - 1 centers O(n²) O(1) Expected answer in interviews
Manacher's Algorithm Reuse mirror radii in a padded string O(n) O(n) Fastest; rarely required
