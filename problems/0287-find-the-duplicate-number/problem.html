287. Find the Duplicate Number Medium Two Pointers Binary Search Array
Key idea: Read i → nums[i] as a link. Every value is 1..n, so following the links from index 0 never comes back to 0 and must run into a cycle. The repeated value has two links pointing to it, so it's where the cycle begins. Floyd's slow/fast pointers find that entry in O(n) time, O(1) space, without changing nums.

Problem View on LeetCode (opens in a new tab) ↗

nums has n + 1 values, each in 1..n. Exactly one value repeats (possibly more than twice). Return it without changing nums and using only O(1) extra space.

  • 1 <= n <= 10⁵

Example: [1,3,4,2,2] → 2. [3,1,3,4,2] → 3. [3,3,3,3,3] → 3.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2,2,2] 2 The value can repeat more than twice, so some values are missing. "sum(nums) − (1 + … + n)" said 3; wrong on 737 of 3006 tests.
[1,1] 1 The smallest case: n = 1.
[3,1,3,4,2] 3 Sorting would find it, but the problem says not to change nums.

Approach 1: Seen Set

Remember every value; the first one you meet again is the answer. The values are 1..n, so C++ and Java use an array of n flags.

  • Simple and fast, but uses O(n) extra space, which the problem doesn't allow.
Time O(n) Space O(n)

10⁵ values, one repeat: Python 4.0 ms, Java 0.30 ms, C++ 0.06 ms.

Approach 2: Binary Search on the Value

Guess mid and count the values ≤ mid. If there are more than mid, two of them must share a value in 1..mid (pigeonhole), so search left; otherwise search right.

  • O(1) space and nums stays as it is.
  • About 17 counting passes over all 10⁵ values.
Time O(n log n) Space O(1)

10⁵ values: Python 60 ms, Java 1.1 ms, the slowest in both. But C++ took only 0.08 ms, faster than Floyd there: each pass reads the array in order, which the CPU does very quickly.

Approach 3: Floyd's Cycle Detection Optimal

Phase 1: from index 0, move slow one link and fast two links per step until they meet inside the cycle. Phase 2: move slow back to 0 and step both one link at a time. They meet at the cycle's entry, the repeated value.

  • The same trick as Linked List Cycle II, with indexes instead of nodes.
  • Phase 2 works because the distance from 0 to the entry equals the distance from the meeting point to the entry, plus whole laps.
Time O(n) Space O(1)

10⁵ values, one repeat: Python 3.6 ms, Java 0.79 ms, C++ 0.71 ms. The fastest in Python and Java. In C++ Approach 2 won, probably because these jumps around memory are slow next to reading the array in order.

In practice No shortcut

Without the space rule you'd write Approach 1, or Counter(nums).most_common(1) in Python. With it, Approach 3 is the expected answer.
