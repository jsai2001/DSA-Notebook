136. Single Number Easy Array Bit Manipulation
Key idea: XOR all the numbers together. x ^ x = 0 and x ^ 0 = x, and the order doesn't matter, so every pair cancels out and only the single number is left. O(n) time, O(1) memory.

Problem View on LeetCode (opens in a new tab) ↗

In nums, every value appears exactly twice except one, which appears once. Return that one. The problem asks for O(n) time and O(1) extra memory.

  • 1 <= nums.length <= 3 × 10⁴
  • -3 × 10⁴ <= nums[i] <= 3 × 10⁴

Example: [2, 2, 1] → 1. [4, 1, 2, 1, 2] → 4.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[4, 1, 2, 1, 2] 4 Starting the XOR at nums[0] and then looping over all of nums uses 4 twice: said 0. Start at 0.
[1, 1, 2] 2 After sorting, the single number is last. Checking pairs all the way to the end read past it: IndexError.
[1] 1 No pairs at all.
[-1, -1, -2] -2 XOR works on negative numbers too: their bits cancel the same way.
[0, 1, 0] 1 0 can be a pair; it doesn't change the XOR.

Approach 1: Count With a Hash Map

Count how many times each value appears, then return the one counted once.

  • Works for any "find the value that appears k times" variant.
  • Uses O(n) memory, which the problem asks you to avoid.
Time O(n) Space O(n)

At n = 29,999 here: Python 2.3 ms, Java 11.5 ms, C++ 1.3 ms. Fast enough, but it doesn't meet the memory rule.

Approach 2: Sort, Then Check Pairs

After sorting, equal values sit side by side. Check the pairs (0, 1), (2, 3), …: the first pair that doesn't match starts with the single number. If every pair matches, it's the last value.

  • Stop the pair loop one short of the end, then handle the last value.
  • C++ and Java sort the input in place.
Time O(n log n) Space O(1) extra (O(n) in Python's sorted)

At n = 29,999: Python 3.8 ms, Java 11.2 ms, C++ 0.56 ms. Meets the memory rule in C++ and Java, but not the time rule.

Approach 3: XOR Everything Optimal

Start with result = 0 and XOR in every number. XOR is its own undo: the second time a value goes in, it flips back exactly the bits the first time flipped. The pairs cancel; the single number is what's left.

  • Order doesn't matter: XOR is commutative and associative, so the two copies of a value don't need to be next to each other.
  • Bit by bit: each bit of the result is 1 exactly when an odd number of inputs have a 1 there, and only the single number makes it odd.
Time O(n) Space O(1)

At n = 29,999: Python 0.9 ms, Java 0.6 ms, C++ 0.002 ms, the fastest here in every language. The answer the problem asks for.

In practice Built-ins

Approach 3 as a one-line fold: reduce(xor, nums) in Python, std::accumulate with std::bit_xor in C++, Arrays.stream(nums).reduce(0, (a, b) -> a ^ b) in Java.

Time O(n) Space O(1)

Same work as Approach 3: Python 1.0 ms, C++ 0.002 ms; the Java stream has some setup cost (6.2 ms). Another Python one-liner is 2 * sum(set(nums)) - sum(nums), which was right on 2,000 test arrays here, but builds a set, so it's O(n) memory.
