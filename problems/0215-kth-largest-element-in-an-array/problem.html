215. Kth Largest Element in an Array Medium Heap (Priority Queue) Quickselect Sorting
Key idea: You don't need the whole array sorted. A min-heap of size k keeps the k biggest values, and its top is the answer: O(n log k). Quickselect does better on average: split around a random pivot and keep only the side that holds the answer, O(n). Split into three parts (bigger, equal, smaller) so repeated values don't slow it down.

Problem View on LeetCode (opens in a new tab) ↗

Return the k-th largest value in nums: the k-th in sorted order, counting repeats (not the k-th distinct value). LeetCode asks for a solution without sorting.

  • 1 <= k <= nums.length <= 10⁵
  • -10⁴ <= nums[i] <= 10⁴

Example: [3,2,1,5,6,4], k = 2 → 5. [3,2,3,1,2,4,5,5,6], k = 4 → 4.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
10⁵ copies of 1, k = 50000 1 Quickselect with a 2-way split moves only one value per round when all are equal: 1.2 s in C++. The 3-way split took 0.07 ms.
[3,2,3,1,2,4,5,5,6], k = 4 4 Repeats count: the order is 6, 5, 5, 4. Removing duplicates first gives 3.
[1], k = 1 1 One value.
[2,1], k = 2 1 k = n is the smallest value: watch the off-by-one (index k − 1 from the top).

Approach 1: Sort

Sort, biggest first, and return index k − 1 (or sort ascending and take index n − k).

  • Two lines, and hard to get wrong.
  • It orders everything, which this problem doesn't need, and LeetCode asks you not to.
Time O(n log n) Space O(n) in Python, O(log n) in place

10⁵ random values: Python 10.9 ms, Java 4.7 ms, C++ 1.7 ms. In Python this is the fastest of the three, because the sort runs in C.

Approach 2: Min-Heap of Size k

Push each value into a min-heap. When it holds more than k, pop the smallest. At the end it holds the k biggest values, and the top is the smallest of those: the answer.

  • Works on a stream: you never need all of nums at once.
  • Fast for small k; slow when k is about n / 2.
Time O(n log k) Space O(k)

10⁵ random values, k = 50000: Python 30 ms, Java 9.5 ms, C++ 3.7 ms, the slowest here in every language.

Approach 3: Quickselect, 3-Way Split Optimal

Pick a random pivot and split the values into bigger, equal and smaller. If k falls in the bigger part, keep only that; if it falls on the equal part, the pivot is the answer; otherwise keep the smaller part and subtract what you skipped from k.

  • Each round keeps one side, so the work is n + n/2 + n/4 + … ≈ 2n on average.
  • The random pivot means no fixed input is always slow. The worst case is still O(n²), but it's very unlikely.
  • C++ and Java split in place (Dutch national flag); Python builds lists for clarity.
Time O(n) average, O(n²) worst Space O(1) in place (O(n) for Python's lists)

10⁵ random values: Java 1.2 ms, C++ 0.84 ms, the fastest written-out solution in both. Python 11.5 ms, about the same as sorting.

In practice Built-ins

C++ has std::nth_element, a quickselect that puts the k-th value in its sorted place. Python has heapq.nlargest(k, nums), which keeps a size-k heap. Java has neither, so use Approach 2 or 3.

Time O(n) average (C++), O(n log k) (Python) Space O(1) (C++), O(k) (Python)

Should pass on LeetCode. nth_element took 0.69 ms on 10⁵ values, the fastest here. heapq.nlargest took 56 ms with k = 50000: for a big k, sorted is faster in Python.
