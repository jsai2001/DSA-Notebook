3. Longest Substring Without Repeating Characters Medium String Hash Map Sliding Window
Key idea: Sliding window. Move right one step at a time, and remember the last index of every character. If s[right] was seen inside the window, jump left to just past that index. The answer is the largest right - left + 1. One pass, O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given a string s, find the length of the longest substring that has no repeating characters.

  • 0 <= s.length <= 5 * 10^4
  • s is made of English letters, digits, symbols and spaces.
  • A substring is contiguous. In "pwwkew" the answer is 3 ("wke"), not 4 ("pwke" is a subsequence, not a substring).

Examples: "abcabcbb" → 3 ("abc"), "bbbbb" → 1, "" → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
s = "" 0 Empty string: the answer is 0.
s = " " 1 A space is a character too.
s = "bbbbb" 1 All the same character.
s = "au" 2 The answer is the whole string, so update the best length inside the loop, not only when a repeat is found.
s = "dvdf" 3 Answer "vdf". Restarting the window after the repeat (at the second d) gives 2.
s = "abba" 2 At the last a, its earlier index is already left of the window. The left edge must never move backwards: use max.
s = "tmmzuxt" 5 Answer "mzuxt": the final t repeats a t that's already outside the window.
s = "a1 !a" 4 Digits, spaces and symbols count, so a 26-letter array isn't enough. Use a set, a map, or a 128-entry array.

Approach 1: Brute Force from Every Start

Try every starting index j. From there, extend i to the right while each new character hasn't been seen in this run, and stop at the first repeat.

  • A fresh hash map per start tracks characters in the current run.
  • tracker[i][j] holds the length of the run starting at j and ending at i, built from tracker[i-1][j] + 1. When i == j that cell is still 0, so it correctly starts at 1.
  • Keep the largest value seen in max_sub_len.
Time O(n²) Space O(n²)

The loops break at the first repeat, so each start only scans at most (charset size + 1) characters. But creating the n × n tracker table already costs O(n²) time and memory: for n = 5 × 10^4 that's 2.5 billion cells, which can hit Memory or Time Limit Exceeded. tracker[i][j] is always just i - j + 1, so the table can be dropped and replaced by that expression for O(1) extra memory. Also, naming a variable hash shadows Python's built-in hash().

Approach 2: Sliding Window with a Set

Restarting from every index throws away work. Instead, keep one window s[left..right] with no repeats and a set of its characters.

  • Move right forward one character at a time.
  • While s[right] is already in the set, remove s[left] and move left forward.
  • Add s[right] and update the best length right - left + 1.
Time O(n) Space O(min(n, m))

Each character enters and leaves the window at most once, so it's at most 2n steps. m is the charset size (the set never holds more distinct characters than that).

Approach 3: Sliding Window with Last-Seen Index Optimal

Rather than shrinking the window one step at a time, jump straight past the duplicate. Store {char: last index}.

  • If s[right] was last seen at index k >= left, set left = k + 1.
  • The k >= left check matters: an index from before the window is stale and must not move left backwards (for example "abba").
  • Record last[s[right]] = right and update the best length.
Time O(n) Space O(min(n, m))

Exactly one pass with O(1) work per character. In C++ and Java a fixed array of 128 slots works as the map, since the input is ASCII.

In practice No shortcut

There's no built-in for "longest substring without repeats". You can lean on set() and check every slice with len(set(s[i:j])) == j - i, but that's O(n³) and times out well before n = 5 × 10⁴.

The sliding window with last-seen index (Approach 3) is about eight lines and is what you'd use in real code too.

Comparison

Approach Technique Time Space Notes
Brute Force from Every Start Extend from each start until a repeat O(n²) O(n²) n × n table can exceed memory limits
Sliding Window with a Set Shrink from the left until no duplicate O(n) O(min(n, m)) Up to 2n steps; easy to reason about
Sliding Window with Last-Seen Index Jump left past the duplicate O(n) O(min(n, m)) Single pass; expected answer in interviews
