105. Construct Binary Tree from Preorder and Inorder Traversal Medium Tree Hash Table Divide and Conquer
Key idea: preorder[0] is the root. Find it in inorder: everything to its left there is the left subtree, everything to its right is the right subtree. Repeat on each part. A map from value to inorder index makes each lookup O(1), and taking the roots from preorder one by one (left subtree first) avoids copying: O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given the preorder (node, left, right) and inorder (left, node, right) lists of the same binary tree, build the tree and return its root.

  • 1 to 3000 nodes; -3000 <= value <= 3000.
  • All values are different (that's what makes the tree unique).
  • Both lists really come from the same tree.

Example: preorder = [3,9,20,15,7], inorder = [9,3,15,20,7] → [3,9,20,null,null,15,7].

Edge cases

Try these against your solution before reading the approaches.

Input (preorder, inorder) Expected Why it's tricky
[-1], [-1] [-1] One node: both subtrees are empty parts.
[1,2], [2,1] [1,2] The root is last in inorder: the right part is empty.
[1,2], [1,2] [1,null,2] The same preorder, but now the root is first in inorder: 2 goes on the right. Only inorder tells left from right.
The example, building the right subtree first [3,9,20,null,null,15,7] Preorder lists the whole left subtree before the right. Taking roots from it in the wrong order uses the wrong values, and here it runs off the end of preorder (IndexError).
The example, slicing preorder as [1:k] same as above The left subtree has k values, so its part of preorder is [1:k+1]. One short, and a value goes looking for itself in the wrong part of inorder (ValueError).
3000 nodes in one line 3000 deep The recursion goes 3000 deep, past Python's default limit of 1000 (LeetCode raises it). Slicing also copies ~n values per level: 63 ms here against 2 ms.

Approach 1: Recursion with Slices

Take the root from preorder[0] and find its index k in inorder. The left subtree has exactly k values: the next k in preorder (preorder[1:k+1]) and the first k in inorder. The rest is the right subtree. Build both the same way.

  • An empty list means an empty subtree: return None.
Time O(n²) worst (searching and copying at every level) Space O(n²) worst for the copies

The clearest way to see the idea. On a balanced tree it's fine (2 ms for 3000 random nodes), but on a 3000-node line it took 63 ms.

Approach 2: Index Map and Bounds Optimal

Remove both costs. A map value → inorder index replaces the search. Instead of slicing, pass the bounds lo..hi of the inorder part. And the roots don't need slicing either: preorder gives them in exactly the order the recursion asks for them, so keep one counter into it.

  • build(lo, hi): take the next preorder value as the root, find k, then build(lo, k − 1) and build(k + 1, hi).
  • Build the left subtree first, or the counter hands out the wrong roots.
Time O(n) Space O(n) for the map, O(h) stack

The answer interviewers expect: 1.1 ms for 3000 random nodes and 2.1 ms for the long line. The same idea works for Construct from Inorder and Postorder (106), where postorder gives the roots from the end.

Approach 3: One Pass with a Stack

Walk preorder once with a stack of nodes that may still get a right child, and a pointer j into inorder. Each new value is the left child of the top, unless the top's value is inorder[j]: then the top's left side is finished, so pop while the top matches inorder (moving j), and the new value is the right child of the last node popped.

  • Inorder reaching a node's value means everything to its left is already built.
  • No recursion and no map.
Time O(n): each node is pushed and popped once Space O(h) for the stack

The fastest here (0.6–0.9 ms) and safe on deep trees, but harder to explain than Approach 2.

In practice No shortcut

No library builds a tree from its traversals, in Python, C++ or Java. Use a hash map for the inorder positions: a dict, unordered_map or HashMap.

Write Approach 2. The two traps: build left before right, and give the left part exactly k values. It only works because the values are all different: with repeats, the root's position in inorder is ambiguous.
