973. K Closest Points to Origin Medium Heap Quickselect Sorting
Key idea: Compare x² + y², never the square root. To get the k smallest without sorting everything, either keep a size-k max-heap (O(n log k)), or quickselect: partition around a random pivot and keep only the side that holds place k − 1 (O(n) on average).

Problem View on LeetCode (opens in a new tab) ↗

Return the k points closest to (0, 0), in any order. The answer is promised to be unique.

  • 1 <= k <= points.length <= 10⁴, -10⁴ <= x, y <= 10⁴

Example: points = [[1,3],[-2,2]], k = 1 → [[-2,2]]. points = [[3,3],[5,-1],[-2,4]], k = 2 → [[3,3],[-2,4]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
10⁴ points already sorted by distance, k = 1 the first point Quickselect that always picks the last element as pivot removes one point per round: 3.7 s in Python. A random pivot: 1 ms.
[[10000,10000],[-10000,-10000],[0,1]], k = 1 [[0,1]] The biggest x² + y² is 2·10⁸, which still fits in a 32-bit int.
[[0,0]], k = 1 [[0,0]] k can equal the number of points.

Approach 1: Sort by Distance

Sort the points by x² + y² and return the first k.

  • Squared distances keep the same order as real ones, with no floating point.
Time O(n log n) Space O(n)

10⁴ random points, k = 5000, average of 30 runs: Python 2.1 ms, Java 4.5 ms, C++ 0.72 ms. In Python that beats Approach 3 (3.0 ms), because the sort runs in C.

Approach 2: Size-k Max-Heap

Push each point into a max-heap by distance. When it holds more than k, pop the top: the farthest of them. The k left are the closest.

  • Works on a stream of points too.
Time O(n log k) Space O(k)

k = 10: Python 3.0 ms, Java 0.22 ms, C++ 0.11 ms. k = 5000: Python 4.8 ms, Java 0.77 ms, C++ 0.68 ms. Good for small k.

Approach 3: Quickselect Optimal

Pick a random pivot and partition: closer points to the left, the pivot at its sorted place store. If store is k − 1, the first k are the answer. Otherwise repeat on the one side that holds place k − 1.

  • Each round keeps about half, so about n + n/2 + n/4 + … ≈ 2n work on average.
  • O(n²) is possible with very bad luck, but no input can force it.
Time O(n) average Space O(n) for the distances

k = 5000: Java 0.11 ms, C++ 0.19 ms, the fastest in both; Python 3.0 ms. k = 10: Java 0.044 ms, C++ 0.063 ms, Python 1.8 ms.

In practice Built-ins

Python's heapq.nsmallest(k, points, key=…) is Approach 2 in C. C++'s std::nth_element is quickselect. Java has neither; use a PriorityQueue or sort.

Time O(n log k) / O(n) average Space O(k) / O(n)

Should pass on LeetCode. Python nsmallest: 0.87 ms with k = 10, the fastest Python here, but 4.7 ms with k = 5000. C++ nth_element: 0.28 to 0.32 ms, slower than Approach 3 here, probably because it moves whole vector<int> points instead of ints.
