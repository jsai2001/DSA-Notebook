167. Two Sum II - Input Array Is Sorted Medium Array Two Pointers Binary Search
Key idea: Start with the smallest and the largest number. If their sum is too small, the smallest can't be in the answer (it can't get bigger), so move left inward; if too big, move right inward. Each step rules out one number: O(n) time, O(1) memory. Return 1-indexed positions.

Problem View on LeetCode (opens in a new tab) ↗

numbers is sorted from small to large. Find the two numbers that add up to target and return their positions [index1, index2], counting from 1, with index1 < index2. There is exactly one answer, the same element can't be used twice, and the solution must use only O(1) extra memory.

  • 2 <= numbers.length <= 3 × 10⁴
  • -1000 <= numbers[i] <= 1000, -1000 <= target <= 1000

Example: [2,7,11,15], target 9 → [1,2]. [2,3,4], target 6 → [1,3].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2,7,11,15], target 9 [1,2] Positions count from 1. Returning array indexes said [0,1].
[0,0], target 0 [1,2] The two numbers are equal. A binary search over the whole array found the first 0 itself: said [1,1]. Search only after i.
[-1,0], target −1 [1,2] Negative numbers: the two-pointer reasoning doesn't change.
[1,2,3,4,4,9,56,90], target 8 [4,5] Duplicates next to each other.
3 × 10⁴ numbers, the pair in the middle the middle two Checking every pair took 13.2 s in Python; the two pointers took 2.4 ms.

Approach 1: Every Pair

Check every pair i < j and return the one that adds up to target.

  • Ignores that the array is sorted.
  • n(n − 1) / 2 pairs.
Time O(n²) Space O(1)

At 3 × 10⁴ with the pair in the middle: Python 13.2 s, C++ 0.14 s, Java 67 ms. Too slow in Python.

Approach 2: Binary Search for the Other Number

For each numbers[i], the other number must be target − numbers[i]. The array is sorted, so binary search for it, but only in the part after i.

  • Uses the sorted order, and O(1) memory.
  • Searching after i also keeps index1 < index2.
Time O(n log n) Space O(1)

At 3 × 10⁴: Python 19 ms, Java 3.1 ms, C++ 0.4 ms. Fast, but not the best possible.

Approach 3: Two Pointers From Both Ends Optimal

lo at the start, hi at the end. Sum too small: lo += 1. Too big: hi -= 1. Equal: return [lo + 1, hi + 1].

  • Why it's safe: if the sum is too small, numbers[lo] plus anything still in range is at most this sum, so lo can never be part of the answer.
  • The pointers never cross the answer, so they meet it.
Time O(n) Space O(1)

At 3 × 10⁴: Python 2.4 ms, Java 1.2 ms, C++ 0.08 ms. The expected answer. A hash map (as in Two Sum, problem 1) is also O(n), but breaks the O(1)-memory rule.

In practice No shortcut

No standard function finds a pair. Python's bisect, C++'s lower_bound and Java's Arrays.binarySearch can replace the hand-written search in Approach 2 (search from i + 1).

Approach 3 is what you'd write: shorter than either, and faster.
