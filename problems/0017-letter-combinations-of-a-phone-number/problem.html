17. Letter Combinations of a Phone Number Medium String Backtracking
Key idea: Every answer picks one letter per digit, so this is every combination of the digits' letters. Backtrack: for digits[i], try each of its letters, recurse on i + 1, then undo. When i == len(digits), the path is one answer. Empty input returns [], not [""]. O(4ⁿ · n), which is the size of the output.

Problem View on LeetCode (opens in a new tab) ↗

Given a string of digits from 2 to 9, return every letter combination the number could spell on a phone keypad, in any order: 2 = abc, 3 = def, 4 = ghi, 5 = jkl, 6 = mno, 7 = pqrs, 8 = tuv, 9 = wxyz.

  • 0 <= digits.length <= 4
  • digits[i] is one of 2 to 9.

Examples: "23" → ["ad","ae","af","bd","be","bf","cd","ce","cf"]; "" → []; "2" → ["a","b","c"].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"" [] The trap: starting from [""], or backtracking with no check, returns [""]. So does itertools.product() of nothing.
"2" ["a","b","c"] One digit: just its letters.
"7" ["p","q","r","s"] 7 and 9 have four letters, not three. Don't assume three letters per key.
"22" 9 combinations, "aa" … "cc" The same digit twice is fine: "aa" is a valid answer.
"79" 16 combinations 4 × 4: the count is the product of the letter counts.
"7999" 256 combinations The largest possible output (4⁴), still tiny.

Approach 1: Build Level by Level

Keep the list of combinations for the digits seen so far. Each new digit replaces every combination with one copy per letter of that digit.

  • Start with [""] (one way to spell nothing), but return [] early for empty input.
  • combos = [c + ch for c in combos for ch in letters[d]]: after the last digit, combos is the answer.
Time O(4ⁿ · n) Space O(4ⁿ · n)

No recursion, and easy to follow. It keeps a full copy of the previous level while building the next, so it uses about twice the output's memory; at n ≤ 4 (256 strings) that's nothing.

Approach 2: Backtracking Optimal

Build one combination at a time. For digit i, add one of its letters to the path, go on to digit i + 1, and when you come back, remove that letter so the next one can take its place.

  • Base case: i == len(digits) means every digit has a letter, so save a copy of the path.
  • Choose → recurse → undo is the backtracking pattern used for Permutations (46), Subsets (78), Combination Sum (39) and N-Queens (51).
Time O(4ⁿ · n) Space O(n) besides the output

Same time as Approach 1 (both have to write out every answer), but only one path of length ≤ 4 is kept besides the result. This is the version interviewers expect, mostly because the same pattern carries over to harder problems.

In practice Built-ins

This is a Cartesian product of the digits' letters, and Python has it: itertools.product. C++ and Java have no standard equivalent, so there you'd write Approach 1 or 2.

Time O(4ⁿ · n) Space O(4ⁿ · n)

Passes, but keep the empty check: product() of nothing yields one empty tuple, which becomes [""] instead of [].
