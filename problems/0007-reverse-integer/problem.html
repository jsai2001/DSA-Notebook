7. Reverse Integer Medium Math
Key idea: Pop the last digit with x % 10 and push it onto the result with rev = rev * 10 + digit. The catch is overflow: check before each push that rev isn't past INT_MAX / 10, so the too-big number is never built. O(log |x|) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given a signed 32-bit integer x, return x with its digits reversed. If the reversed number falls outside the signed 32-bit range [-2³¹, 2³¹ - 1], return 0.

  • -2³¹ <= x <= 2³¹ - 1
  • Assume the environment can't store 64-bit integers (signed or unsigned).

Examples: 123 → 321; -123 → -321; 120 → 21 (the leading zero disappears); 1534236469 → 0 (9646324351 doesn't fit).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
x = 0 0 Zero stays zero.
x = 7 7 One digit.
x = 1200 21 Trailing zeros become leading zeros and disappear.
x = -123 -321 Negative: keep the sign. In Python, -123 % 10 is 7, not -3.
x = 1534236469 0 9646324351 doesn't fit in 32 bits.
x = 1000000003 0 A valid input whose reverse (3000000001) overflows.
x = 2147483647 (INT_MAX) 0 Reverses to 7463847412: overflow.
x = -2147483648 (INT_MIN) 0 abs(x) itself doesn't fit in an int (2147483648), and the reverse overflows too.
x = 1463847412 2147483641 Reverses to 2147483641, just under INT_MAX: it fits.
x = -2147483412 -2143847412 Fits just inside the negative limit.

Approach 1: Build by Place Value

Count the digits first, so you know where each one lands. The last digit of x becomes the first digit of the answer, at place 10^(digits - 1); the next one goes one place lower, and so on. Build the whole number, put the sign back, then check the range once.

  • Working on abs(x) avoids negative remainders, and the sign is restored at the end.
  • The loop runs while decimal is non-zero, so the last digit (the ones place) is added after it. That also covers x = 0, where the loop never runs.
Time O(log |x|) Space O(1)

Correct, and it passes: at most 10 digits. It only works because the full reversed number is built before the range check. Python ints have no size limit, so that's fine there, but C++ and Java need long long / long for it (as written below), which the problem asks you to avoid. In Java, Math.abs(Integer.MIN_VALUE) is still negative as an int, another reason to widen first. The unused from math import ceil is dropped here.

Approach 2: Pop and Push with an Overflow Check Optimal

No digit counting: pop the last digit of x and push it onto rev (rev * 10 + digit). Before each push, ask whether the result would pass the limit, using only numbers that already fit.

  • rev * 10 + digit overflows exactly when rev > INT_MAX / 10, or rev == INT_MAX / 10 and digit > 7 (the last digit of 2147483647). The negative side uses INT_MIN / 10 and -8.
  • In C++ and Java, % keeps the sign (-123 % 10 == -3), so negatives work with no special case. Python's % doesn't (-123 % 10 == 7), so the Python version works on abs(x) with a limit of 2³¹ - 1 or 2³¹.
Time O(log |x|) Space O(1)

Stays within 32-bit ints, as the problem requires. A detail: the digit > 7 half never actually triggers. When rev reaches 214748364, the only digit left is the first digit of x, which is 1 or 2. It's kept because it makes the check obviously correct.

In practice Built-ins

Turn the number into a string, reverse it, and parse it back: str(abs(x))[::-1] in Python, std::reverse in C++, StringBuilder.reverse() in Java. Parsing ignores the leading zeros, so "021" becomes 21.

Time O(log |x|) Space O(log |x|)

Passes on LeetCode, but like Approach 1 it builds the full number first, so C++ and Java parse into 64 bits (stoll, Long.parseLong), against the problem's rule. Fine for everyday code; in an interview, expect to be asked for Approach 2.
