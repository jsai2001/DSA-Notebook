15. 3Sum Medium Array Two Pointers Sorting
Key idea: Sort, then fix the first number nums[i] and find the other two with two pointers: lo just after i, hi at the end. Sum too small → lo++; too big → hi--. Skip repeated values for i and, after a hit, for lo, so no triplet appears twice. O(n²) time, no extra set.

Problem View on LeetCode (opens in a new tab) ↗

Given an integer array nums, return every triplet [nums[i], nums[j], nums[k]] with i, j, k all different and nums[i] + nums[j] + nums[k] == 0. The answer must not contain the same triplet twice. Order doesn't matter.

  • 3 <= nums.length <= 3000
  • -10⁵ <= nums[i] <= 10⁵

Examples: [-1, 0, 1, 2, -1, -4] → [[-1, -1, 2], [-1, 0, 1]]; [0, 1, 1] → []; [0, 0, 0] → [[0, 0, 0]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[0, 1, 1] [] No triplet: return an empty list.
[1, 2, 3] [] All positive. After sorting, a positive first number means you can stop.
[-1, -1, -1] [] All negative: nothing sums to 0.
[0, 0, 0, 0] [[0, 0, 0]] Four ways to pick three zeros, but only one triplet. Skipping repeats is required, not optional.
[-4, 2, 2] [[-4, 2, 2]] The same value can be used twice if it appears twice: indexes must differ, values needn't.
[-1, 0, 1, 0] [[-1, 0, 1]] A repeated middle number: skip repeats of lo after a hit, not just of i.
[-2, -2, 0, 0, 2, 2] [[-2, 0, 2]] Repeats in every position at once.
[-2, 0, 1, 1, 2] [[-2, 0, 2], [-2, 1, 1]] Two triplets share the first number: keep going after the first hit instead of moving on to the next i.
[3, 0, -2, -1, 1, 2] [[-2, -1, 3], [-2, 0, 2], [-1, 0, 1]] Unsorted input with three different triplets.
[-100000, 50000, 50000] [[-100000, 50000, 50000]] The extremes. Any sum of three values is at most 3 × 10⁵ in size, so an int is enough.
3000 zeros [[0, 0, 0]] Every one of the 4.5 × 10⁹ triples sums to 0. Brute force took over 2 minutes in C++ and Java here; sort + two pointers finished instantly.

Approach 1: Brute Force (Every Triple)

Try every i < j < k. When the three add up to 0, sort them and put them in a set, so the same three numbers found in a different order count once.

  • The set handles duplicates; nothing needs to be sorted first.
  • n(n - 1)(n - 2) / 6 triples: about 4.5 × 10⁹ at n = 3000.
Time O(n³) Space O(number of triplets)

Far too slow. In Python, n = 300 alone took 0.2 s, and n = 3000 is 1000× more work. C++ took about 2 s and Java 4–11 s on random inputs of 3000 numbers, and both took over 2 minutes on 3000 zeros, because every triple is a hit that gets sorted and inserted.

Approach 2: Fix One, Then Two Sum with a Hash Set

Fix the first number; now you need two numbers to its right that add up to -nums[i]. That's Two Sum, solved with a set of values seen so far.

  • For each j, the third number must be need = -nums[i] - nums[j]. If need was already seen between i and j, it's a triplet.
  • Sorting first makes every triplet come out as (nums[i], need, nums[j]) in increasing order, so a set of tuples removes repeats. Skipping repeated nums[i] saves work.
Time O(n²) Space O(n)

Passes. At n = 3000 it took 0.5–1.9 s in Python here, and about 0.2–0.5 s in C++ and Java: hashing costs more than the pointer moves in Approach 3, and the result set still dedupes.

Approach 3: Sort + Two Pointers Optimal

After sorting, for a fixed nums[i] the other two can be found the way Two Sum II does it on a sorted array: start at both ends of the rest and close in.

  • Sum < 0: hi is already the largest number left, so only a bigger lo can help. Sum > 0: move hi left.
  • No set needed for repeats: skip nums[i] equal to the previous one, and after a hit skip lo past its repeats. (hi then fixes itself on the next comparisons.)
  • Stop as soon as nums[i] > 0: three numbers that are all at least that big can't sum to 0.
Time O(n²) Space O(1) extra (besides the sort and the output)

The fastest here: under 0.1 s in C++ and Java and at most 0.8 s in Python at n = 3000, even with 1.1 million triplets in the output. This is the expected interview answer.

In practice No shortcut

Python's itertools.combinations(nums, 3) lists every triple, but filtering it is just Approach 1 with the same O(n³) cost. No standard library finds zero-sum triplets faster.

Write Approach 3. The same sort + two pointers pattern solves 3Sum Closest (16) and 4Sum (18), the latter with one more fixed number.
