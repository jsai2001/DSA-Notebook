739. Daily Temperatures Medium Stack Monotonic Stack Array
Key idea: This is "next greater element". Keep a stack of days still waiting for a warmer day; their temperatures only go down toward the top. Each new day pops every waiting day that's colder (their answer is the gap in days), then waits itself. Every day is pushed and popped once: O(n).

Problem View on LeetCode (opens in a new tab) ↗

For each day, return how many days you have to wait for a warmer temperature. If no later day is warmer, the answer for that day is 0.

  • 1 <= temperatures.length <= 10⁵
  • 30 <= temperatures[i] <= 100

Example: [73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]. [30,40,50,60] → [1,1,1,0].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[40,40] [0,0] The same temperature isn't warmer. Popping with <= instead of < said [1,0]; wrong on 1102 of 3006 tests.
[90,80,70] [0,0,0] Nothing is ever warmer: every day stays on the stack, and stays 0.
[50] [0] One day.
10⁴ falling temperatures all 0 Looking ahead day by day checks every pair: 1.3 s in Python for just 10⁴ days.

Approach 1: Look Ahead From Each Day

For each day i, walk j = i + 1, i + 2, … until temperatures[j] is higher. The answer is j − i, or 0 if you run off the end.

  • Quick when warmer days come soon; quadratic when temperatures keep falling.
Time O(n²) Space O(1) besides the answer

10⁴ falling temperatures: Python 1.3 s, Java 17 ms, C++ 17 ms. At 10⁵ that's 100 times the work: too slow.

Approach 2: Right to Left, Jumping

Fill ans from the right. For day i, start at j = i + 1. If day j isn't warmer, no day before day j's own warmer day can be either, so jump straight to j + ans[j]. If ans[j] is 0, nothing to the right is warmer: stop.

  • No extra structure: ans itself holds the jumps.
  • Each day is jumped over at most once more, so the total is O(n).
Time O(n) Space O(1) besides the answer

10⁵ random days: Python 13.3 ms, Java 0.78 ms, C++ 0.68 ms, slightly ahead of the stack in C++ and Java.

Approach 3: Monotonic Stack Optimal

Go left to right with a stack of day indexes still waiting. While today is warmer than the day on top, pop it and set its answer to i − j. Then push today. Days left at the end keep 0.

  • Store indexes, not temperatures: you need the day to compute the wait.
  • The same pattern solves "next greater element" problems in general.
Time O(n) Space O(n) for the stack

10⁵ random days: Python 13.2 ms, Java 0.90 ms, C++ 0.80 ms. About the same as Approach 2, and the one most people know.

In practice No shortcut

No library finds the next greater element. Approach 3 is what you'd write.

Comparison

Approach Technique Time Space Notes
