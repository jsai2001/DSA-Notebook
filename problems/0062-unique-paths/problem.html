62. Unique Paths Medium Math Dynamic Programming Combinatorics
Key idea: You can only reach a cell from above or from the left, so paths(r, c) = paths(r − 1, c) + paths(r, c − 1), with 1 all along the top row and left column. Fill it row by row with one array: O(m·n) time, O(n) space. Or count directly: every path is m − 1 downs and n − 1 rights in some order, so the answer is C(m + n − 2, m − 1).

Problem View on LeetCode (opens in a new tab) ↗

A robot starts at the top-left corner of an m × n grid and wants to reach the bottom-right corner. It can only move down or right, one cell at a time. Return how many different paths it can take.

  • 1 <= m, n <= 100.
  • The answer is at most 2 · 10⁹, so it fits in a 32-bit int.

Examples: m = 3, n = 7 → 28; m = 3, n = 2 → 3 (right-down-down, down-right-down, down-down-right).

Approach 1: Recursion with Memo

The last move into (r, c) came from above or from the left, so paths(r, c) = paths(r − 1, c) + paths(r, c − 1). The top row and left column are 1: there's only the straight line. Ask for the bottom-right corner and let the recursion fill in the rest.

  • Without the memo, the same cells are recomputed over and over: the number of calls grows like the answer itself.
  • With it, each cell is worked out once.
Time O(m·n) Space O(m·n) for the memo, plus O(m + n) recursion depth

The most natural way to find the recurrence. The next approach is the same recurrence written as a loop.

Approach 2: DP, One Row at a Time

Fill the grid row by row instead. Each cell only needs the row above and the cell to its left, so one array is enough: before row[c] is updated it still holds the cell above, and row[c − 1] already holds the cell to the left.

  • Start with all 1s (the top row), then for every row below: row[c] += row[c − 1] for c from 1.
  • Start the rows at 1, not 0: the top row is already right.
Time O(m·n) Space O(n)

The usual interview answer, and the version that adapts to Unique Paths II (63), where obstacles set a cell to 0. Every count is at most the final answer, so a 32-bit int is enough.

Approach 3: Count the Orders of the Moves Optimal

Every path makes exactly m − 1 moves down and n − 1 moves right; paths differ only in the order. So count the orders: choose which of the m + n − 2 moves are the downs, C(m + n − 2, m − 1).

  • Build it as result = result × (total − k + i) / i for i = 1 … k; after each step it is C(total − k + i, i), a whole number, so the division is exact.
  • Multiply first, then divide. Use k = min(m, n) − 1 for fewer steps.
  • The product goes past 2³¹ (up to about 2.8 · 10¹⁰ within the limits), so keep result in 64 bits.
Time O(min(m, n)) Space O(1)

Fastest, but it only works because there are no obstacles. Mention it after the DP; most interviewers want to see the recurrence first.

In practice Built-ins

Python has the binomial built in: math.comb (3.8+), with exact big integers, so overflow can't happen. C++ and Java have nothing built in for this; write Approach 3 with a 64-bit result.

Time O(min(m, n)) multiplications Space O(1)

Passes every allowed input here (1773 of the 10,000 (m, n) pairs keep the answer at most 2 · 10⁹).
