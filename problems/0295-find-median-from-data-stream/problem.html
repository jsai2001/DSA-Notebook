295. Find Median from Data Stream Hard Heap (Priority Queue) Design Data Stream
Key idea: Split the values into two halves: low, a max-heap of the smaller half, and high, a min-heap of the bigger half. Keep every value in low ≤ every value in high, and low's size equal to high's or one more. The median is low's top, or the mean of both tops. O(log n) per add, O(1) per find.

Problem View on LeetCode (opens in a new tab) ↗

Build MedianFinder with addNum(num) and findMedian(), which returns the median of all values so far: the middle value, or the mean of the two middle values when the count is even.

  • -10⁵ <= num <= 10⁵; at most 5 × 10⁴ calls in total
  • findMedian is only called after at least one addNum

Example: add 1, add 2, find → 1.5; add 3, find → 2.0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
add 95423, −53162, −46989, find -46989.0 Putting each value into whichever heap is smaller, without passing it through the other, breaks "low ≤ high": it said 95423.0. Wrong on 1482 of 2004 tests.
add 12633, −62910, find -25138.5 Integer division for the mean rounds down: it said -25139.0. Wrong on 1213 tests.
add −100000, 100000, find 0.0 The two middles cancel out.

Approach 1: Sort on Every Find

addNum appends. findMedian sorts a copy of everything and reads the middle.

  • Fine if you add a lot and ask rarely.
  • Terrible if you ask after every add.
Time O(1) add, O(n log n) find Space O(n)

25,000 adds, each followed by a find: C++ 5.3 s, Java 28 s (Python wasn't even tried). But 5 × 10⁴ adds and one find: C++ 1.1 ms, Python 10 ms, the fastest here.

Approach 2: Sorted List, Binary Insert

Keep the list sorted: binary search for the spot and insert there. findMedian just reads the middle.

  • The search is O(log n), but inserting shifts everything after it.
Time O(n) add, O(1) find Space O(n)

5 × 10⁴ adds and one find: Python 321 ms, Java 62 ms, C++ 43 ms. Find after every add (25,000 each): Python 93 ms, C++ 13 ms.

Approach 3: Two Heaps Optimal

To add: push into low, then move low's biggest into high. That keeps every low value ≤ every high value. If high now has more, move its smallest back to low. To find: low's top if low is bigger, else the mean of both tops.

  • Python's heapq is only a min-heap, so low stores negated values.
  • Use floating-point division for the mean.
Time O(log n) add, O(1) find Space O(n)

Find after every add (25,000 each): Python 26 ms, Java 13 ms, C++ 2.4 ms, the fastest in every language for that pattern.

In practice No shortcut

Python's statistics.median sorts the whole list each call, like Approach 1. Outside LeetCode, the sortedcontainers package's SortedList makes Approach 2 O(log n) per add.

On LeetCode, Approach 3 is what you'd write.

Comparison
