102. Binary Tree Level Order Traversal Medium Tree BFS
Key idea: BFS with a queue, one level at a time. At the start of each round the queue holds exactly one level, so read its size first and pop that many nodes, adding their children to the back. Those children are the next level. O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given the root of a binary tree, return its values level by level: a list for the root, then a list for its children, and so on, each list from left to right.

  • 0 to 2000 nodes (the tree can be empty).
  • -1000 <= Node.val <= 1000.

Examples: [3,9,20,null,null,15,7] → [[3],[9,20],[15,7]]; [1] → [[1]]; [] → [].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[] [] No levels at all. Putting a null root in the queue without checking gives [[]].
[3,9,20,null,null,15,7] [[3],[9,20],[15,7]] Without reading the queue's size per level, BFS gives one flat list, [3,9,20,15,7].
[1,2,3,4,null,null,5] [[1],[2,3],[4,5]] 4 and 5 have different parents but the same depth: one level holds nodes from different subtrees.
[1,2,null,3,null,4] [[1],[2],[3],[4]] A tree that's one line: every level has one node.
DFS that visits right before left left to right Each level comes out reversed: [[3],[20,9],[7,15]].
2000 nodes in one line 2000 levels 2000 deep: recursive DFS passes Python's default limit of 1000. BFS has no depth limit.

Approach 1: DFS with the Depth

Walk the tree in pre-order (node, left, right), passing the depth. Put each value into result[depth]. Because left is always visited before right, every level fills up from left to right.

  • When depth == len(result), this is the first node at that depth: add a new empty list.
Time O(n) Space O(h) call stack

Short, and correct even though it never visits a level all at once. On a 2000-deep line it hit Python's recursion limit (LeetCode raises it, so it passes there).

Approach 2: BFS with a Queue Optimal

A queue serves nodes in the order they arrive, so it visits the tree level by level. To know where one level ends, count: at the start of each round, len(queue) is exactly the number of nodes on this level.

  • Pop that many nodes, saving their values, and add their children to the back.
  • After the round, only the next level is left in the queue.
Time O(n) Space O(w), the widest level

The standard answer: 0.18 ms for 2000 nodes in Python, and no recursion. The same loop solves Right Side View (199), Zigzag (103) and Average of Levels (637).

Approach 3: Two Lists, This Level and the Next

Skip the counting: keep the current level as a plain list. Its values are one answer list; its children, in order, make the next level. Repeat until a level is empty.

  • No queue needed, and no level size to remember.
Time O(n) Space O(w)

The same speed as Approach 2 (0.15 ms) and maybe easier to read: each loop is exactly one level.

In practice No shortcut

No library walks a tree by levels, but each has a good queue: collections.deque in Python (list.pop(0) is O(n)), std::queue in C++, ArrayDeque in Java.

Write Approach 2. Return [] for an empty tree, and read the queue's size before the inner loop, not inside it (it changes as children are added).
