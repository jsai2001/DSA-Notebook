79. Word Search Medium Array String Backtracking Matrix
Key idea: From every cell, try to spell the word with a DFS: match word[k], mark the cell so the path can't use it twice, try the 4 neighbours for word[k + 1], then unmark it on the way back. Prune first: if the board doesn't have enough of some letter, the answer is false without any search. O(R · C · 3ᴸ) in the worst case.

Problem View on LeetCode (opens in a new tab) ↗

Given an R × C grid of letters board and a string word, return true if the word can be spelled by a path of cells, each next to the previous one (up, down, left or right). A cell can be used at most once in the path.

  • 1 <= R, C <= 6, 1 <= word.length <= 15.
  • Board and word use uppercase and lowercase English letters ('A' and 'a' differ).
  • Follow-up: can you prune the search so it's fast on bigger boards?

Examples: with board = [["A","B","C","E"],["S","F","C","S"],["A","D","E","E"]], "ABCCED" → true, "SEE" → true, "ABCB" → false (the B would be used twice).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[["a"]], "a" true The first cell is already the whole word, so success has to be noticed without stepping to any neighbour (there are none).
[["a"]], "aa" false Without marking, the path steps back onto the same a.
The example board, "ABCB" false A-B-C is there, but the only B next to that C is the one already used.
[["a","b"]], "ba" true The word can start anywhere, not just at (0, 0).
[["a","b"],["c","d"]], "ad" false Diagonals don't count: only up, down, left and right.
[["C","A","A"],["A","A","A"],["B","C","D"]], "AAB" true Forget to unmark and a failed try leaves cells blocked: the later path through them is missed (it says false).
[["a"]], "A" false Upper and lower case are different letters.
6 × 6 of "A", "AAAAAAAAAAAAAAB" false There's no B, but plain DFS still walks every 14-letter path of A's first: 1.5 s in Python. Counting letters first answers at once.

Approach 1: DFS with a Seen Grid

dfs(r, c, k) asks: can word[k:] be spelled starting at cell (r, c)? It fails right away if the cell is off the board, already on the path, or the wrong letter. Otherwise it marks the cell in seen and asks the same question of the 4 neighbours for k + 1.

  • Success is k == len(word): every letter matched. Check it first.
  • Unmark (seen[r][c] = False) before returning, success or not: another path may need the cell.
  • Try every cell as the start.
Time O(R · C · 3ᴸ), L = len(word) Space O(R · C) for seen, O(L) stack

After the first letter each step has at most 3 new directions (the 4th is where it came from), hence 3ᴸ. On the all-A board above it took 1.5 s in Python (42 ms in C++).

Approach 2: Mark the Board in Place

Skip the extra grid: overwrite the cell with "#" while it's on the path. "#" never equals a letter, so the "wrong letter" check also catches "already used". Put the letter back on the way out.

  • Save the letter, write "#", search the neighbours, restore the letter.
  • The board is back to normal when exist returns, true or false.
Time O(R · C · 3ᴸ) Space O(L) stack

The usual interview answer: one array fewer, one check fewer. Just as slow as Approach 1 on the bad boards (1.5 s in Python).

Approach 3: Prune First, Then Search Optimal

The follow-up's answer: cheap checks before the expensive search. Count the letters on the board. If the word needs more of some letter than the board has, no path can exist: return false.

  • Then, if the word's first letter is more common on the board than its last, reverse the word. A path spells the word exactly when, walked backwards, it spells the reverse, so the answer is the same, but there are fewer cells to start from.
  • Then the same in-place DFS as Approach 2.
Time O(R · C + L) for the checks, O(R · C · 3ᴸ) worst case Space O(L) stack

Same worst case on paper, but the slow boards above become instant: all A's with no B is caught by the count, and a word ending in a walled-off B starts from the B and fails in one step (both under 0.1 ms in Python, versus 1.5 s and 0.95 s).

In practice No shortcut

No library searches a grid for a path. Python, C++ and Java all need the DFS written out.

Write Approach 2, and mention the letter count and the reverse trick for the follow-up. For many words on one board (Word Search II, 212), put the words in a trie and search the board once.
