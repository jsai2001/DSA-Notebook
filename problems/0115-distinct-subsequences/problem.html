115. Distinct Subsequences Hard String Dynamic Programming
Key idea: For each letter of s, you either skip it or, if it matches the next letter of t, use it. So dp[i][j] = dp[i−1][j] + (dp[i−1][j−1] if s[i−1] == t[j−1]), with dp[i][0] = 1. Keep one row and go right to left: O(m · n) time, O(n) space. In C++ and Java, the counts on the way can pass the int range even when the answer doesn't.

Problem View on LeetCode (opens in a new tab) ↗

Given strings s and t, return how many different ways there are to pick letters of s, keeping their order, that spell t. Two ways are different when they use different positions of s.

  • 1 <= s.length, t.length <= 1000; English letters.
  • The answer fits in a 32-bit signed int (but the numbers on the way may not).

Examples: s = "rabbbit", t = "rabbit" → 3 (any 2 of the 3 b's); s = "babgbag", t = "bag" → 5.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"ab", "abc" 0 t is longer than s: no way at all.
"abc", "cba" 0 The same letters, but the order must be kept.
"aa", "a" 2 Either a works. Forgetting dp[i][0] = 1 (only setting dp[0][0]) says 1; on "babgbag" it says 3, not 5.
"aaa", "aa" with one row 3 Going left to right lets one letter of s be used twice in the same pass: it says 6. Go right to left.
"aaa", "aaa" 1 s and t equal: exactly one way, using every letter.
40 a's + "b", 39 a's + "b" 40 The answer is small, but on the way the table holds C(40, 20) ≈ 1.4 × 10¹¹. A plain C++ int overflows (undefined behaviour); long long isn't enough in general either (60 a's / 30 a's reaches 1.2 × 10¹⁷).

Approach 1: Plain Recursion

count(i, j) = ways to spell t[j:] from s[i:]. Skipping s[i] gives count(i + 1, j); if s[i] == t[j], using it adds count(i + 1, j + 1).

  • Done when j == len(t) (one way); give up when fewer letters are left in s than in t.
Time O(2ᵐ) in the worst case Space O(m) stack

The same (i, j) is reached in many ways: 1.0 s in Python for just 24 a's against 13 a's then a b (the answer is 0).

Approach 2: 2D DP Table

Answer every question once, from the front. dp[i][j] = ways to spell the first j letters of t with the first i of s. The last letter of s, s[i−1], is either not used (dp[i−1][j]) or, if it equals t[j−1], used as t's last letter (dp[i−1][j−1]).

  • dp[i][0] = 1 for every i: the empty start of t is spelled one way, by using nothing.
  • Overflow: only additions happen, so in C++ use unsigned (it wraps modulo 2³², which is defined) and in Java plain int (which also wraps). The final answer fits, so it comes out exact.
Time O(m · n) Space O(m · n)

123 ms in Python at 1000 × 1000. In Python numbers never overflow, so nothing special is needed there.

Approach 3: One Row, Right to Left Optimal

Row i only uses row i − 1, so keep one row and update it for each letter of s. For dp[j] += dp[j − 1], dp[j − 1] must still be the old value, so walk j from right to left.

  • Left to right would add a value already updated with this letter, using the same letter twice.
  • Only positions where t[j−1] equals the letter change at all.
Time O(m · n) Space O(n)

The same counts with one row: 62 ms at 1000 × 1000. Same overflow rule as Approach 2. It's the trick from 0/1 Knapsack: go backwards so each item is used at most once.

In practice Built-ins

In Python, @functools.cache on Approach 1 makes it O(m · n) with no other change, and Python's numbers can't overflow. C++ and Java have nothing like it: write the table.

Time O(m · n) Space O(m · n) for the cache

With a 1000-letter s it recurses about 1000 deep, which goes past Python's default limit (a RecursionError here). LeetCode raises the limit, so it passes there; elsewhere, use Approach 3.

Comparison

Approach Technique Time Space Notes
Plain Recursion Skip or use each letter of s O(2ᵐ) O(m) Too slow from about 25 letters
2D Table dp[i][j] from the row above O(m · n) O(m · n) Easy to check by hand
One Row Right to left, dp[j] += dp[j − 1] O(m · n) O(n) The usual answer
