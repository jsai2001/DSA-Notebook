78. Subsets Medium Array Backtracking Bit Manipulation
Key idea: Every number is either in a subset or out: n yes/no choices, so 2ⁿ subsets. Backtrack with a start index: record path (a copy) at every call, then extend it only with numbers after the last one taken, so no subset comes out twice. O(n · 2ⁿ), the size of the answer.

Problem View on LeetCode (opens in a new tab) ↗

Given an array nums of distinct integers, return all its subsets (the power set). No subset may appear twice; any order is fine.

  • 1 <= nums.length <= 10 and -10 <= nums[i] <= 10.
  • All the numbers are different.

Examples: [1,2,3] → [[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]; [0] → [[],[0]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1] [[],[1]] The empty subset counts. Recording only when something was added gives just [[1]].
[0] [[],[0]] 0 is a real number to take. A Python check like if x: treats it as "nothing".
[1,2,3] 8 subsets Adding path itself instead of a copy gives 8 empty lists: they're all the same list, which ends empty.
[1,2,3] with a start index 8 subsets Recursing on start + 1 instead of i + 1 gives 16 lists, with repeats like [3,2] and impossible ones like [2,2].
[-1,0,1] 8 subsets Negative numbers and 0 are just values; nothing about them is special.
10 numbers 1024 subsets The largest input: 2¹⁰ subsets holding 5120 numbers in total. Small, but every approach has to build all of it.
[1,2] [[1,2],[],[2],[1]] is fine too Any order is accepted. When testing your own code, compare the answers as sets, not as lists in one fixed order.

Approach 1: Take or Skip Each Number

Walk the numbers in order and make one choice per number: take it or leave it. That's a binary tree n levels deep; each of its 2ⁿ leaves is one subset.

  • Take: append nums[i], recurse on i + 1. Skip: pop it, recurse on i + 1 again.
  • When i == n every number is decided: add a copy of path.
Time O(n · 2ⁿ) Space O(n) besides the answer

The easiest one to reason about: the recursion tree is exactly the "in or out" choices. 0.32 ms in Python for n = 10.

Approach 2: Backtracking with a Start Index Optimal

Every path is already a subset, so record it as soon as the call starts. Then try each number from start on as the next one, and recurse on i + 1: only later numbers can follow, so each subset is built in one order only.

  • Record, then for each i from start: append, recurse on i + 1, pop.
  • Each call adds one subset, so there are exactly 2ⁿ calls and no dead ends.
Time O(n · 2ⁿ) Space O(n) besides the answer

The one to know: the same loop, with small changes, solves Subsets II (sort and skip a number equal to the previous one), Combinations and Combination Sum (39, 40). 0.30 ms in Python for n = 10.

Approach 3: Bitmask

Write the in/out choices as bits. Every number from 0 to 2ⁿ − 1 is one subset: bit i is 1 exactly when nums[i] is in it.

  • For each mask, test bit i with (mask >> i) & 1.
  • No recursion. It only works while 2ⁿ fits in an int, which n ≤ 10 easily does.
Time O(n · 2ⁿ) Space O(1) besides the answer

Tests all n bits of every mask, even the 0s, so it's a little slower in Python (0.60 ms for n = 10). In C++ and Java it's as fast as the others.

In practice Built-ins

Python's itertools.combinations(nums, r) gives every subset of size r; join them for r = 0 to n. C++ and Java have nothing built in, so the bitmask loop is the usual short version there.

Time O(n · 2ⁿ) Space O(n) besides the answer

The fastest here (0.09 ms for n = 10): the loop runs in C. The tuples have to become lists.

Comparison
