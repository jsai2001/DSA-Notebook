684. Redundant Connection Medium Graph Union Find Depth-First Search
Key idea: A tree plus one edge has exactly one cycle. Add the edges in order with union-find: the first edge whose two ends already share a root closes that cycle, and since every other cycle edge came before it, it's also the last cycle edge in the input. One pass, O(n) memory.

Problem View on LeetCode (opens in a new tab) ↗

A tree on nodes 1..n got one extra edge, so edges has n edges. Return an edge you can remove so that the rest is a tree again. If there are several, return the one that comes last in edges.

  • 3 <= n <= 1000, edges[i] = [a, b], a != b
  • No repeated edges; the graph is connected

Example: [[1,2],[1,3],[2,3]] → [2,3]. [[1,2],[2,3],[3,4],[1,4],[1,5]] → [1,4].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky

[[1,2],[1,3],[2,3]] [2,3] Union-find with parent[a] = b instead of joining the roots overwrote 1's link to 2 and found no cycle at all. It was wrong on 1693 of 3208 test cases.
[[1,2],[1,3],[2,3]] [2,3] Approach 2 adding the edge before searching always finds b: it said [1,2].
A 3-edge cycle first, then 997 tree edges the 3rd edge Approach 1 removes 998 edges before it hits the cycle: 257 ms in Python.
[[1,2],[2,3],…,[999,1000],[1000,1]] [1000,1] Each search in Approach 2 walks the whole path built so far: 62 ms in Python.

Approach 1: Remove Each Edge and Check

Try the edges from last to first. Leave one out, rebuild the graph, and walk from node 1 with a DFS. If all n nodes are reached, the other n − 1 edges form a tree: return the one you left out.

  • Going from the back makes the first hit the answer LeetCode wants.
  • Each try is a full rebuild and walk, O(n), and there can be n tries.
Time O(n²) Space O(n)

Worst case found here (cycle edges first, 1000 nodes): Python 257 ms, Java 60 ms, C++ 53 ms. Simple to trust, but slow.

Approach 2: DFS Before Adding Each Edge

Build the graph one edge at a time. Before adding a–b, search from a in the graph so far. If b is already reachable, this edge closes the cycle: return it. Otherwise add it and go on.

  • The edge that closes the cycle is the last of the cycle's edges to appear, so it's the answer. Edges after it aren't on the cycle.
  • The graph so far is always a forest, so each search is O(n).
Time O(n²) Space O(n)

Worst case found here (a path in order, then the closing edge): Python 62 ms, Java 27 ms, C++ 2.9 ms.

Approach 3: Union-Find Optimal

Same idea as Approach 2, but "are a and b already connected?" is answered by union-find instead of a search. find walks up to a group's root. Same root: return the edge. Different roots: join them with parent[ra] = rb.

  • Join the roots, not a and b: moving a can cut it off from its old group.
  • Path halving (parent[x] = parent[parent[x]]) keeps the trees short as you walk.
Time O(n log n) at worst, close to O(n) Space O(n)

Slowest of 3208 test cases (up to 1000 nodes): Python 0.3 ms, Java 0.7 ms, C++ 0.03 ms. Adding union by rank would make it O(n α(n)), but at n = 1000 it doesn't matter.

In practice No shortcut

Python, C++ and Java have no built-in union-find. Approach 3 is about ten lines and is what you'd write.
