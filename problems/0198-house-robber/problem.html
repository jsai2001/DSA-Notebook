198. House Robber Medium Array Dynamic Programming
Key idea: At each house there are two choices: skip it (keep the best so far) or rob it (add it to the best from two houses back). So best = max(cur, prev + x), and only the last two answers are needed: two variables, one pass.

Problem View on LeetCode (opens in a new tab) ↗

nums[i] is the money in house i along a street. You can't rob two houses next to each other. Return the most money you can rob.

  • 1 <= nums.length <= 100
  • 0 <= nums[i] <= 400

Example: [1,2,3,1] → 4 (houses 0 and 2). [2,7,9,3,1] → 12 (2 + 9 + 1).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2,1,1,2] 4 The best pick skips two houses in a row. "Even houses or odd houses, whichever sums more" said 3; it was wrong on 2360 of 4508 tests.
[1,3,3] 4 Greedy "rob the richest house left" takes a 3 and blocks the rest: it said 3.
[243,193] 243 dp[i] = dp[i − 2] + nums[i − 1] without the max always robs the last house: it said 193.
[5] 5 One house. A DP that reads nums[1] to start would go out of range.

Approach 1: Recursion with Memo

best(i) = the most from house i to the end. Either skip house i (best(i + 1)) or rob it and skip its neighbour (nums[i] + best(i + 2)). Remember each answer.

  • Without the memo the calls double like Fibonacci: 4.4 million calls at 30 houses here, and roughly 10²¹ at 100.
  • With it, each best(i) is worked out once.
Time O(n) Space O(n)

At 100 houses: Python 30 µs, the slowest here because of the function calls. Average over 4508 tests: Java 0.29 µs, C++ 0.16 µs.

Approach 2: DP Table

Build it from the left. dp[i] is the most from the first i houses: dp[0] = 0, dp[1] = nums[0], and dp[i] = max(dp[i − 1], dp[i − 2] + nums[i − 1]).

  • Same choice as Approach 1, with a loop instead of calls.
  • The extra dp[0] slot means one house needs no special case.
Time O(n) Space O(n)

At 100 houses: Python 8.9 µs. Average: Java 0.20 µs, C++ 0.14 µs.

Approach 3: Two Variables Optimal

dp[i] only uses dp[i − 1] and dp[i − 2]. Keep them as cur and prev. For each house x: prev, cur = cur, max(cur, prev + x).

  • Update both at once (or use a temporary), so prev gets the old cur.
Time O(n) Space O(1)

At 100 houses: Python 5.0 µs. Average: Java 0.14 µs, C++ 0.03 µs, the fastest in every language.

In practice No shortcut

No library function picks non-adjacent items. Approach 3 is four lines and is what you'd write.
