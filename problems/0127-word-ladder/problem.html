127. Word Ladder Hard Hash Table String BFS
Key idea: Words are nodes, and two words are joined if they differ by one letter. The shortest ladder is a BFS from beginWord. Find neighbors by changing each letter to a…z and looking the result up in a set, and remove a word from the set as soon as it's queued. Searching from both ends at once is faster still.

Problem View on LeetCode (opens in a new tab) ↗

A ladder goes from beginWord to endWord, changing one letter at a time. Every word after the first must be in wordList (beginWord itself doesn't have to be). Return the number of words in the shortest ladder, or 0 if there is none.

  • 1 <= beginWord.length <= 10; endWord and every word in wordList have the same length
  • 1 <= wordList.length <= 5000
  • Lowercase letters only; beginWord != endWord; the words in wordList are unique

Example: "hit" → "cog" with ["hot","dot","dog","lot","log","cog"] → 5 (hit → hot → dot → dog → cog). Without "cog" in the list → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky

"hit", "cog", ["hot","dot","dog","lot","log","cog"] 5 Count the words, not the moves. Starting the count at 0 says 4.
"hit", "hot", ["hot"] 2 One change: the shortest possible ladder.
"a", "c", ["a","b","c"] 2 One-letter words: every word is next to every other. beginWord is in the list too; don't visit it again.
"hot", "dog", ["hot","dog"] 0 endWord is in the list but two letters away, with nothing in between.
"hot", "dog", ["hot","dot","dog"] 3 The list holds beginWord. Remove it from the set first, or it can be queued again later.
5,000 words of length 10, endWord with no neighbors 0 A one-way BFS visits every reachable word before giving up. The two-ended search stops at once: its back side is empty after one level.
5,000 words of length 10, about 12 neighbors each 9 Comparing each queued word with every unused word came to 7.2 million comparisons; Python took 2.7 s here.

Approach 1: BFS, Comparing With Every Word

BFS from beginWord, one level per extra word. For each word taken from the queue, compare it letter by letter with every word not used yet; the ones that differ in exactly one place join the queue.

  • BFS finds the shortest ladder because it reaches every word with the fewest steps first.
  • Mark a word used when it's queued, not when it's taken out, so it's never in the queue twice.
Time O(n² · L) Space O(n · L)

n = number of words, L = word length. Each word is compared with up to n others. Measured here on 5,000 words of length 10: Python 2.7 s, Java 0.2 s, C++ 71 ms. Fine when the words are long and few; slow when there are many short ones.

Approach 2: BFS, Trying Every One-Letter Change

Instead of comparing with all n words, make the neighbors: change each of the L letters to each of a…z and check whether the result is in a set of unused words. That's 26 · L lookups per word, no matter how long the list is.

  • Removing a word from the set when it's queued doubles as the "used" mark.
  • Marking it only when it comes out of the queue still gives the right answer, but the same word gets queued many times: 28,691 pushes instead of 4,960 on the 5,000-word test.
  • In C++ and Java, change the letter in place and put it back, instead of building a new string for every try.
Time O(n · 26 · L²) Space O(n · L)

26 · L tries per word, each costing O(L) to build and hash. On the same 5,000 words: Python 0.2 s (13× faster than Approach 1), Java 36 ms, C++ 13 ms. The standard interview answer.

Approach 3: Two-Ended BFS Optimal

Grow one level from beginWord and one from endWord, taking turns, and stop when a new word is already on the other side. Always grow the smaller side.

  • If each word has about d neighbors and the ladder has k steps, a one-way BFS looks at about dk words. Two searches that meet in the middle look at about 2 · dk/2.
  • Keep the endWord check: without it, the back side starts at a word that isn't allowed.
  • Swapping to the smaller side is what makes it fast: without the swap it took 192 ms here instead of 26 ms in Python.
Time O(n · 26 · L²) worst case Space O(n · L)

Same worst case as Approach 2, but far less work in practice. On the 5,000 words: Python 25 ms (8× faster than Approach 2), Java 15 ms, C++ 6 ms. When endWord has no neighbors, it stops after one level (0 ms vs 0.2 s). A strong follow-up after Approach 2.

In practice No shortcut

Python, C++ and Java have no shortest-path helper for this. The parts that matter are the set (set, unordered_set, HashSet) and the queue (deque, std::queue, ArrayDeque), both used above.

Approach 2 is what you'd write first; switch to Approach 3 when the list is large or the ladders are long.
