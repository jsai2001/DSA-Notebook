2013. Detect Squares Medium Array Hash Table Design
Key idea: Store a count per point (a point can be added more than once). To count squares with corner q = (x, y), pick a point (x, y2) straight above or below it: that fixes the side d = y2 − y, and the square is to the right or to the left. Multiply the counts of the three stored corners. With points grouped by column this is O(points in q's column) per count.

Problem View on LeetCode (opens in a new tab) ↗

Build a class DetectSquares:

  • add(point) stores a point [x, y]. Repeats are allowed and count separately.
  • count(point) returns how many ways to pick three stored points that make, with the query point, a square of positive area whose sides are parallel to the axes. The query point is not stored.
  • 0 <= x, y <= 1000, and at most 3000 calls to add and count in total.

Example: add [3,10], [11,2], [3,2]; count([11,10]) → 1; count([14,8]) → 0; add [11,2] again; count([11,10]) → 2 (either copy of (11, 2) can be the corner).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
The example, after adding [11,2] twice 2 Repeats are separate points. Storing a set of points (not counts) says 1.
Add [5,5] twice, count([5,5]) 0 Side 0 is not a square: skip points with the query's own y (or x).
Corners (0,0) (1,0) (0,2) (1,2), count([1,0]) 0 A rectangle, not a square: the two sides must have the same length.
Add (0,0) (0,1) (1,1), count([1,0]) 1 The square is to the left of the query. Checking only x + d (the right side) says 0.
Add (1000,0) (1000,1000) (0,1000), count([0,0]) 1 The biggest square. With a 1001 × 1001 table, x ± d can fall outside 0..1000: check before indexing.
count before any add 0 Nothing stored: the loops must simply find nothing.
1500 adds on a 10 × 10 corner, then counts up to 71525 Many repeats: a list scanned for each corner took 20 s in Python. Counting each point once is what makes it fast.

Approach 1: Keep Every Point in a List

Store the points as they come. For count, try every stored point p as the corner across from the query (the diagonal): it must differ in x and y by the same amount. Then the other two corners are fixed, (x, py) and (px, y); scan the list to see how many of each there are.

  • Squares for this p = (copies of one corner) × (copies of the other). Repeats of p itself are counted because p's own repeats are separate list entries.
Time O(1) add, O(n²) count (n = points added) Space O(n)

Fine with few points, but with 1500 points on a small board, 1500 counts took 20 s in Python. Too slow.

Approach 2: Count Each Point, Try Each as the Diagonal

Store cnt[(x, y)], how many times each point was added. For count, loop over the distinct points as the diagonal corner, and look the other two corners up in O(1).

  • Squares for diagonal p = cnt[p] · cnt[(x, py)] · cnt[(px, y)]. A missing corner has count 0, so the product is 0.
Time O(1) add, O(k) count (k = distinct points) Space O(k)

The usual answer: 0.014 s for the dense test. With 1500 points spread over the whole 1001 × 1001 board it took 0.19 s, because every count still looks at every distinct point.

Approach 3: Group Points by Column Optimal

Every square through the query has a corner straight above or below it, in the same column. So also keep, for each x, the y's added in that column. Each one, (x, y2), gives the side d = y2 − y, and then there are just two squares to check: to the right (x + d) and to the left (x − d).

  • Squares = cnt[(x, y2)] · cnt[(x2, y)] · cnt[(x2, y2)] for each x2 in (x + d, x − d).
  • Skip y2 == y: side 0.
Time O(1) add, O(points in the query's column) count Space O(k)

A column holds at most 1001 different y's, whatever else is stored: 0.002 s for the spread-out test and 0.007 s for the dense one.

In practice No shortcut

No library counts squares, but the hash maps do the work: defaultdict(int) or Counter in Python, unordered_map (or a plain table, since coordinates are small) in C++, HashMap or an int[][] in Java.

Remember the three things: counts, not a set; skip side 0; check both the right and the left square.
