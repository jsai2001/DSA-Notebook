200. Number of Islands Medium Matrix Breadth-First Search Union Find
Key idea: Scan the grid. Every "1" that's still land is a new island: add 1, then flood the whole island and sink it (set it to "0") so it's never counted again. A BFS queue does the flood without deep recursion.

Problem View on LeetCode (opens in a new tab) ↗

grid is a map of "1" (land) and "0" (water). An island is land joined up, down, left or right. Count the islands.

  • 1 <= m, n <= 300
  • Cells are the characters '0' and '1', not numbers

Example: ["11110","11010","11000","00000"] → 1. ["11000","11000","00100","00011"] → 3.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
["01","11"] 1 Counting land cells with no land above or to the left said 2: an island can be reached from below. Wrong on 939 of 3038 tests.
300 × 300, all land 1 The recursive DFS goes up to 90,000 calls deep. In Java, with the default stack here, it threw StackOverflowError.
300 × 300, all land 1 A BFS that sinks cells when they're popped (not when queued) still counts right, but queued 179,401 cells instead of 90,000.
300 × 300 checkerboard 45000 The most islands possible: every land cell is alone.

Approach 1: Recursive DFS

sink(r, c) stops on off-grid cells and water. Otherwise it sets the cell to "0" and calls itself on the four neighbours. Each land cell the scan finds adds one island and sinks it.

  • The shortest code, and usually the first answer people give.
  • One call per cell can nest m·n deep: 90,000 calls here.
  • Python needs sys.setrecursionlimit; it ran fine with that on Python 3.14.
Time O(m·n) Space O(m·n) call stack

300 × 300 of land: Python 57 ms, C++ 2.8 ms. Java crashed with StackOverflowError on that grid and on a 300 × 300 snake, and passed the other 3036 tests.

Approach 2: Union-Find

Start with count = number of land cells, each its own group. For every land cell, look at the cell below and to the right. If it's land in a different group, join the groups and subtract 1. What's left is the number of islands.

  • Down and right are enough: every touching pair is met exactly once.
  • It doesn't change grid, and it suits the follow-up where land is added over time (Number of Islands II).
Time O(m·n·log(m·n)) at worst, near O(m·n) Space O(m·n)

300 × 300 of land: Python 81 ms, Java 2.6 ms, C++ 2.1 ms. The slowest in Python, but no recursion anywhere.

Approach 3: BFS Optimal

Same scan as Approach 1, but flood with a queue. Sink each cell the moment it's queued; pop cells and queue their land neighbours until the queue is empty.

  • Sink on queue, not on pop, so a cell is never queued twice.
  • No recursion, so no stack limit in any language.
Time O(m·n) Space O(m·n) at worst, usually far less

300 × 300 of land: Python 52 ms, Java 1.4 ms, C++ 0.6 ms, the fastest in every language on that grid.

In practice No shortcut

The standard libraries have no flood fill. Outside LeetCode, scipy.ndimage.label returns the number of islands directly, with 4-way joins by default.

On LeetCode, Approach 3 is what you'd write.
