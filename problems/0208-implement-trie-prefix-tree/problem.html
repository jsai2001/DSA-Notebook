208. Implement Trie (Prefix Tree) Medium Trie Design Hash Table
Key idea: A trie is a tree of letters. Each node has one child per next letter, and a flag that says "a word ends here". Inserting or looking up a word of length L walks L nodes, so startsWith costs O(L) no matter how many words are stored. search must also check the end flag.

Problem View on LeetCode (opens in a new tab) ↗

Build a Trie class with insert(word), search(word) (was this exact word inserted?) and startsWith(prefix) (does any inserted word start with it?).

  • 1 <= word.length, prefix.length <= 2000, lowercase letters only
  • At most 3 × 10⁴ calls in total

Example: insert("apple"), search("apple") → true, search("app") → false, startsWith("app") → true, insert("app"), search("app") → true.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
insert("apple"), search("app") false "app" is only a prefix. A search that doesn't check the end flag says true.
then insert("app"), search("app") true Inserting a word that's a prefix of another adds no nodes: it only sets the end flag.
10,000 inserts, then 20,000 searches and prefix checks - A plain set has to scan every word for startsWith: 3.2 s in Python.
a 2000-letter word - 2000 nodes in one chain. Fine for a loop; a recursive insert would go 2000 calls deep.

Approach 1: Hash Set of Words

Keep the words in a set. insert and search are one hash operation each. startsWith has no shortcut: check whether any stored word starts with the prefix.

  • Fine if prefix checks are rare.
  • startsWith costs O(total letters stored).
Time O(L) insert/search, O(N·L) startsWith Space O(total letters)

10,000 words, then 20,000 mixed queries: Python 3.2 s, Java 692 ms, C++ 236 ms. About 45 to 190 times slower than a trie.

Approach 2: Trie of Hash Maps

Each node is a map from letter to child. insert walks the letters, adding missing nodes, and marks the last node as a word end. A shared walk finds the node for a string; search also needs the end mark, startsWith doesn't.

  • Nodes only store the letters they use: good for big alphabets.
  • In Python a node is just a dict, with "$" as the end mark.
Time O(L) per call Space O(total letters)

Same 30,000 calls: Python 20 ms, the fastest in Python. Java 6.6 ms, C++ 5.2 ms.

Approach 3: Trie With 26 Child Slots Optimal

Only lowercase letters appear, so each node can hold an array of 26 children: the child for ch is at ch − 'a'. No hashing, just an index.

  • The usual interview answer, and the fastest in C++ and Java.
  • Each node holds 26 slots even if it uses one, so it takes more memory.
Time O(L) per call Space O(26 · nodes)

Same 30,000 calls: Java 3.6 ms, C++ 3.1 ms. Python 35 ms: slower than Approach 2 here. In Python, a small dict per node beat a 26-slot list.

In practice No shortcut

The standard libraries have no trie. With a sorted list of words, a binary search (bisect, lower_bound, TreeSet.ceiling) finds the first word ≥ the prefix, and checking that one word answers startsWith.

For this problem, Approach 2 or 3 is what you'd write.
