43. Multiply Strings Medium Math String Simulation
Key idea: Do school multiplication in one array of m + n places. The digit product num1[i] × num2[j] belongs at places i + j and i + j + 1: add it to pos[i + j + 1], keep the last digit there, carry the rest into pos[i + j]. Return "0" early if either input is "0", and drop the one possible leading zero. O(m · n).

Problem View on LeetCode (opens in a new tab) ↗

Given two non-negative integers num1 and num2 written as strings, return their product, also as a string.

  • 1 <= num1.length, num2.length <= 200, digits only.
  • No leading zeros, except the number "0" itself.
  • You must not use a big-integer library or convert the inputs to integers directly.

Examples: "2" × "3" → "6"; "123" × "456" → "56088".

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"0" × "0" "0" Stripping every leading zero leaves an empty string; the answer must still be "0".
"0" × "52" "0" Without an early check, the shifted rows of long multiplication give "00".
"2" × "3" "6" The product has m + n − 1 digits, so the m + n array starts with a 0: "06" if it isn't dropped.
"9" × "9" "81" The product has the full m + n digits: nothing to drop, and the top place gets a carry.
"10" × "10" "100" Zeros inside and at the end of the answer must stay; only the front is trimmed.
"99" × "99" "9801" Carries chain across several places.
"123" × "456" "56088" The usual case, with a 0 in the middle of the answer.
200 nines × 200 nines 400 digits The largest input: far past 64-bit integers (about 19 digits), which is why the problem exists.

Approach 1: Long Multiplication, Row by Row

Exactly what you'd do on paper: multiply num1 by each digit of num2, shift each row one more place to the left (append zeros), and add the rows up as strings.

  • Two helpers: a number times one digit, and Add Strings (LeetCode 415) for the running total.
  • A digit of 0 adds nothing, so its row can be skipped.
Time O(n · (m + n)) Space O(m + n) per row

Easy to trust because it's the method you already know, but it builds a new string for every row and every addition. It was the slowest here: 21 ms in Python for 200 × 200 digits, against 6 ms for Approach 2.

Approach 2: One Array of Places Optimal

Skip the rows and add every digit product straight into the place it belongs. With pos of length m + n and index 0 on the left, num1[i] × num2[j] covers pos[i + j] (tens) and pos[i + j + 1] (ones).

  • total = num1[i] × num2[j] + pos[i + j + 1]
  • pos[i + j + 1] = total % 10, pos[i + j] += total / 10
  • pos[i + j] can briefly go above 9; the next product that lands there (or the final digits) carry it on, so the result is right.
  • Only pos[0] can be a leading zero.
Time O(m · n) Space O(m + n)

The answer interviewers expect: one array, no string additions. The index rule i + j / i + j + 1 is the part to remember.

Approach 3: Column Sums, Then One Carry Pass

Separate the two jobs. First add up every digit product into its column (place i + j, counting from the ones place) without carrying. Then make one pass from the ones place up, turning each column into a single digit and carrying the rest.

  • A column can hold up to 81 × 200 = 16,200 before carrying: no risk of overflow.
  • Then drop the unused top place, if it's 0.
Time O(m · n) Space O(m + n)

Same complexity as Approach 2 with only m + n carry steps instead of one per product, so it was the fastest here in Python (2 ms for 200 × 200 digits). It's also how big-number libraries begin: the column sums are a convolution, which faster methods (Karatsuba, FFT) speed up.

In practice Built-ins

Day to day you'd never write this. Python's int has no size limit, and Java has BigInteger. C++ has no standard big integer (you'd use a library such as Boost.Multiprecision or GMP).

Time faster than O(m · n) for large numbers Space O(m + n)

Both pass on LeetCode's tests, but the problem statement forbids them, so in an interview write Approach 2.
