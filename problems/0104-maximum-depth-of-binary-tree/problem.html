104. Maximum Depth of Binary Tree Easy Tree DFS BFS
Key idea: A tree's depth is 1 (this node) + the deeper of its two subtrees, and an empty tree has depth 0. That's three lines of recursion, O(n). On a very deep tree, count the levels with BFS instead, so there's no recursion at all.

Problem View on LeetCode (opens in a new tab) ↗

Given the root of a binary tree, return its maximum depth: the number of nodes on the longest path from the root down to a leaf.

  • 0 to 10⁴ nodes (the tree can be empty).
  • -100 <= Node.val <= 100.

Examples: [3,9,20,null,null,15,7] → 3; [1,null,2] → 2.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[] 0 No nodes. Reading root.left without checking crashes.
[0] 1 One node is depth 1: the answer counts nodes, not edges.
[3,9,20,null,null,15,7] 3 Counting edges (a leaf as 0) gives 2.
[1,null,2] 2 The left side is empty. Taking the min of the two sides by mistake gives 1.
[1,2,3,null,null,null,4,null,5] 4 The deepest path isn't on the left: both sides must be checked.
10⁴ nodes in one line 10000 10⁴ deep: plain recursion passes Python's default limit of 1000. BFS or a stack has no such limit.

Approach 1: BFS, Count the Levels

The depth is the number of levels. Walk the tree level by level with a queue, as in Level Order Traversal (102), and add 1 for each level.

  • At the start of each round the queue holds exactly one level: pop that many nodes, adding their children.
Time O(n) Space O(w), the widest level

No recursion, so a 10⁴-deep line is no problem (1.4 ms in Python).

Approach 2: Recursion Optimal

Ask each subtree for its depth and add 1 for the current node: 1 + max(depth(left), depth(right)). An empty subtree answers 0, which makes a leaf come out as 1.

  • Every node is visited once, after both its children (post-order).
Time O(n) Space O(h) call stack

The answer interviewers expect, and the base of many tree problems: Balanced Binary Tree (110) and Diameter of Binary Tree (543) use the same height. On a 10⁴-deep line it hit Python's recursion limit (LeetCode raises the limit, so it passes there).

Approach 3: DFS with a Stack

The same depth-first walk without recursion: push (node, depth) pairs on a stack, and keep the biggest depth seen.

  • Push the right child first, so the left one is popped first (the same order as the recursion).
Time O(n) Space O(h) for the stack

Depth first like Approach 2, but safe on deep trees (1.3 ms for the 10⁴-deep line).

In practice No shortcut

LeetCode's TreeNode has no height or depth built in, in any of the three languages.

Write Approach 2. Return 0 for an empty tree, and use max, not min (that's 111, Minimum Depth, and it needs extra care for nodes with one child).

Comparison

Approach Technique Time Space Notes
BFS Levels Count rounds of a level-by-level queue O(n) O(w) No recursion
Recursion 1 + max(left, right) O(n) O(h) The usual answer
DFS Stack (node, depth) pairs, keep the max O(n) O(h) Depth first, no recursion
