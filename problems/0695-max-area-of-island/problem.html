695. Max Area of Island Medium Matrix Depth-First Search Breadth-First Search
Key idea: Scan the grid. Each land cell you meet starts a new island: flood it with a DFS and count the cells. Sink every cell you reach (set it to 0) so no cell is counted twice. Every cell is touched a constant number of times: O(m·n).

Problem View on LeetCode (opens in a new tab) ↗

grid holds 0 (water) and 1 (land). An island is a group of land cells joined up, down, left or right. Return the area (number of cells) of the biggest island, or 0 if there is no land.

  • 1 <= m, n <= 50
  • grid[i][j] is 0 or 1

Example: LeetCode's 8 × 13 grid → 6. [[0,0,0,0,0,0,0,0]] → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[0,0,0,0,0,0,0,0]] 0 No land at all: the answer is 0, not an error from max of nothing.
[[1,1],[1,1]] 4 Approach 3 sinking a cell when it's popped instead of when it's pushed lets a cell be pushed twice: it said 5.
50 × 50, all land 2500 Recursive DFS goes 2500 calls deep. With Python's default limit of 1000 it raised RecursionError, so Approach 2 raises the limit.
50 × 50, all land 2500 Approach 1 floods the same island once per cell: 6.25 million cell visits, 4.6 s in Python.

Approach 1: Flood From Every Land Cell

For each land cell, find its whole island with a fresh seen set and a stack, and count it. Keep the biggest count. The grid isn't changed.

  • Easy to get right: each count starts clean.
  • But an island of k cells is counted k times, k cells each time.
Time O((m·n)²) Space O(m·n)

On a 50 × 50 grid of land: Python 4.6 s, Java 174 ms, C++ 41 ms. Too slow; it shows why sinking matters.

Approach 2: Recursive DFS, Sinking Cells

area(r, c) returns 0 for off-grid, water, or an already sunk cell. Otherwise it sinks the cell and returns 1 + the areas of its four neighbours. Call it on each land cell the scan finds.

  • Sinking replaces the seen set, so each cell is counted once.
  • It changes grid. Copy it first if the caller still needs it.
  • One call per cell can stack up m·n deep, hence sys.setrecursionlimit in Python.
Time O(m·n) Space O(m·n) call stack

On a 50 × 50 grid of land: Python 1.6 ms, Java 0.3 ms, C++ 0.06 ms. Java and C++ handled 2500 calls deep without trouble here.

Approach 3: DFS With a Stack Optimal

Same flood, but with your own stack instead of recursion. Sink a cell the moment you push it, and count it when you pop it. When the stack is empty, the island is done.

  • Sink on push: if you sink on pop, two neighbours can push the same cell.
  • No recursion limit to worry about in any language.
Time O(m·n) Space O(m·n)

On a 50 × 50 grid of land: Python 1.5 ms, Java 0.4 ms, C++ 0.02 ms. Same speed as Approach 2, without the deep calls.

In practice No shortcut

The standard libraries have no flood fill. Outside LeetCode, scipy.ndimage.label labels every island of a NumPy grid in one call (4-way joins by default); counting the cells of each label gives the answer.

On LeetCode, Approach 3 is what you'd write.
