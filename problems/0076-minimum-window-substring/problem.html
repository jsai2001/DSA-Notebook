76. Minimum Window Substring Hard Hash Table String Sliding Window
Key idea: Grow the window to the right until it covers t, then shrink it from the left while it still does. Keep need[c] (how many more of each letter the window needs) and missing (how many letters of t are still missing): the window covers t exactly when missing == 0. Each letter enters and leaves once, so O(m + n).

Problem View on LeetCode (opens in a new tab) ↗

Given strings s and t, return the shortest substring of s that contains every letter of t, duplicates included. If there's none, return "".

  • m = s.length, n = t.length, 1 <= m, n <= 10⁵.
  • Both strings are uppercase and lowercase English letters ('A' and 'a' are different).
  • The answer is unique in LeetCode's tests.
  • Follow-up: can you do it in O(m + n)?

Examples: s = "ADOBECODEBANC", t = "ABC" → "BANC"; s = "a", t = "a" → "a"; s = "a", t = "aa" → "" (s has only one a).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"a", "aa" "" t has two a's. Checking only that each letter appears (a set) says "a".
"ab", "abc" "" t is longer than s: no window can cover it. The answer must start as "none", not as all of s.
"ab", "A" "" Upper and lower case are different letters.
"abc", "cba" "abc" The answer is all of s. Starting best at len(s) and keeping only shorter windows never records it; start one past it.
"xxxab", "ba" "ab" The answer ends at the last letter: it's found inside the loop, so nothing is left to check after it.
"aaab", "ab" "ab" The first window that covers t is "aaab". Shrinking has to drop two extra a's, not just one.
"aba", "aa" "aba" The two a's aren't next to each other, so the b in between has to stay.
"bba", "ab" "ba" The first b is extra. Approach 3: need[b] goes to −1, which is how it knows that b can go.
"ADOBECODEBANC", "ABC" "BANC" "ADOBEC" covers t first; the shortest window only shows up after giving up the A and growing again.

Approach 1: Try Every Start

For each start i, grow the window to the right one letter at a time until it covers t. That's the shortest window starting at i; keep the shortest of them all.

  • Count missing, the letters of t not yet in the window: a new letter lowers it only while the window has fewer of that letter than t does.
  • Stop growing at the first cover (break): longer windows from the same start can't be shorter.
Time O(m² + n) Space O(1) (a count per letter)

Correct, but every start can scan to the end. With s = "aa…ab" and t = "ab" it took 5.6 s in Python at m = 10⁴ here; at m = 10⁵ that's 100 times more. C++ took 10.4 s at m = 10⁵.

Approach 2: Sliding Window, Compare Counts

Don't restart for every i. Move right one letter at a time and add it to have. Whenever s[left..right] covers t, record it, then drop s[left] and check again. Both ends only move right.

  • "Covers" means have[c] >= need[c] for every distinct letter c of t (k of them, at most 52).
  • The while keeps shrinking as long as it still covers, so every window recorded is the shortest one ending at right.
Time O(k · m + n), k = distinct letters in t Space O(1)

The cover check looks at up to 52 counts after each move. With random letters and all 52 in t, it took 0.52 s in Python at m = 10⁵ (5 ms in C++). Fast enough to pass.

Approach 3: Sliding Window, Count What's Missing Optimal

Replace the 52-way check with one number. need[c] starts as the count of c in t and drops by 1 whenever c enters the window; missing starts at len(t). The window covers t exactly when missing == 0.

  • A letter coming in lowers missing only if need[c] > 0 before (t still wanted it). Then need[c] −= 1, which can go below 0: that many extra copies.
  • Once it covers: drop letters from the left while need[s[left]] < 0 (extra copies), record the window, then give up s[left] so one letter is missing again and keep growing.
Time O(m + n) Space O(1) (128 counts)

Each letter of s enters once and leaves at most once, so the work is constant per letter: 20 ms in Python and 0.3 ms in C++ at m = 10⁵. The same need/missing idea as Permutation in String (567), with a window that changes size.

In practice Built-ins

In Python, collections.Counter gives Approach 2 almost for free: need <= have asks "does every count in t fit in the window?" in one expression. C++ and Java have nothing built in for this, so write Approach 3.

Time O(k · m + n) Space O(k)

Passes every test here; 0.84 s in Python on the same 10⁵ random letters, so slower than Approach 2 but still fine. <= on Counters needs Python 3.10 or later.
