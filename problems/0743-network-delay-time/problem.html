743. Network Delay Time Medium Graph Shortest Path Heap (Priority Queue)
Key idea: The signal reaches each node along its fastest path, so find the shortest time from k to every node (Dijkstra, since no time is negative). The answer is the largest of those times, or -1 if some node is never reached. With at most 100 nodes, the simple O(n²) Dijkstra with an array is never slow here; a heap pays off when the graph is big and sparse.

Problem View on LeetCode (opens in a new tab) ↗

Nodes are 1..n. times[i] = [u, v, w] means a signal sent from u reaches v after w. Send a signal from k. Return how long it takes for every node to receive it, or -1 if some never do.

  • 1 <= k <= n <= 100, 1 <= times.length <= 6000
  • 0 <= w <= 100; edges are one-way and no (u, v) pair repeats

Example: [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2 → 2. [[1,2,1]], n = 2, k = 1 → 1. [[1,2,1]], n = 2, k = 2 → -1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[1,2,1]], n = 2, k = 2 -1 Edges are one-way: node 1 is never reached. Returning the largest time found without checking that every node was reached said 0. Wrong on 871 of 1758 small tests.
[[1,2,1],[2,3,2],[1,3,4]], n = 3, k = 1 3 Dijkstra that fixes a node's time when it's first pushed keeps the direct edge 1→3 (4) instead of 1→2→3 (3). Wrong on 223 tests.
[[1,2,0]], n = 2, k = 1 0 A time of 0 is allowed; don't treat 0 as "not reached".
a 100-node chain listed backwards, plus 5900 slow edges 99 Bellman-Ford can't stop early: each round moves the signal one node. 99 rounds × 6000 edges took 23 ms in Python.

Approach 1: Bellman-Ford

Start with dist[k] = 0 and everyone else at ∞. In each round, try every edge: if dist[u] + w < dist[v], lower dist[v]. After n − 1 rounds every shortest path is found; stop sooner if a round changes nothing.

  • The simplest to write, and it also works with negative times (this problem has none).
  • On random graphs it usually stops after a few rounds.
Time O(n·E) Space O(n)

The worst case above (99 full rounds): Python 23 ms, Java 1.1 ms, C++ 0.55 ms. A random 100-node graph with 6000 edges: Python 1.7 ms.

Approach 2: Dijkstra With a Heap

A heap holds (time, node) offers. Pop the earliest: if that node is already done, skip it; otherwise its time is final, and each edge out of it pushes a new offer.

  • A node's time is only final when it's popped, not when it's pushed.
  • The usual Dijkstra, and the right choice for large sparse graphs.
  • Here the graph can be dense, so the heap gets up to E entries.
Time O(E log E) Space O(n + E)

A random 100-node graph with 6000 edges: Python 2.0 ms, Java 0.6 ms, C++ 0.32 ms, the slowest of the three on that graph.

Approach 3: Dijkstra With an Array Optimal

Store the edge times in an n × n table. n times: scan for the unfinished node with the smallest time, mark it final, and lower the time of every node it has an edge to. If the smallest is ∞, return -1.

  • No heap: O(n²) = 10⁴ steps, less than the heap's E log E with up to 6000 edges.
  • It also stops at once if the rest can't be reached.
Time O(n² + E) Space O(n²)

A random 100-node graph with 6000 edges: Python 1.4 ms, Java 0.10 ms, C++ 0.03 ms, the fastest in Python and C++ (Java's Bellman-Ford, which stopped early, was 0.06 ms). The worst case above: C++ 0.03 ms, against 0.25 ms for the heap and 0.55 ms for Bellman-Ford.

In practice No shortcut

The standard libraries have heaps but no shortest-path function. Outside LeetCode, scipy.sparse.csgraph.dijkstra or networkx.single_source_dijkstra_path_length do it.

On LeetCode, write Approach 2 or 3. Approach 2 is the one that carries over to bigger problems.
