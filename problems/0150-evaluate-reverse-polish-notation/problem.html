150. Evaluate Reverse Polish Notation Medium Array Stack Math
Key idea: One stack. Push every number. On an operator, pop two: the top is the right operand, the one under it the left. Push the result. At the end the stack holds the answer. Division rounds toward zero, so in Python use int(a / b), not a // b.

Problem View on LeetCode (opens in a new tab) ↗

Evaluate an expression written in Reverse Polish Notation: each operator comes after its two operands, so ["2","1","+","3","*"] means (2 + 1) × 3. Operators are + - * /; division truncates toward zero.

  • 1 <= tokens.length <= 10⁴
  • Numbers are in [-200, 200]; the expression is valid, never divides by zero, and every result fits in 32 bits

Example: ["4","13","5","/","+"] → 6 (4 + 13 / 5). ["10","6","9","3","+","-11","*","/","*","17","+","5","+"] → 22.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
["-7","2","/"] -3 Rounds toward zero. Python's // floors: it said -4. Same for ["7","-2","/"].
["4","13","5","/","+"] 6 The first pop is the right operand. Popping in the wrong order computed 5 / 13 = 0: said 4.
["3","-4","-"] 7 "-4" is a number, not an operator. Testing numbers with isdigit() treated it as "minus" and popped an empty stack.
["5"] 5 No operator at all.
["0","3","/"] 0 Zero divided by something is fine.
9,999 tokens: 1 1 + 1 + … 5000 A recursive solution nests about 5,000 calls deep; Python's limit is 1,000. Without raising it, Python failed already at 1,999 tokens.
9,999 tokens: all numbers, then all + 5000 Rewriting the list from the start each time scans half of it per operator: 651 ms in Python here.

Approach 1: Rewrite the List

Find the first operator. The two items right before it are numbers, its operands. Replace the three items with the result, and repeat until one number is left.

  • Mirrors doing it by hand.
  • Each operator rescans from the start and shifts the rest of the list.
Time O(n²) Space O(n)

On 9,999 tokens with every operator at the end: Python 651 ms, Java 37 ms, C++ 6.4 ms. On the alternating chain the operators are found early, so it's fast (Python 5 ms).

Approach 2: Recursion From the End

The last token is the final operation. Reading backwards, a number is just itself; an operator first evaluates its right operand (the tokens just before it), then its left, then combines them.

  • The expression is a tree, and this walks it from the root.
  • The calls nest as deep as the tree: about n / 2 on a long chain. The Python code raises the recursion limit for that.
Time O(n) Space O(n) call stack

Python 2.4 ms, Java 2–2.4 ms, C++ 0.2 ms on 9,999 tokens. Works, but the deep recursion is a risk the stack version doesn't have.

Approach 3: One Stack Optimal

Go left to right. Push numbers. On an operator, pop b (top) then a, and push a op b. Return the one number left.

  • A number is anything that isn't exactly + - * /: "-4" has length 2.
  • C++ and Java / already truncates toward zero; Python needs int(a / b) (safe here, since values fit in 32 bits).
Time O(n) Space O(n)

Python 1.7–1.9 ms, Java 3–3.5 ms, C++ 0.13–0.15 ms on 9,999 tokens. The expected answer, and the reason RPN exists: it needs no parentheses and no precedence rules.

In practice No shortcut

No standard library evaluates RPN. In Python, a dict from operator to function (operator.add, operator.sub, …) shortens Approach 3, but division still needs a truncating lambda, since operator.floordiv floors.

Approach 3 is what you'd write. Don't build a string for eval: it's slow and unsafe on untrusted input.
