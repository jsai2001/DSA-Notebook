763. Partition Labels Medium Greedy String Hash Table
Key idea: Record each letter's last index. Walk the string keeping end = the furthest last index of any letter in the current part. When i == end, no letter in the part appears later, so cut there. Cutting as early as possible gives the most parts. O(n).

Problem View on LeetCode (opens in a new tab) ↗

Cut s into as many parts as possible so that each letter appears in only one part. Return the sizes of the parts, in order.

  • 1 <= s.length <= 500, lowercase letters

Example: "ababcbacadefegdehijhklij" → [9,7,8]. "eccbbbbdec" → [10].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"baba" [4] Cutting at the first letter's last copy without growing for the letters inside said [3,1]: the last a was left out. Wrong on 1249 of 3006 tests.
"abc" [1,1,1] All letters different: every letter is its own part.
"eccbbbbdec" [10] The first and last letters match, so it can't be cut at all.

Approach 1: Grow Each Part by Searching

Start a part at the next letter. Its end is at least that letter's last copy. For every letter inside, search from the back for its last copy and push the end out if needed. When nothing pushes it further, cut.

  • Each search (rindex, rfind, lastIndexOf) scans up to n letters.
Time O(n²) Space O(1) besides the answer

With n ≤ 500 it's fast anyway: Python 0.11 ms, Java 0.10 ms, C++ 0.03 ms on 500 letters.

Approach 2: Merge Letter Spans

Each letter covers the span from its first to its last index. Two overlapping spans must be in the same part. Sort the spans (at most 26) by start and merge them, as in Merge Intervals; each merged span is one part.

  • Turns the problem into one you may already know.
Time O(n) (sorting ≤ 26 spans is constant) Space O(1)

500 letters: Python 36 µs (the fastest in Python here), Java 7.4 µs, C++ 2.0 µs.

Approach 3: Last Index, One Pass Optimal

First record last[ch] for every letter. Then walk the string with end = max(end, last[ch]). When i == end, every letter seen in this part is finished: record the size and start a new part.

  • Two short loops and an array of 26.
Time O(n) Space O(1)

500 letters: Python 52 µs, Java 11 µs, C++ 1.6 µs, the fastest in C++. At this size all three are well under a millisecond.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write.

Comparison

Approach Technique Time Space Notes
Grow by Searching rindex for each letter O(n²) O(1) Fine at n ≤ 500
Merge Letter Spans Merge Intervals on ≤ 26 spans O(n) O(1) Reuses a known pattern
Last Index, One Pass Cut when i == end O(n) O(1) Expected answer
