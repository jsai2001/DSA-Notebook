875. Koko Eating Bananas Medium Binary Search
Key idea: If speed k finishes in time, every faster speed does too. That yes/no flips once, so binary search the speed between 1 and max(piles), checking Σ ceil(p / k) <= h each time. O(n log max).

Problem View on LeetCode (opens in a new tab) ↗

Each hour Koko picks one pile and eats k bananas from it (or the whole pile if it has fewer). Return the smallest k that lets her finish every pile within h hours.

  • 1 <= piles.length <= 10⁴, piles.length <= h <= 10⁹, 1 <= piles[i] <= 10⁹

Example: piles = [3,6,7,11], h = 8 → 4. piles = [30,11,23,4,20], h = 5 → 30; with h = 6 → 23.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
piles = [10⁹,10⁹,10⁹], h = 3 1000000000 At speed 1 that's 3·10⁹ hours. Summed in an int it wraps to −1,294,967,296, which looks "within 3 hours": a Java linear scan with an int returned 1. Use a 64-bit sum.
piles = [10⁹], h = 2 500000000 The answer is huge: trying speeds one by one from 1 took 148 s in Python.
piles = [3,6,7,11], h = 4 11 h equals the number of piles: one pile per hour, so the answer is max(piles).

Approach 1: Try Every Speed

Try k = 1, 2, 3, … and return the first one where the hours Σ ceil(p / k) are at most h.

  • (p + k − 1) // k is ceil(p / k) without floats.
Time O(n · max(piles)) Space O(1)

10⁴ piles up to 10⁴, h = 3·10⁴ (answer 1998): Python 1.0 s, Java 15 ms, C++ 13 ms.

Approach 2: Start at the Lower Bound

In h hours Koko eats at most h · k bananas, so k is at least ceil(sum / h). Start the scan there.

  • Often lands close to the answer, but not always.
Time O(n · max(piles)) at worst Space O(1)

Same input (scan starts at 1668): Python 169 ms, Java 7.2 ms, C++ 2.3 ms. But one pile of 10⁶ and 99 piles of 1 with h = 101: the bound is 9902, the answer 500000, and Python took 2.6 s.

Approach 3: Binary Search on the Speed Optimal

Keep the answer in [lo, hi], starting at [1, max(piles)]. If the middle speed is fast enough, the answer is it or slower: hi = k. If not, it's faster: lo = k + 1. Stop when they meet.

  • About 30 rounds for max(piles) = 10⁹.
  • Same loop shape as 704. Binary Search with lo < hi and hi = mid.
Time O(n log max(piles)) Space O(1)

Same input: Python 6.7 ms, Java 0.30 ms, C++ 0.095 ms. 10⁴ piles up to 10⁹: Python 17 to 24 ms, Java and C++ 0.2 ms, whatever h is. The 2.6 s case above took under 1 ms.

In practice No shortcut

Python 3.10+ could use 1 + bisect_left(range(1, max(piles) + 1), True, key=lambda k: hours(k) <= h) (the 1 + turns the index into a speed), but it's the same search. Approach 3 is what you'd write.
