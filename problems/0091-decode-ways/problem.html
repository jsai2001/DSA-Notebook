91. Decode Ways Medium String Dynamic Programming
Key idea: The last letter used either one digit (1–9) or two digits (10–26). So dp[i] = dp[i − 1] (if the last digit isn't 0) + dp[i − 2] (if the last two make 10–26), with dp[0] = 1. Like Climbing Stairs (70), but each step is allowed only when its digits spell a letter. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Letters are written as numbers: "A" → "1", "B" → "2", …, "Z" → "26". Given a string of digits s, return how many ways it can be read back as letters. A code can't start with 0: "06" is not "F".

  • 1 <= s.length <= 100; s holds only digits and may start with '0'.
  • The answer fits in a 32-bit int.
  • If nothing works, the answer is 0.

Examples: "12" → 2 ("AB" or "L"); "226" → 3 ("BBF", "BZ", "VF"); "06" → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"0", "06" 0 A leading 0 can't start a letter. Checking only "two digits ≤ 26" counts "06" as F and says 1.
"10" 1 The 0 must go with the 1 before it ("J"); it can't stand alone.
"30", "100" 0 A 0 with nothing it can join: 30 is too big, and in 100 the second 0 has a 0 before it.
"2101" 1 The only way is "2 10 1" (B J A). Accepting "01" as a code adds "21 01" and "2 1 01", and says 3.
"27" 1 27 is past Z: only "2 7".
"26" 2 26 itself is Z, so the upper limit is <= 26, not < 26.
"12" 2 dp[0] (no digits) must be 1, not 0: it's what the two-digit step "12" adds. Starting it at 0 says 1.
"1" × 45 1836311903 Every pair is valid, so the count grows like Fibonacci. Plain recursion would take about 10 minutes here (estimated from 0.47 s at 30 digits).

Approach 1: Plain Recursion

ways(i) = the number of ways to decode s[i:]. The next letter is either s[i] alone or s[i:i+2]; add up the ways for whatever is left after each.

  • ways(len(s)) = 1: nothing left is one finished decoding.
  • If s[i] == "0", return 0: no letter starts with 0.
  • The two-digit choice needs 10 <= s[i:i+2] <= 26.
Time O(2ⁿ) (Fibonacci-like growth) Space O(n) stack

The same ways(i) is worked out again and again. On 30 ones it took 0.47 s in Python, and each 5 more digits make it about 11 times slower.

Approach 2: Bottom-Up DP Array

Work from the front instead. dp[i] = ways to decode the first i digits. Look at how the last letter was made: from the last digit alone, or from the last two.

  • dp[0] = 1.
  • If s[i−1] != "0": dp[i] += dp[i − 1].
  • If 10 <= s[i−2:i] <= 26: dp[i] += dp[i − 2].
Time O(n) Space O(n)

Each dp[i] is computed once: 45 ones take 0.01 ms in Python. The array makes it easy to check by hand.

Approach 3: Two Variables Optimal

dp[i] only looks back at dp[i − 1] and dp[i − 2], so keep just those two: prev1 and prev2. After each digit, slide them along.

  • Start with prev1 = dp[0] = 1 and prev2 = 0 (never used at i = 1, since a two-digit code needs two digits).
  • Once both are 0, every later value is 0 too: the string can't be decoded.
Time O(n) Space O(1)

The same work as Approach 2 without the array (0.008 ms for 45 ones). The two-variable trick is the same as Climbing Stairs (70).

In practice Built-ins

In Python, @functools.cache on Approach 1 remembers each ways(i), which turns the slow recursion into O(n) with no other change. C++ and Java have no such decorator: use an array, as in Approach 2.

Time O(n) Space O(n) for the cache and the stack

0.018 ms for 45 ones. @cache needs Python 3.9 or later; the recursion is at most 100 deep here, far under Python's limit.
