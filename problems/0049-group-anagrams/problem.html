49. Group Anagrams Medium Array Hash Table String Sorting
Key idea: Give every word a key that only anagrams share, and group by it in a hash map. The sorted word ("eat" → "aet") works; the 26 letter counts work without sorting, in O(k) per word. One pass: O(n · k).

Problem View on LeetCode (opens in a new tab) ↗

Given an array of strings strs, group the anagrams together (words made of the same letters, each used the same number of times). The groups, and the words inside them, can be in any order.

  • 1 <= strs.length <= 10⁴ and 0 <= strs[i].length <= 100.
  • Only lowercase English letters.

Examples: ["eat","tea","tan","ate","nat","bat"] → [["bat"],["nat","tan"],["ate","eat","tea"]]; [""] → [[""]]; ["a"] → [["a"]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[""] [[""]] The empty word is a real word with a real group, not something to skip.
["",""] / ["a","a"] [["",""]] / [["a","a"]] Duplicates stay: both copies go into the same group. A set would lose one.
["aab","abb"] [["aab"],["abb"]] Same letters, different counts: not anagrams. A key made from the set of letters groups them by mistake.
["ab","ba","abc"] [["ab","ba"],["abc"]] A word containing another's letters isn't its anagram; lengths must match too.
["abbbbbbbbbbb","aaaaaaaaaaab"] Two groups Counts 1, 11 and 11, 1. Joining counts into a string without a separator gives "111…" for both and merges them.
["eat","tea","tan","ate","nat","bat"] 3 groups The usual case: groups of different sizes, words out of order.
10⁴ different words of 100 letters 10⁴ groups of one No anagrams at all: comparing each word with every group so far is about 5 × 10⁷ checks.

Approach 1: Compare with Every Group

Keep a list of groups. For each word, check it against one word from each group (are they anagrams?), and join the first one that matches, or start a new group.

  • Two words are anagrams if they have the same length and the same letters when sorted.
Time O(n · g · k log k), g = groups Space O(n · k)

Correct, but each word may be checked against every group. With 10⁴ words and no anagrams it took about 9 minutes in Python here (about 2 in Java): far over the time limit.

Approach 2: Sorted Word as the Key

Instead of comparing words with each other, give each word a label that all its anagrams share. Sorting the letters does that: "eat", "tea" and "ate" all become "aet". A hash map from label to group finds the right group in one lookup.

  • Python dict.setdefault, C++ map[key].push_back, Java computeIfAbsent.
Time O(n · k log k) Space O(n · k)

The one most people write first, and plenty fast: 0.07 s in Python here for 10⁴ words of 100 letters.

Approach 3: Letter Counts as the Key Optimal

With only 26 letters, the key can be "how many of each": one pass over the word instead of a sort. Two words are anagrams exactly when all 26 counts are equal.

  • Python: a tuple of the 26 counts (lists can't be dict keys).
  • Java: a 26-character string where each char is a count (at most 100, so it fits).
  • C++: the counts joined with a separator ("1#0#…"), so 1, 11 and 11, 1 stay different.
Time O(n · k) Space O(n · k)

Linear in the total number of letters. In practice the gap to Approach 2 is small for short words (0.05 s vs 0.07 s here); it grows with longer words.

In practice Built-ins

Java's Collectors.groupingBy builds the map from key to list for you. Python's itertools.groupby also works, but only groups neighbouring items, so the words must be sorted by key first. C++ has no grouping helper; the map of Approach 2 is the idiomatic way.

Time O(n · k log k), plus O(n log n) for Python's sort Space O(n · k)

Both pass. Forgetting the sort before groupby splits a group wherever another word sits between its members.
