704. Binary Search Easy Binary Search Array
Key idea: Keep lo and hi so that target, if it's there, is always in nums[lo..hi]. Look at the middle: too small means drop it and everything to its left (lo = mid + 1); too big means drop it and everything to its right (hi = mid − 1). Loop while lo <= hi. O(log n).

Problem View on LeetCode (opens in a new tab) ↗

nums is sorted in ascending order with no repeats. Return the index of target, or -1 if it isn't there. It must run in O(log n).

  • 1 <= nums.length <= 10⁴, values in (-10⁴, 10⁴)

Example: [-1,0,3,5,9,12], target = 9 → 4. Same array, target = 2 → -1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[5], target = 5 0 Looping while lo < hi skips the last remaining value: it said -1. Wrong on 1022 of 3008 tests.
[5], target = -5 -1 Setting hi = mid (not mid − 1) with lo <= hi never shrinks a 1-value range: it looped forever. Hit on 873 tests.
[2,5], target = 9 -1 Bigger than everything: lo walks off the right end and the loop stops.

Approach 1: Linear Scan

Check every value from the left. It ignores that the array is sorted, and doesn't meet the O(log n) rule.

Time O(n) Space O(1)

10⁴ values, target at the end: Python 233 µs, Java 22 µs, C++ 3.5 µs, about 100 times slower than binary search in Python.

Approach 2: Recursive Binary Search

find(lo, hi) compares target with nums[mid] and calls itself on the half that can still hold it. An empty range (lo > hi) means not found.

  • Clear to read; the calls are only about log₂ n = 14 deep for 10⁴ values.
  • mid = lo + (hi − lo) / 2 in C++ and Java avoids overflowing lo + hi on huge arrays.
Time O(log n) Space O(log n) call stack

10⁴ values, target at the end: Python 4.0 µs, Java 0.2 µs, C++ under 0.1 µs.

Approach 3: Iterative Binary Search Optimal

The same search as a loop: while lo <= hi, compare with the middle, then move lo or hi past it.

  • Every step drops mid itself, so the range always shrinks and the loop always ends.
Time O(log n) Space O(1)

10⁴ values, target at the end: Python 1.8 µs, Java 0.3 µs, C++ 0.3 µs. Too fast to tell apart from Approach 2 in C++ and Java.

In practice Built-ins

Python's bisect.bisect_left and C++'s std::lower_bound give the first index with a value ≥ target; check that it's equal. Java's Arrays.binarySearch returns a negative number when the value is missing.

Time O(log n) Space O(1)

Should pass on LeetCode. In Python, bisect took 1.5 µs, a little faster than the loop. Java's negative result encodes where the value would go, so turn it into −1.
