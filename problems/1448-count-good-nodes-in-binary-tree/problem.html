1448. Count Good Nodes in Binary Tree Medium Tree DFS BFS
Key idea: Walk down from the root carrying the largest value seen on the path so far. A node is good when node.val >= best; then pass max(best, node.val) to its children. Each path has its own maximum, so it's a parameter, not a global. O(n) time, O(h) space.

Problem View on LeetCode (opens in a new tab) ↗

Given the root of a binary tree, a node X is good if no node on the path from the root to X has a value greater than X. Return the number of good nodes.

  • The number of nodes is between 1 and 10⁵.
  • Each value is between -10⁴ and 10⁴.

Examples (level order, null = no child): [3, 1, 4, 3, null, 1, 5] → 4 (3, 4, 5 and the lower 3); [3, 3, null, 4, 2] → 3; [1] → 1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1] 1 One node: the root is always good.
[3, 3, null, 4, 2] 3 Equal counts as good: the second 3 is good. Use >=, not >.
[2, 2, 2, 2, 2] 5 All equal: every node is good.
[5, 1, null, 3] 1 3 is bigger than its parent 1, but not than 5 at the top. Compare with the largest value on the whole path, not just the parent.
[2, null, 4, 10, 8, null, null, 4] 4 Each path has its own maximum: 8 is good even though its sibling 10 is bigger. A single global maximum gets this wrong.
[-3, -2, -1] 3 Negative values: start best at root.val (or −∞). Starting at 0 counts nothing here.
[5, 4, null, 3, null, 2, null, 1] 1 A one-sided chain that only decreases: only the root is good.
[-10⁴, 10⁴, -10⁴] 3 Both limits: the root −10⁴ is good, and each child is ≥ it.
A chain 0 → 1 → … → 99999, each a left child 100000 10⁵ levels deep: recursion goes past Python's default limit of 1,000, and overflowed Java's default stack here. Raise the limit, or use a stack or queue.

Approach 1: Recursive DFS

The only thing a node needs from above is the largest value on its path. Pass it down as a parameter: each call checks its own node, then hands max(best, node.val) to both children.

  • dfs(node, best) returns the number of good nodes in that subtree: 1 if node.val >= best, plus the counts from the left and right subtrees.
  • Starting with best = root.val makes the root good and handles negative values. A starting value of 0 would not.
Time O(n) Space O(h)

h is the tree's height: about log n when balanced, up to n = 10⁵ when it's a single chain. Python raises its recursion limit here (default 1,000); with that, a 10⁵-deep chain passed in testing. C++ handled it too with a normal build. Java's recursive version threw StackOverflowError on that chain with the default JVM stack on this machine. LeetCode's JVM settings may differ, but Approach 2 avoids the question.

Approach 2: Iterative DFS with a Stack

The same walk, with your own stack instead of the call stack. Each entry is a pair: a node and the largest value above it. That pair is exactly what the recursive call had in its parameters.

  • Pop a pair, count the node if it's good, then push its children with max(best, node.val).
  • Pushing right before left makes left come out first, the same order as the recursion. For counting, any order works.
Time O(n) Space O(h)

The stack lives on the heap, so a 10⁵-deep tree is fine in every language. In Java, two stacks kept in step avoid creating a pair object per node.

Approach 3: BFS with a Queue

Visit level by level with a queue of (node, largest value above it). Because every entry carries its own path's maximum, it doesn't matter that nodes from different branches are mixed together.

  • Same check and same max(best, node.val) for the children; only the order of visits changes.
  • The queue holds about one level at a time, so memory follows the tree's width instead of its height.
Time O(n) Space O(w)

w is the widest level: up to about n / 2 for a full tree, 1 for a chain. Choose BFS when the tree is likely deep and narrow, DFS when it's wide and shallow; for this problem both pass easily.

In practice No shortcut

None of the standard libraries have a binary tree type with a traversal built in, and LeetCode's TreeNode is a bare class. A traversal is the shortest correct answer.

Approach 1 is the one to write: about six lines and the clearest. If the tree can be very deep (or in Java), use Approach 2.

Comparison

Approach Technique Time Space Notes
Recursive DFS Pass the path maximum down as a parameter O(n) O(h) Shortest; deep trees can overflow the call stack
Iterative DFS with a Stack Stack of (node, max above it) O(n) O(h) Safe for 10⁵-deep trees in any language
BFS with a Queue Queue of (node, max above it), level by level O(n) O(w) Memory follows the width, not the height
