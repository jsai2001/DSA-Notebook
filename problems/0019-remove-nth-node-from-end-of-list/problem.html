19. Remove Nth Node From End of List Medium Linked List Two Pointers
Key idea: Put a dummy node in front of the head, start fast and slow on it, and move fast n + 1 steps ahead. Then move both until fast is null: slow is now just before the node to remove, so slow.next = slow.next.next. Return dummy.next. One pass, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given the head of a linked list, remove the n-th node from the end and return the head.

  • The list has between 1 and 30 nodes.
  • 0 <= Node.val <= 100 and 1 <= n <= length.
  • Follow-up: can you do it in one pass?

Examples: [1,2,3,4,5], n = 2 → [1,2,3,5]; [1], n = 1 → []; [1,2], n = 1 → [1].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1], n = 1 [] The only node goes: return null / None, not the old head.
[1,2], n = 2 [2] Removing the head: there's no node before it to update. A dummy node in front handles this without a special case.
[1,2,3,4,5], n = 5 [2,3,4,5] n equals the length: also the head. Without a dummy, moving fast n + 1 steps runs past the end.
[1,2], n = 1 [1] Removing the tail: the new last node must point to null.
[1,2,3,4,5], n = 2 [1,2,3,5] The usual case: off-by-one errors land on 3 or 5 instead of 4.
[1,1,1], n = 2 [1,1] Remove by position, not by value: comparing values can't tell these nodes apart.
30 nodes, n = 30 or n = 1 29 nodes The extremes at the largest size: the head and the tail.

Approach 1: Count the Length, Then Walk

The n-th from the end is the (length - n + 1)-th from the start. Count the nodes in a first pass, then walk to the node just before it and skip over it.

  • Start prev on a dummy node in front of the head and move it length - n times. When the target is the head, that's 0 moves and prev is the dummy.
  • prev.next = prev.next.next removes it; return dummy.next, which is the new head.
Time O(L) Space O(1)

Two passes over the list. Perfectly good, but the follow-up asks for one. In C++ the removed node is deleted; Java and Python free it automatically.

Approach 2: Stack

Push every node (dummy first) onto a stack. The nodes come back off in reverse, so after n pops the top of the stack is the node just before the target.

  • Pushing the dummy means there's always a node left on top, even when the head is removed.
  • It reads the list once, but stores all of it.
Time O(L) Space O(L)

A natural way to "count from the end", but the extra O(L) memory is what the two-pointer trick avoids.

Approach 3: Two Pointers, One Pass Optimal

Keep a fixed gap. If fast is n + 1 nodes ahead of slow, then when fast falls off the end, slow is exactly one node before the n-th from the end.

  • Both start on the dummy. Move fast n + 1 times, then move both until fast is null.
  • Why n + 1, not n: you want to stop before the target so you can change its predecessor's next.
  • Starting from the dummy keeps n = length safe: fast lands exactly on null and slow stays on the dummy.
Time O(L) Space O(1)

One pass and no extra memory: the answer to the follow-up. The same fixed-gap idea finds the middle of a list (fast moves 2, slow moves 1) and the k-th from the end.

In practice No shortcut

LeetCode's ListNode is a bare class, so the standard library can't help. Copying the values into an array and rebuilding the list works, but it's slower, uses O(L) memory, and makes new nodes instead of removing one.

Write Approach 3. The dummy node is worth remembering on its own: it removes the "what if it's the head?" case from most linked-list problems.
