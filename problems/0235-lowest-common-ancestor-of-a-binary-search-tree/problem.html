235. Lowest Common Ancestor of a Binary Search Tree Medium Binary Search Tree Tree
Key idea: In a BST, values tell you which way a node is. Walk down from the root: if p and q are both smaller, go left; if both bigger, go right. The first node where they're not on the same side (or that is one of them) is the answer. O(h) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given a BST and two of its nodes p and q, return their lowest common ancestor: the deepest node that has both below it. A node counts as its own ancestor.

  • 2 <= n <= 10⁵; all values are different
  • p != q, and both are in the tree

Example: [6,2,8,0,4,7,9,null,null,3,5], p = 2, q = 8 → 6. Same tree, p = 2, q = 4 → 2. [2,1], p = 2, q = 1 → 2.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2,1], p = 2, q = 1 2 p is the ancestor of q. Stopping only when p < node < q (strictly) walked past it and returned nothing; wrong on 1915 of 3003 tests.
p = 2, q = 4 in the example tree 2 The same: the answer is p itself.
10⁵ nodes in one chain, the two deepest the second deepest h = n: walking down takes 10⁵ steps. A recursive walk would also go 10⁵ calls deep.

Approach 1: Parent Pointers (Any Binary Tree)

Walk the whole tree and record each node's parent. Put p and all its ancestors in a set. Climb from q until you reach a node in that set.

  • Doesn't use the BST order, so it works on any binary tree.
  • Visits all n nodes even when the answer is the root.
Time O(n) Space O(n)

10⁵ random values: Python 18 ms, Java 20 ms, C++ 7.3 ms, about 700 times slower than Approach 3 in Python.

Approach 2: Compare the Two Search Paths

Search for p from the root (smaller left, bigger right) and keep the path. Do the same for q. Both paths start the same way; the last node they share is the answer.

  • Uses the BST order: only two root-to-node paths are walked.
  • Keeps both paths, O(h) memory.
Time O(h) Space O(h)

A 10⁵-node chain: Python 13.5 ms, Java 3.0 ms, C++ 1.2 ms. On the random tree (h about 40): Python 26 µs.

Approach 3: Walk Down to the Split Point Optimal

Start at the root. If both values are smaller than the node, go left; if both are bigger, go right. Otherwise this node is between them, or is one of them: return it.

  • One walk, no lists, no recursion.
  • Everything below the split point is on one side of it, so nothing deeper can hold both.
Time O(h) Space O(1)

A 10⁵-node chain: Python 5.5 ms, Java 0.23 ms, C++ 0.13 ms, the fastest in every language.

In practice No shortcut

No library works on LeetCode's TreeNode. Approach 3 is a few lines and is what you'd write.
