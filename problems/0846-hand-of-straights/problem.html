846. Hand of Straights Medium Greedy Hash Map Sorting
Key idea: The smallest card left has nothing smaller to go before it, so it must start a group. Count the cards and go through the different cards in sorted order: if x has c copies left, start c groups at once and take c of each card from x to x + groupSize − 1. O(n log n).

Problem View on LeetCode (opens in a new tab) ↗

Can the cards in hand be split into groups of groupSize cards, each group being consecutive numbers?

  • 1 <= hand.length <= 10⁴, 0 <= hand[i] <= 10⁹, 1 <= groupSize <= hand.length
  • Same problem as 1296. Divide Array in Sets of K Consecutive Numbers.

Example: hand = [1,2,3,6,2,3,4,7,8], groupSize = 3 → true ([1,2,3], [2,3,4], [6,7,8]). hand = [1,2,3,4,5], groupSize = 4 → false.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
hand = [8,7], groupSize = 2 true Go through the cards in sorted order. Going in hash map order started a group at 8 and gave false; that bug was wrong on 1,009 of 3,009 tests.
hand = [1,2,3,4,5], groupSize = 4 false 5 cards don't split into groups of 4. Check n % groupSize first.
hand = [1,1,2,2,3,3], groupSize = 3 true Two copies of 1 start two groups at once.

Approach 1: Sort and Remove

Sort the cards. Take the smallest card left, then find and remove start, start + 1, … from the list. If one is missing, it's impossible.

  • Correct, but every search and removal in a list is O(n).
Time O(n²) Space O(n)

10⁴ cards in groups of 100: Python 425 ms, Java 26 ms, C++ 9.2 ms.

Approach 2: Count + Min-Heap

Count each card and put the different cards in a min-heap. The heap top starts the next group; take one of each card in the run. When a card runs out, it must be the heap top, so pop it. If a smaller card is still left, it can't be finished, so stop early.

  • One group at a time, one card at a time.
Time O(n log n) Space O(n)

10⁴ cards in groups of 100, average of 40 runs: Python 1.4 ms, Java 0.24 ms, C++ 0.065 ms. 5,000 pairs spread far apart: Python 5.3 ms, Java 1.6 ms, C++ 0.95 ms.

Approach 3: Count + Sorted Cards, Whole Batches Optimal

Count each card and sort the different cards. Walk them smallest first. If x still has c copies, all of them must start groups, so take c of each card from x to x + groupSize − 1. If any has fewer than c, it's impossible.

  • No heap: a card with 0 copies left is just skipped.
  • Use a hash map plus one sort of the keys. A sorted map (std::map, TreeMap) also works, but was 1.8 to 5.8 times slower here.
Time O(n log n) Space O(n)

Groups of 100: Python 0.53 ms, Java 0.15 ms, C++ 0.042 ms. Spread pairs: Python 3.1 ms, Java 0.98 ms, C++ 0.83 ms. The fastest in every language on both.

In practice No shortcut

Nothing built in. Approach 3, with Counter in Python.
