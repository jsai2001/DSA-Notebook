494. Target Sum Medium Dynamic Programming Knapsack
Key idea: Split the numbers into a plus part P and a minus part N. P − N = target and P + N = sum, so P = (sum + target) / 2. The answer is the number of subsets that add up to P: a counting 0/1 knapsack, dp[s] += dp[s − x] going down. O(n · sum).

Problem View on LeetCode (opens in a new tab) ↗

Put + or - before every number in nums. How many ways give a total of target?

  • 1 <= nums.length <= 20, 0 <= nums[i] <= 1000, sum(nums) <= 1000, -1000 <= target <= 1000

Example: nums = [1,1,1,1,1], target = 3 → 5. nums = [1], target = 1 → 1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
nums = [100], target = -200 0 P = -50. Without the |target| > sum check, Python's dp[-50] raised an IndexError, and other negative Ps silently read from the end of the list. Wrong or crashed on 44 of 3,009 tests.
nums = [0,0,0], target = 0 8 +0 and -0 count as different choices. The downward loop includes s = x = 0, which doubles every count.
nums = [1,2], target = -1 1 A negative target is fine: P = 1.

Approach 1: Try Every Sign

Recurse: give the next number a +, then a -, and count the totals that hit target.

  • n ≤ 20, so 2²⁰ ≈ 10⁶ choices: slow but it passes.
Time O(2ⁿ) Space O(n) call stack

20 numbers: Python 0.19 to 0.23 s, Java 2.2 to 2.8 ms, C++ 2.6 ms, whatever the values.

Approach 2: Count Ways per Running Total

Keep how many sign choices reach each running total. Each number sends every total t to t + x and t − x, carrying its count.

  • Totals stay between −sum and sum, so there are at most 2·sum + 1 of them.
  • C++ and Java use an array shifted by 1000 instead of a hash map.
Time O(n · sum) Space O(sum)

20 random numbers up to 100: Python 1.4 ms, Java 0.033 ms, C++ 0.027 ms. With twenty 50s there are only 21 different totals at the end: Python 0.047 ms, faster than Approach 3's 0.37 ms.

Approach 3: Subset-Count Knapsack Optimal

If |target| > sum or sum + target is odd, return 0. Otherwise count subsets adding up to P = (sum + target) / 2: dp[0] = 1, and for each x, dp[s] += dp[s − x] for s from P down to x.

  • The same loop as 416. Partition Equal Subset Sum, counting instead of yes/no.
  • The table has P + 1 <= sum + 1 slots, about half of Approach 2's.
Time O(n · sum) Space O(sum)

20 random numbers up to 100: Python 0.35 ms, Java 0.038 ms, C++ 0.0035 ms. Fastest in Python and C++ on random input.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write; Approach 2 if you don't spot the P trick.
