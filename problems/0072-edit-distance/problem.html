72. Edit Distance Hard String Dynamic Programming
Key idea: Let dp[i][j] be the edits to turn the first i letters of word1 into the first j of word2. Look at the last letters: if they match, dp[i][j] = dp[i−1][j−1]; otherwise it's 1 + min(replace dp[i−1][j−1], delete dp[i−1][j], insert dp[i][j−1]). The edges are dp[i][0] = i and dp[0][j] = j. O(m·n) time; one row is enough for O(min(m, n)) space.

Problem View on LeetCode (opens in a new tab) ↗

Given two strings word1 and word2, return the minimum number of operations to turn word1 into word2. Each operation is one of: insert a character, delete a character, or replace a character.

  • 0 <= word1.length, word2.length <= 500: either word can be empty.
  • Both are lowercase English letters.

Examples: "horse" → "ros" is 3 (replace h with r, delete r, delete e); "intention" → "execution" is 5.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"", "" 0 Both empty. The table is a single cell, dp[0][0] = 0.
"abc", "" 3 Delete everything. Leaving the first column at 0 (no dp[i][0] = i) gives 0 here, and 2 for "horse" → "ros".
"a", "a" 0 Matching letters cost nothing. Adding 1 even when they match gives 1 (and 5 for "horse" → "ros").
"a", "b" 1 One replace. Without replace (only insert and delete) it takes 2.
"ab", "ba" 2 There's no "swap" operation: two replaces (or delete + insert).
"intention", "execution" 5 Same length but not 9: "tion" lines up. Counting only inserts and deletes, m + n − 2·LCS, gives 8.
"aaaaaaaaaaa", "bbbbbbbbbbb" 11 Recursion without a memo tries three branches at every pair: 8.4 s in Python here for 11 letters each, about 5× slower per extra letter.

Approach 1: Recursion with Memo

dist(i, j) turns word1[i:] into word2[j:]. Look at the first letters left: if they match, keep them, dist(i + 1, j + 1). If not, do one edit and recurse: replace (i + 1, j + 1), delete (i + 1, j), or insert (i, j + 1), whichever is cheapest.

  • When word1 runs out, insert the rest of word2; when word2 runs out, delete the rest of word1.
  • There are only (m + 1)(n + 1) different (i, j), so the memo makes it polynomial.
Time O(m·n) Space O(m·n), plus O(m + n) call depth

The most natural way to find the recurrence. At the limits (500 × 500) it took 210 ms in Python here, about 5 times slower than the table, because of the calls and the dictionary.

Approach 2: The DP Table

The same recurrence, filled in row by row. dp[i][j] is for the first i letters of word1 and the first j of word2, so it only needs the cells above, to the left and above-left, which are already filled.

  • ↖ replace (or keep, if the letters match), ↑ delete word1's letter, ← insert word2's letter.
  • Fill the first row and column first: dp[0][j] = j, dp[i][0] = i.
  • Walking back from dp[m][n] along the choices gives the actual edits, not just their number.
Time O(m·n) Space O(m·n)

The standard answer (the Levenshtein distance). 45 ms in Python at the limits. Keep the full table if you need to print the edits.

Approach 3: One Row Optimal

Each row only uses the row above, so keep one array and overwrite it left to right. Before row[j] is overwritten it still holds the cell above; row[j − 1] already holds the new cell to the left. The above-left cell is gone by then, so save it in diag first.

  • At the start of each row: diag = row[0], then row[0] = i.
  • After each cell: diag = the old row[j], for the next cell.
  • Swap the words so the row runs over the shorter one: the distance is the same both ways.
Time O(m·n) Space O(min(m, n))

31 ms in Python at the limits, and far less memory. It gives the number only; you can't read the edits back from one row.

In practice No shortcut

None of the standard libraries has an edit distance function. Python's difflib compares sequences, but its similarity ratio isn't this distance. In real projects people use a library such as rapidfuzz (Python) or Apache Commons Text's LevenshteinDistance (Java), which aren't available on LeetCode.

Write Approach 2, then mention Approach 3. The two things people get wrong: the first row and column (i and j, not 0), and no +1 when the letters match.
