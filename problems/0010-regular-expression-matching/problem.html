10. Regular Expression Matching Hard String Dynamic Programming Recursion
Key idea: Match with two indexes, i in s and j in p. If p[j + 1] is *, there are two choices: use x* zero times (skip to j + 2), or, if x matches s[i], use one x and stay on x* (i + 1). Otherwise the characters must match and both move on. The same (i, j) comes up again and again, so memoize it or fill a table: O(m · n).

Problem View on LeetCode (opens in a new tab) ↗

Given a string s and a pattern p, return whether p matches all of s, where . matches any single character and * matches zero or more of the element right before it.

  • 1 <= s.length <= 20 and 1 <= p.length <= 20
  • s has only lowercase letters.
  • p has only lowercase letters, . and *.
  • Every * has a valid character right before it.

Examples: "aa", "a" → false (it must cover the whole string); "aa", "a*" → true; "ab", ".*" → true.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
s = "aa", p = "a" false A match must cover the whole string, not just the start.
s = "ab", p = ".*" true .* is "any character, any number of times", so the letters can differ.
s = "aab", p = "c*a*b" true c* is used zero times, at the very start.
s = "a", p = "ab*" true After s runs out, a leftover b* still matches (zero b's). Don't stop just because s is used up.
s = "aaa", p = "a*a" true a* must leave the last a for the final a. Taking as many as possible and never giving any back fails.
s = "aaa", p = "ab*a*c*a" true Several stars, some used zero times, in the middle of the pattern.
s = "ab", p = ".*c" false .* can't create the c the pattern needs at the end.
s = "a", p = ".*..a*" false The two plain dots need at least 2 characters.
s = "mississippi", p = "mis*is*p*." false p* can cover "pp", but nothing in the pattern covers the "i" that comes before it.
s = "bbbba", p = ".*a*a" true .* takes "bbbb", a* takes nothing, and the last a matches the last letter.
s = "aaaaaaaaaaaaaaaaaaab", p = "a*a*a*a*a*a*a*a*a*c" false The worst case for plain recursion: it tries every way to share the a's between the nine stars. It took 3.3 s in Python here, against 0.06 s in C++ and 0.04 s in Java; with a memo it's instant.

Approach 1: Plain Recursion

Ask "does s[i:] match p[j:]?" and answer it with smaller versions of the same question. The only hard part is *, which gives two choices, so try both.

  • Pattern used up: it's a match only if s is used up too.
  • first = s[i] exists and equals p[j] (or p[j] is .).
  • If p[j + 1] is *: skip x* (match(i, j + 2)), or use one x (first and match(i + 1, j)). Otherwise first and match(i + 1, j + 1).
Time exponential Space O(m + n)

Correct, but the same (i, j) is solved again every time a different mix of star choices reaches it. On the worst-case edge case above that's about 17 million calls for only 420 different (i, j) questions: 3.3 s in Python on this Mac, which risks a time-out. The recursion is at most m + n + 1 calls deep, so it never overflows.

Approach 2: Recursion with Memo

The same recursion, but each answer is saved. There are only (m + 1) × (n + 1) different (i, j) questions, and each is worked out once.

  • Check the memo first; store the answer before returning.
  • The code reads the same as Approach 1, so it's the easiest step up in an interview.
Time O(m · n) Space O(m · n)

At most 21 × 21 = 441 states, each O(1). The worst case that took 3.3 s before now finishes in well under a millisecond.

Approach 3: Bottom-Up DP Table Optimal

Fill a table from small prefixes to big ones. dp[i][j] says whether the first i characters of s match the first j of p.

  • dp[0][0] = true. Row 0 (empty s): dp[0][j] = dp[0][j - 2] when p[j - 1] is *, so patterns like a*b* match "".
  • p[j - 1] is * on x: dp[i][j] = dp[i][j - 2] (zero x's) or (x matches s[i - 1] and dp[i - 1][j]) (one more x).
  • Otherwise: p[j - 1] matches s[i - 1] and dp[i - 1][j - 1].
Time O(m · n) Space O(m · n)

No recursion, and every cell only looks at the current and previous row, so it can be cut to two rows (O(n) space) if needed. Same speed as Approach 2; this is the version most write-ups show.

In practice Built-ins

. and * mean the same thing in real regular expressions, so the standard library can do it in one line: Python's re (anchored with \Z, like re.fullmatch), C++'s std::regex_match, and Java's String.matches. All three require the whole string to match.

Time depends on the engine Space depends on the engine

All three gave the right answer on every test here, with one exception: on the worst-case edge case, C++'s std::regex_match (Apple's library on this Mac) threw regex_error because the match took too many steps. LeetCode's C++ library is different and wasn't tested. Python and Java finished it in 0.04 s. These engines backtrack, so long inputs can get slow. In an interview, the point is to write Approach 2 or 3 yourself.
