134. Gas Station Medium Array Greedy
Key idea: Drive once around from station 0, keeping a tank. If the tank goes negative at station i, no station from the current start up to i can be the answer, so restart at i + 1 with an empty tank. At the end, if total gas ≥ total cost, the last start is the answer; otherwise there is none. O(n), O(1).

Problem View on LeetCode (opens in a new tab) ↗

n stations sit on a circle. At station i you can fill up gas[i], and driving on to station i + 1 costs cost[i]. Starting with an empty tank, return the station where you can start and drive once all the way around, or -1 if no station works. If an answer exists, it's unique.

  • 1 <= n <= 10⁵
  • 0 <= gas[i], cost[i] <= 10⁴

Example: gas = [1,2,3,4,5], cost = [3,4,5,1,2] → 3. gas = [2,3,4], cost = [3,4,3] → -1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
gas = [2,3,4], cost = [3,4,3] -1 Not enough gas overall (9 vs 10). Skipping the total check returned 2.
gas = [1,2,3,4,5], cost = [3,4,5,1,2] 3 Restart at i + 1, not i: station i is where it failed. Restarting at i returned 2.
gas = [0], cost = [0] 0 A tank of exactly 0 is fine. Resetting on tank <= 0 returned 1, which isn't even a station.
gas = [5], cost = [4] 0 One station: the trip is one leg back to itself.
gas = [3,1,1], cost = [1,2,2] 0 The answer is the very first station.
10⁵ stations: gas all 1, cost all 1 except the last, 2 -1 Every start fails only at the last station. Trying every start drives about 5 × 10⁹ legs: 3.3 s in C++ here.

Approach 1: Try Every Start

For each start, drive around the circle, adding gas[i] - cost[i] at each station. Stop as soon as the tank goes negative and try the next start. The first start that finishes all n legs is the answer.

  • Use (start + k) % n to wrap around the circle.
  • Clearly right, and easy to explain first.
Time O(n²) Space O(1)

On the worst case (every start fails at the last station), the time quadruples each time n doubles. Python: 0.13 s at 2,000, 0.53 s at 4,000, 2.2 s at 8,000. At n = 10⁵: C++ 3.3 s, Java 4.7 s. Too slow.

Approach 2: One Pass, Restart After Each Failure Optimal

Drive from station 0. When the tank goes negative at i, set start = i + 1 and empty the tank. Also keep total, the sum over every station. If total >= 0, return start; else -1.

  • Why skip everything up to i: we reached every station between start and i with a tank ≥ 0. Starting at one of them means arriving at i with that gas missing, so it fails at i too.
  • Why total >= 0 is enough: the gas lost before the final start is made up by the stretch after it, so the trip around from start never runs dry.
  • Sums stay within ±10⁹ (10⁵ stations × 10⁴), which fits in a 32-bit int.
Time O(n) Space O(1)

At n = 10⁵ here: Python 5–8 ms, Java 2–2.5 ms, C++ 0.1 ms. The expected answer; be ready to explain both "why" points above.

Approach 3: Start After the Lowest Point

Track run, the gas left after each station if we started at 0 with an unlimited tank. The best start is right after the station where run is lowest: from there, every later point of the trip is at least as high, so the tank never drops below what it started with.

  • The same answer as Approach 2, seen as a graph of run: Approach 2's restarts happen exactly at new lowest points.
  • Start with low = 0 at position −1, so "never below 0" gives start 0.
Time O(n) Space O(1)

Same speed as Approach 2: Python 4–5 ms, Java ~2 ms, C++ under 0.1 ms at n = 10⁵. A good way to explain why the greedy works.

In practice No shortcut

No standard library function finds the start. Python's itertools.accumulate can build the run list from Approach 3, but it stores all n values where a loop needs one variable.

Approach 2 is what you'd write: one loop, three variables.
