787. Cheapest Flights Within K Stops Medium Graph Shortest Path Dynamic Programming
Key idea: "At most k stops" means at most k + 1 flights. Run Bellman-Ford for k + 1 rounds, and in each round read only the previous round's prices (work on a copy). Then round r can only add one flight to a route, so after k + 1 rounds you have the cheapest route with at most k + 1 flights. O(k·E).

Problem View on LeetCode (opens in a new tab) ↗

flights[i] = [from, to, price] between cities 0..n−1. Return the cheapest price from src to dst with at most k stops in between, or -1 if there's no such route.

  • 1 <= n <= 100, 0 <= k < n, prices 1 to 10⁴
  • No repeated flights; src != dst

Example: n = 4, [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1 → 700 (0→1→3; the cheaper 0→1→2→3 needs 2 stops).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[1,0,48],[0,2,9]], src = 1, dst = 2, k = 0 -1 Bellman-Ford without the copy uses prices set earlier in the same round, chaining two flights: it said 57. Wrong on 33 of 2005 tests.
[[0,1,1],[0,2,5],[1,2,1],[2,3,1]], src = 0, dst = 3, k = 1 6 Plain Dijkstra marks city 2 done via the cheap 0→1→2, then can't reach 3 in time: it said -1. The pricier 0→2→3 is the answer.
n = 2, flights = [] -1 No flights at all.

Approach 1: BFS by Number of Flights

Level by level: each level takes one more flight from every city in the queue. A route only continues when it reaches a city more cheaply than any route found so far. Stop after k + 1 levels.

  • Levels count the flights, so the k limit is easy to enforce.
  • The pruning keeps the queue small on most inputs.
Time usually near O(k·E); a city can be queued more than once per level Space O(n + E)

100 cities, 4950 flights, k = 99: Python 1.6 ms, Java 0.57 ms, C++ 0.08 ms.

Approach 2: Dijkstra With a Flight Count

The heap holds (price, city, flights used). Pop the cheapest; reaching dst means done. A pop is useless if a cheaper route already got to that city with no more flights, so keep fewest[city] and skip those.

  • Plain Dijkstra (each city done once) is wrong here: a pricier route with fewer flights may be the only one that fits.
Time O(k·E log(k·E)) at worst Space O(k·E)

Same graph: Python 0.91 ms (the fastest in Python), Java 0.40 ms, C++ 0.10 ms.

Approach 3: Bellman-Ford, k + 1 Rounds Optimal

Start with price[src] = 0. Each round, copy the prices, try every flight using the old prices, and write into the copy. After round r, price[v] is the cheapest route to v with at most r flights. If a round changes nothing, stop early.

  • The copy is the whole trick: without it, one round can chain several flights.
  • A firm O(k·E) bound, and no heap.
Time O(k·E) Space O(n)

Same graph: Java 0.20 ms, C++ 0.06 ms, the fastest in both. Python 2.4 ms. Before adding the early stop, Python took 20 ms here.

In practice No shortcut

Shortest-path libraries don't limit the number of edges. Approach 3 is what you'd write.
