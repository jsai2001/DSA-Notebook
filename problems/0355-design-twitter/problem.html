355. Design Twitter Medium Heap Design Hash Map
Key idea: Keep each user's tweets in posting order with a time stamp. A feed is "merge k sorted lists", stopped after 10: put each followed user's newest tweet in a max-heap, pop the newest, and push that user's next older tweet. O(F + 10 log F) per feed.

Problem View on LeetCode (opens in a new tab) ↗

Build a Twitter class:

  • postTweet(userId, tweetId): the user posts a new tweet. Tweet ids are unique.
  • getNewsFeed(userId): the 10 most recent tweet ids posted by the user or anyone they follow, newest first.
  • follow(followerId, followeeId) and unfollow(followerId, followeeId).
  • 1 <= userId <= 500, 0 <= tweetId <= 10⁴, at most 3·10⁴ calls in all.

Example: post(1, 5), feed(1) → [5], follow(1, 2), post(2, 6), feed(1) → [6, 5], unfollow(1, 2), feed(1) → [5].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
post(2, 1), feed(2) [1] The feed includes your own tweets. Reading only the users you follow was wrong on 1,137 of 1,504 tests.
unfollow(1, 2) before any follow nothing happens Python's set.remove raises a KeyError here; use discard. With remove, 1,175 of 1,504 tests crashed.
12 posts by user 1, then feed(1) the last 10, newest first Stop at 10.

Approach 1: One Global List

Append every (user, tweet) to one list. For a feed, walk it from the newest end and keep tweets by the user or anyone they follow, stopping at 10.

  • No clock needed: the list order is the time order.
  • Fast when the newest tweets are the ones you want. Slow for a user whose tweets are old: the scan passes everyone else's.
Time post O(1), feed O(T) for T tweets Space O(T + follows)

15,000 feeds for a user whose one tweet is behind 15,000 others': Python 8.2 s, Java 0.53 s, C++ 0.11 s. 3·10⁴ random calls over 500 users: Python 260 ms, 6 times Approach 3.

Approach 2: Gather and Sort

Keep tweets per user, each with a time stamp. For a feed, take the last 10 tweets of the user and of each followed user (older ones can never make the top 10), sort them newest first, and keep 10.

  • The "last 10" cut keeps a feed from depending on how much anyone has posted.
Time post O(1), feed O(10F log(10F)) for F followed users Space O(T + follows)

A user following 499 busy users, 14,500 feeds: Python 14.4 s, Java 4.7 s, C++ 1.8 s, the slowest here. It sorts about 5,000 tweets for every feed.

Approach 3: Merge With a Heap Optimal

Each user's tweets are already sorted by time. Put every followed user's newest tweet in a max-heap by time. Pop the newest into the feed and push that user's next older tweet. Stop after 10 pops.

  • The same merge as 23. Merge k Sorted Lists, cut off at 10.
Time post O(1), feed O(F + 10 log F) Space O(T + follows)

3·10⁴ random calls: Python 41 ms, Java 18 ms, C++ 5.5 ms, the fastest in every language. Following 499 users: Python 1.6 s, Java 0.31 s, C++ 0.061 s, 9 to 30 times faster than Approach 2. Approach 1 was faster still there (C++ 2.3 ms) because the newest 10 tweets were all in the feed.

In practice No shortcut

Nothing built in. Python's heapq.merge could replace the hand-written merge in Approach 3. Real feed systems usually do the work when tweets are posted (fan-out on write) instead of on every read.
