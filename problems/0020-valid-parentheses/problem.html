20. Valid Parentheses Easy String Stack
Key idea: Use a stack of open brackets. Push every opener. For a closer, the stack must be non-empty and its top must be the matching opener; pop it. At the end the stack must be empty. The most recent open bracket is always the one that has to close next, and that's exactly what a stack's top gives you. O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given a string s of the characters ( ) [ ] { }, return whether it is valid: every open bracket is closed by the same type of bracket, brackets close in the right order, and every closing bracket has an open bracket before it.

  • 1 <= s.length <= 10⁴
  • s contains only ()[]{}.

Examples: "()[]{}" → true; "(]" → false; "([)]" → false; "{[]}" → true.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
")" false A closer with nothing open: check the stack is non-empty before looking at its top, or the code crashes.
"((" false Every character is fine on its own, but brackets are left open: check the stack is empty at the end.
"(]" false The right count, the wrong type.
"([)]" false Each type is balanced on its own, but they cross. Counting each type separately says true; only a stack catches the order.
"){" false Even length, but it starts with a closer.
"(()" false An odd length can never be valid: a quick early exit.
"{[()]}" true Nested three deep: each closer matches the most recent opener.
"()[]{}" true Side by side: the stack empties and refills.
5000 × ( then 5000 × ) true The longest input, nested as deep as it gets. Removing pairs one layer at a time needs 5000 passes.

Approach 1: Remove Matching Pairs Until Nothing Changes

In a valid string there's always a pair like (), [] or {} with nothing between, and removing it leaves a string that's still valid. So keep removing them: valid exactly when nothing is left.

  • Stop when a pass removes nothing, then check whether the string is empty.
  • Removing an inner pair brings its outer brackets together, so the next pass can remove those.
Time O(n²) Space O(n)

Each pass is O(n), and deep nesting needs up to n / 2 passes. It still passes at n = 10⁴: the deepest input took 0.15 s in Python here and about 0.1 s in C++ and Java, against 0.002 s for the stack. Short to write, and a nice way to see why the answer works.

Approach 2: Stack Optimal

Read left to right and keep the brackets that are still open. The one that must close next is always the most recent one, so a stack (last in, first out) is the right shape.

  • Opener: push it.
  • Closer: if the stack is empty, or its top isn't the matching opener, return false. Otherwise pop.
  • At the end, return whether the stack is empty. An odd length can return false straight away.
Time O(n) Space O(n)

One pass. The stack holds at most n / 2 openers on a valid string. The same "most recent unmatched thing" stack shows up in Min Stack (155), Daily Temperatures (739) and expression evaluation.

In practice No shortcut

A standard regular expression can't check nesting to any depth, and no standard library has a bracket checker. The stack is a few lines with list / std::stack / ArrayDeque, which is what you'd write.

In Java, prefer ArrayDeque over the old Stack class, which locks on every call.
