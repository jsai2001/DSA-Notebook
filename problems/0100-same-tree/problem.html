Key idea: Walk both trees together. At each spot: both missing is a match; only one missing, or different values, is a mismatch; otherwise compare the left children with each other and the right children with each other. O(n), and it stops at the first difference.

Problem View on LeetCode (opens in a new tab) ↗

Given the roots of two binary trees p and q, return true if they are the same: the same shape, with the same value at every node.

  • Each tree has 0 to 100 nodes (a tree can be empty).
  • -10⁴ <= Node.val <= 10⁴.

Examples: [1,2,3] and [1,2,3] → true; [1,2] and [1,null,2] → false; [1,2,1] and [1,1,2] → false.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[], [] true Two empty trees are the same. Reading p.val before checking for null crashes here.
[], [0] false Only one is empty. Treating a missing node like a node with value 0 says true.
[1,2], [1,null,2] false The same values, but 2 is on the left in one and on the right in the other. Comparing only the values in order (with no marks for missing children) says true.
[1,2,1], [1,1,2] false The children are swapped: the same set of values, not the same tree.
[12,3], [1,23] false When comparing as text, separate the values: without commas both become "123##…".
[1,1], [1,null,1] false Every value is 1: only the shape differs.
[1], [1] true One node each, with both children missing on both sides.

Approach 1: Write Both Trees as Text, Compare

Turn each tree into a string with a pre-order walk (node, left, right), writing # for every missing child. Two trees are the same exactly when their strings are equal.

  • The # marks are what record the shape; without them [1,2] and [1,null,2] look alike.
  • Put a separator between values, or 12, 3 and 1, 23 blur together.
Time O(n + m) Space O(n + m) for the two strings

Easy to trust, but it always writes out both whole trees, even when the roots already differ. 0.044 ms for two 100-node trees in Python.

Approach 2: Recursion on Both Trees Optimal

Compare the two roots, then ask the same question of the two left children and of the two right children.

  • Both null: true. Exactly one null: false. Different values: false.
  • Otherwise: same(p.left, q.left) and same(p.right, q.right). The and stops at the first false.
Time O(min(n, m)) Space O(h) call stack

Four lines, no extra memory, and it stops at the first difference: 0.019 ms in Python. The same check is the core of Subtree of Another Tree (572).

Approach 3: Queue of Pairs (BFS)

The same checks without recursion: keep a queue of node pairs that should match, starting with (p, q). Take a pair, check it, and add its two child pairs.

  • A pair of two nulls is fine: skip it.
  • In Java, ArrayDeque can't store null, so store each pair as a small array.
Time O(min(n, m)) Space O(width) for the queue

Compares the trees level by level (0.026 ms). Useful when trees can be very deep; here they have at most 100 nodes, so recursion is fine.

In practice No shortcut

LeetCode's TreeNode has no equality built in: in Python p == q only checks that they're the same object, in Java equals does the same, and in C++ p == q compares pointers.

Write Approach 2. Check the null cases before reading .val.
