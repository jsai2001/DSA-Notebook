33. Search in Rotated Sorted Array Medium Array Binary Search
Key idea: Cut the range at mid and one half is always sorted. If nums[lo] <= nums[mid] the left half is sorted, otherwise the right half is. A sorted half holds exactly the values between its two ends, so one comparison tells you whether the target can be in it: keep that half, or else the other. O(log n).

Problem View on LeetCode (opens in a new tab) ↗

An array sorted in ascending order with distinct values may have been rotated at an unknown index (for example, [0,1,2,4,5,6,7] becomes [4,5,6,7,0,1,2]). Given the array nums and a target, return the index of target, or -1 if it's not there.

  • 1 <= nums.length <= 5000 and -10⁴ <= nums[i], target <= 10⁴.
  • All values are different, and nums is a sorted array that may be rotated.
  • Your algorithm must run in O(log n) time.

Examples: [4,5,6,7,0,1,2], target 0 → 4; target 3 → -1; [1], target 0 → -1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1], target 1 / 0 0 / -1 One element: lo, mid and hi are all the same index.
[3,1], target 1 1 The classic trap: lo == mid. Testing "is the left half sorted?" with < instead of <= returns -1 here.
[1,3], target 3 1 Two elements, not rotated: the target is in the last cell.
[4,5,6,7,0,1,2], target 0 4 The target is the smallest value, right where the rotation starts.
[4,5,6,7,0,1,2], target 3 -1 Missing, but between the smallest and largest values: the search must still end cleanly.
[1,2,3,4,5], target 4 3 Not rotated at all: "may be rotated" includes zero. The code shouldn't assume a drop exists.
[5,1,2,3,4], target 5 0 The left part is a single value and holds the largest one.
[2,3,4,5,1], target 1 4 The rotation point is the very last index.
[4,5,1,2,3], target 6 / 0 -1 / -1 Larger than everything / smaller than everything.

Approach 1: Linear Scan

Look at every value until you find the target.

  • Always correct, rotated or not.
  • It ignores that the array is sorted in two pieces.
Time O(n) Space O(1)

LeetCode would accept it (n ≤ 5000), but the problem asks for O(log n), so in an interview it doesn't count as a solution.

Approach 2: Find the Rotation Point, Then Binary Search

A rotated array is two sorted runs. Find where the second run starts (the smallest value), decide which run could hold the target, and do an ordinary binary search there.

  • Finding the smallest: if nums[mid] > nums[hi], the values drop after mid, so lo = mid + 1; otherwise mid..hi is sorted and hi = mid. (This is Find Minimum in Rotated Sorted Array, LeetCode 153.)
  • If nums[pivot] <= target <= nums[n - 1], search [pivot, n - 1]; otherwise search [0, pivot - 1].
Time O(log n) Space O(1)

Two simple binary searches, each easy to get right on its own. It also leaves you with the rotation point, which some follow-ups ask for.

Approach 3: One Binary Search, Pick the Sorted Half Optimal

No need to find the rotation point first. Whatever mid is, the drop is in at most one of the two halves, so the other half is sorted, and a sorted half tells you its range from its two ends.

  • nums[lo] <= nums[mid]: the left half is sorted. If nums[lo] <= target < nums[mid], go left; else go right.
  • Otherwise the right half is sorted. If nums[mid] < target <= nums[hi], go right; else go left.
  • The <= in nums[lo] <= nums[mid] matters: when lo == mid the "left half" is one cell, which is sorted. With <, it failed 76 of the test cases here, starting with [3,1], target 1.
Time O(log n) Space O(1)

One loop and the expected answer. At n = 5,000 it took at most 13 rounds. It relies on the values being distinct; with duplicates (Search in Rotated Sorted Array II, LeetCode 81) you can't always tell which half is sorted.

In practice Built-ins

There's no built-in search for a rotated array: nums.index, std::find and friends are O(n). But once you know where the rotation starts, each part is plainly sorted, so the library's binary search can do step 3 of Approach 2: bisect_left, std::lower_bound or Arrays.binarySearch with a start and end index.

Time O(log n) Space O(1)

Java's Arrays.binarySearch returns a negative number when the value is missing, not -1, so map it to -1 yourself. In an interview, write Approach 3.
