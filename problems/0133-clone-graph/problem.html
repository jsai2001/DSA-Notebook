133. Clone Graph Medium Hash Table DFS BFS
Key idea: Walk the graph (DFS or BFS) with a map from each original node to its copy. Put a node's copy in the map as soon as you make it, before visiting its neighbors. Then a cycle that comes back to it finds the copy instead of making another one. O(V + E).

Problem View on LeetCode (opens in a new tab) ↗

Given one node of a connected, undirected graph, return a deep copy: new nodes with the same values and the same edges, and no link back to any original node. Each node has a val and a list of neighbors.

  • 0 to 100 nodes; values are unique, from 1 to 100
  • No repeated edges and no self-loops; the graph is connected
  • The input is written as an adjacency list: list i holds the neighbors of node i + 1, and you're given node 1

Example: [[2,4],[1,3],[2,4],[1,3]] (a square: 1–2–3–4–1) → a copy of the same square. [[]] → one node with no neighbors. [] → null.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[] null No graph at all: the given node is null.
[[]] [[]] One node and no edges: still a new node, not the original.
[[2],[1]] [[2],[1]] The smallest cycle. Putting the copy in the map only after its neighbors are done loops forever: Python raised RecursionError here.
[[2,4],[1,3],[2,4],[1,3]] same square Copying a node but reusing its old neighbors list looks right, but the copy points at original nodes: not a deep copy.
100 nodes in a line same line A recursive DFS goes 100 calls deep: fine here, since the limit is only 100 nodes.
100 nodes, every pair joined same graph 4,950 edges, the most possible. Each edge is linked twice (once from each end).

Approach 1: DFS With a Map

clone(old) returns the copy of old. If it's in the map, return it. Otherwise make the copy, record it in the map, and set its neighbors to clone(nb) for each neighbor.

  • The map does two jobs: it stops the cycles, and it makes every edge point to the one copy of each node.
  • Order matters: record the copy before the loop over neighbors.
Time O(V + E) Space O(V) for the map and the call stack

Shortest to write. The call stack can be V deep, which is fine for 100 nodes. On a 100-node graph with every pair joined: Python 1.1 ms, Java 2.3 ms, C++ 0.15 ms.

Approach 2: BFS With a Map Optimal

Copy node 1 and queue it. Each time a node is taken from the queue, go through its neighbors: if a neighbor has no copy yet, make one and queue it. Either way, link the popped node's copy to the neighbor's copy.

  • Copy a node when it's first seen and link its edges when it's popped: every edge is linked exactly once from each end.
  • No recursion, so no depth limit, even on a long chain.
Time O(V + E) Space O(V)

On the 100-node complete graph: Python 0.5 ms, Java 3.9 ms, C++ 0.21 ms. The same speed as DFS in practice. Give either one in an interview; BFS is the safe choice when graphs can be deep.

Approach 3: Two Passes With Arrays

The values are unique and between 1 and 100, so they can be array indexes instead of hash map keys. First pass: find every node and store it at old[val]. Make one copy per node. Second pass: give each copy the copies of its neighbors, looked up by value.

  • Separating "make" from "link" removes the order question completely: every copy exists before any edge is linked.
  • Only works because of the value rules. With repeated or very large values, go back to a map keyed by node.
Time O(V + E) Space O(V), two arrays of 101

Fastest here, since there's no hashing: Python 0.45 ms, Java 2.0 ms, C++ 0.08 ms on the 100-node complete graph. A nice extra to mention; the map versions are what interviewers expect.

In practice Built-ins

Python's copy.deepcopy(node) copies a graph of objects, cycles included: it keeps its own memo map from old object to copy, the same idea as Approach 1. C++ and Java have no deep copy for object graphs.

Handy in everyday Python code, but it's the whole problem in one call, so an interviewer will ask you to write the map version. It's also recursive: it copied all 303 test graphs correctly here, and a 100-node chain is fine, but a 300-node chain raised RecursionError.
