543. Diameter of Binary Tree Easy Tree DFS
Key idea: Every path has one highest node where it bends: it goes down the left side and down the right side. So the longest path bending at a node has height(left) + height(right) edges. One post-order DFS returns each node's height to its parent and, on the way, keeps the largest left + right it sees. O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given the root of a binary tree, return the length of its diameter: the longest path between any two nodes. The length is the number of edges on the path, and the path may or may not pass through the root.

  • The tree has between 1 and 10⁴ nodes.
  • -100 <= Node.val <= 100.

Examples: [1,2,3,4,5] → 3 (4 – 2 – 1 – 3 or 5 – 2 – 1 – 3); [1,2] → 1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1] 0 One node, no edges. Counting nodes instead of edges gives 1.
[1,2] 1 The path ends at the root: one side has height 0.
[1,2,3,4,5] 3 The usual case: the path bends at the root.
[1,2,null,3,4,5,null,null,6] 4 The longest path (5 – 3 – 2 – 4 – 6) bends at 2 and skips the root. Only checking the root gives 3.
[1,2,null,3,null,4,null,5] 4 A chain: the path runs from the root straight down to the leaf.
[1,2,3,4,5,6,7] 4 A full tree: leaf to leaf through the root, 2 + 2 edges.
[-1,-2,-3] 2 The values don't matter, only the shape. Don't add up vals.
A chain of 10⁴ nodes 9999 The deepest tree: recursion goes 10⁴ calls deep (over Python's default limit of 1,000), and recomputing heights at every node gets slow.

Approach 1: Brute Force (Heights from Scratch at Every Node)

Try every node as the bend. For each one, compute the heights of its two subtrees with a separate height() function and add them. The answer is the largest sum, so also look inside the left and right subtrees.

  • height(node) = number of nodes on the longest path down (0 for an empty child).
  • A path bending at a node goes down height(left) edges on one side and height(right) on the other.
Time O(n²) worst case Space O(h) call stack

The same heights get worked out again and again. On a 10⁴-node chain it took 7.4 s in Python here (about 0.4 s in C++ and 0.3 s in Java); on a balanced tree it's only O(n log n).

Approach 2: One DFS That Returns Heights Optimal

A node's height needs its children's heights first, which is exactly what the bend check needs too. So do both in one post-order DFS: get left and right, update best with left + right, and return 1 + max(left, right).

  • The function returns a height but the answer is a path: keep the answer in a separate variable.
  • A path can't go down both sides of a node and then continue up, which is why the parent only gets max(left, right), not the sum.
Time O(n) Space O(h) call stack

Every node is visited once. The Python version raises the recursion limit, because a chain of 10⁴ nodes is 10⁴ calls deep. The same "return one thing, track another" DFS solves Binary Tree Maximum Path Sum and Balanced Binary Tree.

Approach 3: Iterative Post-Order with a Stack

The same post-order work without recursion. Each node goes on the stack twice: first to push its children, then (marked "back") to finish it once both children have heights.

  • Push (node, true), then the right child, then the left: the stack is last-in, first-out, so the left side runs first and the node finishes last.
  • A map holds each finished node's height, with an empty child counted as 0.
Time O(n) Space O(n)

No recursion limit to worry about, at the cost of a height map for every node. Useful when a tree can be very deep.

In practice No shortcut

LeetCode's TreeNode is a bare class, so there's no library function for a tree's diameter. Graph libraries (like NetworkX's diameter) would need the tree turned into a graph first.

Write Approach 2. The pattern to remember: when the answer at a node combines both children but the parent only needs one of them, return one value and keep the answer in a variable.
