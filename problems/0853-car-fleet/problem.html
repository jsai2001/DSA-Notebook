853. Car Fleet Medium Stack Sorting
Key idea: Only cars ahead can slow a car down. Sort the cars closest to the target first and work out each one's arrival time alone. A car whose time is no later than the fleet ahead catches it and joins; a later time starts a new fleet. Keep the times on a stack, or just the slowest one. O(n log n) for the sort.

Problem View on LeetCode (opens in a new tab) ↗

n cars drive along one lane to target. Car i starts at position[i] with speed speed[i]. A car can't pass the one ahead: when it catches up, they drive on together at the slower speed as one fleet. Cars meeting exactly at the target count as one fleet. How many fleets arrive?

  • 1 <= n <= 10⁵, 0 < target <= 10⁶, 0 <= position[i] < target (all different), 0 < speed[i] <= 10⁶

Example: target = 12, position = [10,8,0,5,3], speed = [2,4,1,1,3] → 3. target = 100, position = [0,2,4], speed = [4,2,1] → 1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
target = 5, position = [2,0], speed = [6,10] 1 Both arrive at time 0.5: they meet at the target, so one fleet. Comparing with < instead of <= was wrong on 144 of 3,006 tests.
target = 10, position = [3], speed = [3] 1 One car is one fleet.
Equal times from different fractions, like 6/3 and 4/2 one fleet Floating-point division is rounded correctly, so equal fractions give exactly equal doubles. Checked against exact fractions on all 3,006 tests.

Approach 1: Check Every Car Ahead

A car is the front of a fleet when no car ahead of it arrives later or at the same time. For each car, check all the others.

  • No sorting. Slow when few cars merge: each one scans everything.
Time O(n²) Space O(n)

10⁴ cars that never merge: Python 3.4 s, Java 57 ms, C++ 41 ms. At LeetCode's 10⁵, O(n²) means about 100 times the work.

Approach 2: Sort + Stack

Sort closest to the target first. Push each car's time. If it's no later than the time below it, the car catches that fleet: pop it. The stack ends with one time per fleet.

  • The stack's times only go up from bottom to top.
Time O(n log n) Space O(n)

10⁵ random cars, average of 10 runs: Python 84 ms, Java 16 ms, C++ 4.8 ms. The sort is most of it.

Approach 3: Sort + Slowest Time Optimal

Approach 2 only ever compares with the top of the stack, so keep just that one number: the slowest arrival time so far. A car with a later time is a new fleet and becomes the new slowest.

  • No stack. Same sort.
Time O(n log n) Space O(n) for the sorted cars

Same input: Python 74 ms, Java 16 ms, C++ 4.8 ms. Faster than Approach 2 in Python; the same in Java and C++.

In practice No shortcut

Nothing built in beyond the sort. Approach 3 is what you'd write.
