143. Reorder List Medium Linked List Two Pointers Stack
Key idea: Three steps you already know: find the middle (slow and fast pointers), reverse the second half, then merge the two halves one node at a time. O(n) time, O(1) memory. Remember to cut the list after the middle, or it loops.

Problem View on LeetCode (opens in a new tab) ↗

Reorder the list L0 → L1 → … → Ln−1 → Ln into L0 → Ln → L1 → Ln−1 → L2 → Ln−2 → …, in place. You may only change the next links, not the values in the nodes.

  • 1 <= n <= 5 × 10⁴
  • 1 <= Node.val <= 1000

Example: [1,2,3,4] → [1,4,2,3]. [1,2,3,4,5] → [1,5,2,4,3].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1,2,3,4] [1,4,2,3] In the array version, the new last node still points to its old neighbor. Without the final cut, the list looped here: 1 → 4 → 2 → 3 → 4 → …
[1,2,3,4] [1,4,2,3] In the O(1) version, forgetting to cut after the middle made node 3 point to itself after the merge: another endless loop.
[1,2,3,4,5] [1,5,2,4,3] Odd length: the middle node ends up last.
[1] and [1,2] unchanged Nothing to move.
[7,7,7,7] [7,7,7,7] Looks unchanged, but the nodes must be in the new order. Swapping values instead of links isn't allowed.
5 × 10⁴ nodes reordered The largest input. Every approach here is O(n): about 3 ms in Python, under 0.3 ms in C++.

Approach 1: Nodes in an Array

Copy the nodes (not the values) into an array, so the back is easy to reach. Then with i at the front and j at the back, link nodes[i] → nodes[j] → nodes[i + 1], moving both inward until they meet.

  • Finish with nodes[i].next = None: the node that ends up last still points to its old neighbor.
  • The simplest to get right.
Time O(n) Space O(n)

At 5 × 10⁴ nodes here: Python 3.3 ms, Java 3.5 ms, C++ 0.26 ms. Fine in practice; the interviewer will ask for O(1) memory next.

Approach 2: Stack of Nodes

Push every node on a stack; the top is the tail. Walk from the head and, (n − 1) / 2 times, pop the top node and slip it in right after the current node. Then cut the link from the node now on top, which is the new tail.

  • Popping gives the back nodes in exactly the order they're needed.
  • Same memory as Approach 1, a different way to think about it.
Time O(n) Space O(n)

At 5 × 10⁴ nodes: Python 2.6 ms, Java 3.5 ms, C++ 0.31 ms.

Approach 3: Middle, Reverse, Merge Optimal

(1) Find the middle with slow and fast. (2) Cut after it and reverse the second half: 4 → 5 becomes 5 → 4. (3) Merge: take one node from the first half, then one from the reversed second half, until the second half runs out.

  • Stopping when fast.next.next is null puts the extra node of an odd list in the first half, so the second half is never longer.
  • Each step is a classic problem: Middle of the List (876), Reverse Linked List (206), Merge Two Sorted Lists (21).
Time O(n) Space O(1)

At 5 × 10⁴ nodes: Python 2.7 ms, Java 1.8 ms, C++ 0.13 ms, the fastest in C++ and Java. The expected answer.

In practice No shortcut

No standard library reorders a custom linked list. C++'s std::list has reverse and splice, but LeetCode passes its own ListNode, so they don't apply.

Approach 3 is what you'd write in an interview. In everyday code, Approach 1 is shorter and just as fast.
