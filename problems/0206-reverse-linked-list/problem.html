206. Reverse Linked List Easy Linked List Recursion
Key idea: Walk the list once with prev and cur. For each node: save cur.next, point cur.next back at prev, then step both forward. At the end prev is the new head. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Reverse a singly linked list and return the new head.

  • The number of nodes is in [0, 5000]
  • -5000 <= Node.val <= 5000

Example: [1,2,3,4,5] → [5,4,3,2,1]. [1,2] → [2,1]. [] → [].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1,2,3,4,5] [5,4,3,2,1] Setting cur.next = prev before saving cur.next loses the rest of the list: it returned [1].
[1,2,3,4,5] [5,4,3,2,1] The recursive version without head.next = None leaves 1 and 2 pointing at each other: the list read 5,4,3,2,1,2,1,2,… forever.
[] [] head is None: return it as is, don't read head.next.
5000 nodes reversed The recursion goes 5000 calls deep, past Python's default limit of 1000.

Approach 1: Copy the Values, Write Them Back

Walk the list and copy every value into an array. Walk it again and write the values back from the end of the array. The links never change; the values move.

  • Easy to get right, but it's not what "reverse the list" usually means: nodes keep their place.
  • Needs O(n) extra space for the values.
Time O(n) Space O(n)

At 5000 nodes: Python 0.45 ms, C++ 39 µs. Fine here, but an interviewer will ask you to move the links.

Approach 2: Recursion

Reverse everything after head first. Now head.next is the tail of that reversed part, so set head.next.next = head and head.next = None. The last node, found at the bottom, is passed back up as the new head.

  • Short, and a good way to think about lists recursively.
  • One call per node: Python needs sys.setrecursionlimit for 5000 nodes.
Time O(n) Space O(n) call stack

At 5000 nodes: Python 0.61 ms, C++ 64 µs, the slowest here because of the calls. Java handled 5000 deep without trouble.

Approach 3: Three Pointers Optimal

prev holds the reversed part, cur the rest. Each step: nxt = cur.next, cur.next = prev, prev = cur, cur = nxt. When cur is None, prev is the new head.

  • The order matters: save first, flip second, step last.
  • Empty and one-node lists need no special case.
Time O(n) Space O(1)

At 5000 nodes: Python 0.36 ms, C++ 8 µs, the fastest in both. Correct on all 3105 tests in every language.

In practice No shortcut

LeetCode's ListNode has no methods. With real lists you'd call list.reverse(), std::reverse or Collections.reverse; C++'s std::forward_list even has reverse(). Here, Approach 3 is what you'd write.
