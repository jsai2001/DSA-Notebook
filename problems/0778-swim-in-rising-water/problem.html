778. Swim in Rising Water Hard Matrix Heap (Priority Queue) Union Find
Key idea: The time a path needs is its highest cell, so you want the path whose highest cell is lowest. Since the heights are exactly 0..n²−1, let the water rise one unit at a time: at time t the cell of height t opens and joins its open neighbours (union-find). The first t at which the two corners are in one group is the answer. Dijkstra on "max so far" also works.

Problem View on LeetCode (opens in a new tab) ↗

grid[r][c] is a height. At time t the water is at height t, and you can swim between neighbouring cells (up, down, left, right) whose heights are both ≤ t, instantly. Starting at (0, 0), return the earliest time you can reach (n−1, n−1).

  • 1 <= n <= 50
  • The heights are 0 to n² − 1, each exactly once

Example: [[0,2],[1,3]] → 3. LeetCode's 5 × 5 spiral → 16.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[0,2],[1,3]] 3 A path's time is its highest cell, not the sum. Dijkstra that adds heights said 4; wrong on 1278 of 1504 tests.
[[1,2],[3,0]] 2 "The higher of the two corners" ignores the cells in between: it said 1. Wrong on 487 tests.
[[0]] 0 Start and end are the same cell.

Approach 1: Binary Search the Time + Flood

If you can make it by time t, you can make it by any later time. So binary search t: for each guess, flood from (0, 0) through cells ≤ t and check whether the far corner is reached.

  • A useful pattern: "is the answer at most t?" is easier than "what is the answer?".
  • Each guess floods the grid from scratch.
Time O(n² log n) Space O(n²)

A 50 × 50 snake (one long path): Python 16 ms, Java 1.1 ms, C++ 0.14 ms. The slowest in every language on that grid.

Approach 2: Dijkstra on the Highest Cell

A heap holds (time, r, c), where time is the highest cell on the way there. Always expand the soonest one; a neighbour's time is max(time, its height). The first time the far corner is popped, that's the answer.

  • Dijkstra works with max instead of +, because a path's time never goes down as it gets longer.
Time O(n² log n) Space O(n²)

A random 50 × 50 grid: Python 2.3 ms, Java 0.24 ms, C++ 0.18 ms.

Approach 3: Rising Water + Union-Find Optimal

Record where each height is. For t = 0, 1, 2, …: open the cell with height t and join it with every neighbour that's already open. As soon as (0, 0) and (n−1, n−1) share a root, return t.

  • The heights are a permutation of 0..n²−1, so no sorting is needed: where[h] gives the cell directly.
  • No heap: each cell opens once and does at most 4 joins.
Time O(n² · α(n²)), nearly O(n²) Space O(n²)

A random 50 × 50 grid: Python 1.7 ms, Java 0.12 ms, C++ 0.06 ms, the fastest in every language on that grid.

In practice No shortcut

No library solves bottleneck paths on a grid. Approach 2 or 3 is what you'd write.
