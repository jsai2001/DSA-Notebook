300. Longest Increasing Subsequence Medium Dynamic Programming Binary Search
Key idea: Keep tails, where tails[L] is the smallest last value of any increasing subsequence of length L + 1. It's always sorted. For each value, binary search for the first tail ≥ it: replace that tail, or append if there's none. The length of tails is the answer. O(n log n), against O(n²) for the usual DP.

Problem View on LeetCode (opens in a new tab) ↗

Return the length of the longest strictly increasing subsequence of nums (values in order, not necessarily side by side).

  • 1 <= nums.length <= 2500, -10⁴ <= nums[i] <= 10⁴
  • Follow-up: O(n log n)

Example: [10,9,2,5,3,7,101,18] → 4 (2, 3, 7, 18). [0,1,0,3,2,3] → 4. [7,7,7,7] → 1.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[2,2] 1 Strictly increasing. Using bisect_right (first tail > x) lets equal values extend: it said 2. Wrong on 262 of 2007 tests.
[10,9,2,5,3,7,101,18] 4 The final tails is [2, 3, 7, 18], which happens to be a real answer; often it isn't (see below), only its length is.
2500 rising values 2500 The memoized recursion goes 2500 calls deep: Python's default limit of 1000 isn't enough.

Approach 1: Recursion with Memo

longest(i) = the longest increasing subsequence that starts with nums[i]: 1, plus the best longest(j) over every later, bigger nums[j]. Remember each result, and take the best start.

Time O(n²) Space O(n) memo + O(n) calls

2500 random values: Python 289 ms, Java 5.0 ms, C++ 4.2 ms.

Approach 2: DP, Ends at i

dp[i] = the longest increasing subsequence that ends at nums[i]: 1, plus the best dp[j] over every earlier, smaller nums[j]. The answer is the biggest dp.

  • The usual first answer, and the base for variants like "count them" (673).
Time O(n²) Space O(n)

2500 random values: Python 163 ms, Java 2.9 ms, C++ 4.3 ms.

Approach 3: Tails + Binary Search Optimal

For each value x, find the first tail ≥ x with a binary search. If none, x makes a longer subsequence: append it. Otherwise replace that tail with x: a subsequence of that length can now end lower, which leaves more room for later values.

  • tails stays sorted, which is why binary search works.
  • For [3,4,1] the final tails are [1, 4], which isn't a subsequence; the length 2 is still right.
Time O(n log n) Space O(n)

2500 random values: Python 0.28 ms, Java 0.06 ms, C++ 0.04 ms, about 600 times faster than Approach 2 in Python.

In practice No shortcut

No library computes the LIS, but Approach 3 leans on the built-in binary searches: bisect_left and std::lower_bound.
