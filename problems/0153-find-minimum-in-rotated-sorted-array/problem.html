153. Find Minimum in Rotated Sorted Array Medium Array Binary Search
Key idea: Binary search, comparing nums[mid] with nums[hi]. If nums[mid] > nums[hi], the drop (and the minimum) is to the right of mid: lo = mid + 1. Otherwise mid..hi is sorted and the minimum is mid or left of it: hi = mid. Stop when lo == hi. O(log n).

Problem View on LeetCode (opens in a new tab) ↗

A sorted array of different numbers was rotated some number of times (moving the last number to the front each time), maybe zero times. Return the smallest number, in O(log n) time.

  • 1 <= n <= 5000
  • -5000 <= nums[i] <= 5000, all different

Example: [3,4,5,1,2] → 1. [4,5,6,7,0,1,2] → 0. [11,13,15,17] → 11 (not rotated).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[3,1,2] 1 hi = mid - 1 throws away mid, which can be the minimum: said 3.
[2,1] 1 Looping on lo <= hi while setting hi = mid never ends: stuck here after 1,000 rounds.
[1,2,3,4] 1 Not rotated. Searching for "the first number smaller than nums[0]" without a separate check said 4. Comparing mid with nums[lo] instead of nums[hi] said 3.
[1] 1 One number: the loop doesn't run.
[2,3,4,5,1] 1 The minimum is last.
[5,1,2,3,4] 1 The minimum is second: the drop is right at the start.

Approach 1: Look at Every Number

Scan the array and keep the smallest number.

  • Always right, but ignores that the array is sorted.
  • Doesn't meet the O(log n) requirement.
Time O(n) Space O(1)

At n = 5000, averaged over 1,000 arrays: Python 70 µs, Java 3.5 µs, C++ 0.3 µs per call.

Approach 2: Binary Search Against nums[0]

If nums[0] <= nums[-1], the array isn't rotated: return nums[0]. Otherwise everything before the drop is ≥ nums[0] and everything after is smaller, so binary search for the first number smaller than nums[0].

  • A clear "yes/no" split, the kind binary search is built for.
  • The not-rotated check is required: there's no number smaller than nums[0] then.
Time O(log n) Space O(1)

At n = 5000: Python 13 µs, Java 0.6 µs, C++ 0.1 µs per call, 5× faster than the scan in Python. About 13 comparisons instead of 5000.

Approach 3: Binary Search Against nums[hi] Optimal

Compare nums[mid] with nums[hi]. Bigger: the array drops somewhere after mid, so lo = mid + 1. Smaller: mid..hi is sorted, so the minimum is mid or left of it, hi = mid. When one number is left, it's the minimum.

  • No special case: a not-rotated array just keeps moving hi left.
  • hi = mid with while lo < hi go together; mixing in mid - 1 or lo <= hi breaks it.
Time O(log n) Space O(1)

At n = 5000: Python 11 µs, Java 1.0 µs, C++ 0.15 µs per call. The expected answer. With duplicates allowed (problem 154), equal values need hi -= 1, and the worst case becomes O(n).

In practice Built-ins

min(nums) in Python, std::min_element in C++, Arrays.stream(nums).min() in Java. All scan the whole array.

Time O(n) Space O(1)

Python 70 µs, Java 19 µs, C++ 3.3 µs per call at n = 5000 here: fine for everyday code, but it's Approach 1, so it misses the point of the problem.
