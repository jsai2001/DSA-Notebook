130. Surrounded Regions Medium Matrix BFS Union Find
Key idea: Flip the question around. Instead of asking which O's are surrounded, find the ones that aren't: start from every O on the border and mark everything connected to it as safe. Every O left unmarked is surrounded, so flip it. One pass, O(m · n).

Problem View on LeetCode (opens in a new tab) ↗

board is a grid of 'X' and 'O'. A region is a group of O's joined up, down, left or right. A region is surrounded if none of its cells is on the edge of the board. Change every surrounded region to X, in place.

  • 1 <= m, n <= 200
  • board[i][j] is 'X' or 'O'

Example: XXXX / XOOX / XXOX / XOXX → XXXX / XXXX / XXXX / XOXX. The O at the bottom touches the edge, so it stays.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
XOX / XOX / XXX XOX / XOX / XXX The middle O isn't on the edge, but it connects to one that is. Flipping every inner O said XOX / XXX / XXX.
O O A 1 × 1 board: the only cell is on the edge.
OOO / OXO / OOO unchanged Every O is on the edge; nothing flips.
XXXXX / XOOOX / XOXOX / XOOOX / XXXXX all X A ring of O's with an X in the middle: the whole ring is surrounded.
200 × 200, one path of 19,701 O's zigzagging to the edge unchanged A recursive DFS goes 19,701 calls deep. Python's limit is 1,000: it raised RecursionError here. Use a queue or an explicit stack.
200 × 200, all O inside a ring of X all X One huge surrounded region. Searching it again from each of its 39,204 cells took 7.6 s in C++.

Approach 1: Search From Every O

For each O, run a fresh search through the O's next to it. If the search reaches the edge, the O stays; otherwise it's trapped. Flip the trapped ones at the end, after all the checks.

  • Simple, and each check is clearly right.
  • Wasteful: every O in a region searches that whole region again, so a region of k cells costs k².
Time O((m · n)²) Space O(m · n)

Measured on 200 × 200 boards. Random half-O: Python 0.6 s, C++ 0.12 s. One big surrounded region: C++ 7.6 s, Java 22 s. The zigzag path: Python 172 s, C++ 1.6 s. Far too slow at full size.

Approach 2: Spread From the Border (BFS) Optimal

An O survives only if it connects to the edge. So put every O on the edge in a queue, mark it safe (S), and spread through neighboring O's. When the queue is empty, any O still left is surrounded: turn it into X, and turn every S back into O.

  • Mark a cell S when it's queued, not when it's taken out, so no cell is queued twice.
  • The board itself holds the marks: no extra visited array.
  • A recursive DFS works the same way on small boards, but a long path overflows Python's recursion limit (and can overflow the stack in C++ and Java). The queue has no such limit.
Time O(m · n) Space O(m · n) for the queue

Every cell is queued at most once. On every 200 × 200 test here: Python 7–16 ms, Java 2–4 ms, C++ under 0.1 ms. The standard answer.

Approach 3: Union-Find With a Border Node

Give each cell an id, r · n + c, plus one extra node that stands for "the border". Join each O with the O below and the O to the right, and join every edge O with the border node. Then an O stays only if it's in the border node's group.

  • Joining only down and right is enough: every pair of neighbors is visited once from its top or left cell.
  • Path halving in find keeps the trees flat, so each call is close to O(1).
Time O(m · n · α(m · n)) ≈ O(m · n) Space O(m · n)

Python 14–48 ms, Java 3–5 ms, C++ 0.2–1.1 ms on the 200 × 200 tests: a bit slower than Approach 2, with no recursion. Worth knowing because the same "extra node" trick solves other connected-to-the-edge problems.

In practice No shortcut

The standard libraries have no flood fill. The only built-in that helps is the queue (collections.deque, std::queue, ArrayDeque), used in Approach 2.

Approach 2 is what you'd write: a dozen lines, no recursion, and each cell is touched a fixed number of times.
