572. Subtree of Another Tree Easy Tree DFS String Matching
Key idea: A subtree means a node and everything below it. Try each node of root as the top and ask "is this the same tree as subRoot?", where same means equal values and both trees end (None) in the same places. That's O(m·n). For O(m + n), write both trees in preorder with a marker for every missing child and search for one list inside the other.

Problem View on LeetCode (opens in a new tab) ↗

Given the roots of two binary trees, root and subRoot, return true if some node of root, together with all of its descendants, has exactly the same structure and values as subRoot. A tree counts as a subtree of itself.

  • root has 1 to 2000 nodes; subRoot has 1 to 1000.
  • -10⁴ <= Node.val <= 10⁴.

Examples: root = [3,4,5,1,2], subRoot = [4,1,2] → true; root = [3,4,5,1,2,null,null,null,null,0], same subRoot → false (the 4 there has an extra 0 below it).

Edge cases

Try these against your solution before reading the approaches.

root / subRoot Expected Why it's tricky
[3,4,5,1,2,null,null,null,null,0] / [4,1,2] false The 4 matches until its 2, which has a 0 below it. A same() that returns true as soon as subRoot runs out says true.
[1,2,3] / [1,2] false subRoot is the top part of root, not a subtree: root's 1 also has a 3. Same mistake, same wrong true.
[1,2] / [1,null,2] false Left child vs right child. Without markers for missing children, both preorders are 1, 2.
[12] / [2] false As strings, "12,#,#" contains "2,#,#". Put a separator before each value too: ",12,#,#" doesn't contain ",2,#,#".
[1,1] / [1] true The root 1 fails (it has a child), but its child 1 is a leaf and matches. Keep looking after a failure.
[1,2,null,3] / [3] true The match is two levels down. Calling same() on root's children instead of recursing only looks one level down and says false.
[1] / [1,1] false subRoot is bigger than root.

Approach 1: Same Tree at Every Node

Two helpers. same(a, b) walks both trees together: equal values, then same left subtrees, then same right subtrees; two Nones are the same, one None isn't. isSubtree asks same(node, subRoot) at root, then recurses into both children.

  • same() stops at the first difference, so most tries end quickly.
  • Recurse with isSubtree on the children (not same), so every node gets tried.
Time O(m · n) Space O(height) for the recursion

The answer most interviewers expect, and fast enough here: the worst input tried (a 2000-node chain of 1s against a 1000-node chain of 1s ending in 2) took 140 ms in Python and 10 ms in C++. Approaches 2 and 3 took about 1 ms on it.

Approach 2: Preorder Lists + KMP Optimal

Write each tree as its preorder list, with a marker (∅) for every missing child. With the markers, the list describes the tree exactly, and each subtree is one unbroken run of the list. So subRoot is a subtree exactly when its list appears inside root's list.

  • Keep the values as list items (or put a separator before each one), so 12 can't be mistaken for 2.
  • KMP finds the pattern in O(m + n): on a mismatch it falls back using fail[] and never re-reads the text.
  • A match must start at a value, and a subtree's list can't stop partway through another subtree, so a match is always a whole subtree.
Time O(m + n) Space O(m + n)

Linear in the worst case, and it uses no hashing. The cost is writing KMP correctly; the built-in string search below does the same job with less code.

Approach 3: Number Every Subtree

Give each distinct subtree a number, bottom up: empty is #0, and a node's number is looked up by the key (value, left #, right #). A key not seen before gets the next number. Two subtrees get the same number exactly when they're equal.

  • Number subRoot first; call its number target.
  • Then number root with the same table: true if any node gets target.
  • The numbers are exact, not hashes that might collide, so no double-check is needed.
Time O(m + n) with a hash map Space O(m + n)

The same numbering finds every pair of equal subtrees in one tree, as in Find Duplicate Subtrees (652). The C++ version here uses std::map, which adds a log factor.

In practice Built-ins

Approach 2 with the language's own substring search: build a string with a "," before every value and "#" for every missing child, then use in (Python), find (C++), or indexOf (Java).

Time O(m + n) to build; the search is fast in practice Space O(m + n)

All three pass every test here, in a few milliseconds at most. The library searches don't all promise linear time in the worst case, so KMP is the version to explain if asked for a guarantee.
