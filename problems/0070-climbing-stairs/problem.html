70. Climbing Stairs Easy Math Dynamic Programming Memoization
Key idea: Your last move onto step n was either 1 step (from n − 1) or 2 steps (from n − 2), so ways(n) = ways(n − 1) + ways(n − 2): the Fibonacci numbers. Keep just the last two values: O(n) time, O(1) space. For O(log n), raise [[1, 1], [1, 0]] to the power n.

Problem View on LeetCode (opens in a new tab) ↗

You are climbing a staircase with n steps. Each time you can climb either 1 or 2 steps. In how many distinct ways can you reach the top?

  • 1 <= n <= 45.

Examples: n = 2 → 2 (1 + 1, or 2); n = 3 → 3 (1 + 1 + 1, 1 + 2, 2 + 1).

Approach 1: Recursion with Memo

Look at the last move. To stand on step k you came from k − 1 (a 1-step) or from k − 2 (a 2-step), and those two groups of ways don't overlap. So ways(k) = ways(k − 1) + ways(k − 2), with ways(1) = 1 and ways(2) = 2.

  • Remember each answer: without the memo, the same k is worked out over and over.
  • The recursion goes about n levels deep, fine for n ≤ 45.
Time O(n) Space O(n) for the memo and the call stack

The way to find the recurrence. The next approach is the same recurrence as a loop.

Approach 2: Two Variables

Work upward from the bottom instead. Each value only needs the two before it, so keep just those: prev = ways(k − 1) and cur = ways(k), then shift them up one step at a time.

  • Start from ways(0) = 1 (stand still) and ways(1) = 1; that makes n = 1 and n = 2 need no special case.
  • Return cur, the newer of the two.
Time O(n) Space O(1)

The answer interviewers expect. It's at most 44 additions here, so it's as fast as anything else in practice.

Approach 3: Matrix Fast Power Optimal

One step of the recurrence is a matrix multiplication: [[1, 1], [1, 0]] × [ways(k), ways(k − 1)] = [ways(k + 1), ways(k)]. So M^n = [[ways(n), ways(n − 1)], [ways(n − 1), ways(n − 2)]], and M^n can be built from M^1, M^2, M^4, … using the bits of n, as in Pow(x, n) (50).

  • For each bit of n, from the right: if it's 1, multiply result by base; then square base.
  • Use 64-bit numbers. The loop squares base once after the last bit, a value it never uses. For n ≥ 32 that's M^64, whose top-left is 17167680177565. With int in C++ it overflowed right there (3524578 × 3524578).
Time O(log n) Space O(1)

Asymptotically best, but at n ≤ 45 it does 10 matrix products against Approach 2's 44 additions, so there's no real gain here. Worth knowing for the "huge n, answer mod 10⁹ + 7" versions of this problem.

In practice No shortcut

None of the standard libraries has a Fibonacci function. There is a closed form, round(φ^(n+1) / √5) with φ = (1 + √5) / 2, but in 64-bit floating point it was exact only up to n = 69 here and wrong from n = 70 on. It works within this problem's limits, but it depends on rounding luck.

Write Approach 2. The things to remember: the last move was 1 or 2 steps, start from ways(0) = ways(1) = 1, and return the newer value.
