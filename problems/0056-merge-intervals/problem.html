56. Merge Intervals Medium Array Sorting
Key idea: Sort by start. Then an interval overlaps something before it only if it overlaps the last merged interval. If start <= last.end, set last.end = max(last.end, end); otherwise start a new merged interval. O(n log n) time.

Problem View on LeetCode (opens in a new tab) ↗

Given an array of intervals where intervals[i] = [start, end], merge all overlapping intervals and return the non-overlapping intervals that cover exactly the same numbers.

  • 1 <= intervals.length <= 10⁴ and 0 <= start <= end <= 10⁴.
  • Intervals that touch, like [1,4] and [4,5], count as overlapping.

Examples: [[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]]; [[1,4],[4,5]] → [[1,5]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[1,4],[4,5]] [[1,5]] They only touch, which counts. Checking start < last.end instead of <= keeps them apart.
[[1,4],[5,6]] [[1,4],[5,6]] No shared number: 4 and 5 are next to each other but don't overlap.
[[4,7],[1,4]] [[1,7]] Not sorted. Merging in the given order returns [[4,7]]: [1,4] is "merged" into [4,7] and its start is lost.
[[2,3],[4,5],[1,10]] [[1,10]] The last interval covers everything. Without sorting you get [[2,3],[4,10]].
[[1,10],[2,3],[4,5]] [[1,10]] Nested: [2,3] sits inside [1,10]. Setting last.end = end without max shrinks it: [[1,3],[4,5]].
[[1,4],[0,0]] [[0,0],[1,4]] A single point, 0, is a valid interval. Sorting moves it to the front.
[[1,1],[1,1]] [[1,1]] Duplicates merge into one.
[[0,0]] [[0,0]] One interval: return it as it is.

Approach 1: Absorb Overlaps, No Sorting

Keep a list of disjoint merged intervals. For each new interval, compare it with every merged one: absorb each one it overlaps (take the smaller start and the larger end), keep the rest, then add the grown interval.

  • Two intervals overlap when s <= end and start <= e: neither ends before the other starts.
  • The list stays disjoint after every step, so one pass over it per interval is enough.
  • Sort the result at the end, only so it comes out in order.
Time O(n²) Space O(n)

Correct, but slow when few intervals overlap: 10⁴ separate points took 4.6 s in Python here (0.14 s in C++). Useful if intervals arrive one at a time and you can't sort them all up front.

Approach 2: Sort by Start, Then One Pass Optimal

After sorting by start, the merged intervals come out left to right. The next interval can only overlap the last merged one: every earlier merged interval ended before that one began.

  • start <= last.end: it overlaps (or touches), so last.end = max(last.end, end).
  • Otherwise there's a gap: add it as a new merged interval.
  • Add a new pair, not the input's own list or array. Otherwise last.end = … later writes into the input: [[1,3],[2,6]] becomes [[1,6],[2,6]].
Time O(n log n) Space O(n) for the sorted copy

The expected answer. Sorting in place (intervals.sort()) saves the copy but reorders the caller's list; LeetCode doesn't mind. In Java, compare with Integer.compare(a[0], b[0]): a[0] - b[0] is fine for these values but can overflow for numbers near ±2³¹.

Approach 3: Count Starts and Ends, Then Sweep

The values are small whole numbers (at most 10⁴), so you can skip the sort. Count how many intervals start and end at each number, then sweep from 0 upward, keeping active, the number of intervals covering the current point.

  • When active goes from 0 to positive, a merged interval begins.
  • When it drops back to 0 at a point where something ends, the merged interval closes.
  • Count both the starts and the ends at a point before checking for a close. Checking between them splits [[1,4],[4,5]] into [[1,4],[1,5]].
Time O(n + V) Space O(V), V = the largest end

As fast as Approach 2 here, and the result comes out sorted. But it only works because the values are small integers. With values up to 10⁹, or decimals, the counting arrays don't fit; sort instead.

In practice No shortcut

No standard library merges intervals. The built-in part is the sort: sorted(intervals, key=lambda x: x[0]) in Python, std::sort with a comparator in C++, Arrays.sort with a comparator in Java. The pass after it is yours to write.

Write Approach 2. The three things to remember: sort by start, use <= so touching intervals merge, and take the max of the ends.
