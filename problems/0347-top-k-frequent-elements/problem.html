347. Top K Frequent Elements Medium Heap Bucket Sort Hash Map
Key idea: Count each value. A count is at most n, so put each value in bucket[count] and read the buckets from the top until you have k. O(n), no sort. A size-k min-heap (O(n log k)) is the other common answer.

Problem View on LeetCode (opens in a new tab) ↗

Return the k values that appear most often in nums, in any order. The answer is promised to be unique.

  • 1 <= nums.length <= 10⁵, -10⁴ <= nums[i] <= 10⁴
  • k is between 1 and the number of different values
  • Follow-up: better than O(n log n).

Example: nums = [1,1,1,2,2,3], k = 2 → [1,2]. nums = [1], k = 1 → [1].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
nums = [1], k = 1 [1] A value can appear n times, so the buckets need slots 0 to n. With only n buckets this crashed with an IndexError on 184 of 3,006 tests.
nums = [-1,-1,2], k = 2 [-1,2] Negative values: count with a hash map, not an array indexed by value.
10⁵ different values plus one repeat, k = 1 the repeated value Almost every bucket is empty, but the bucket loop still only walks n + 1 of them.

Approach 1: Count, Then Sort

Count each value in a hash map. Sort the different values by count, biggest first, and return the first k.

  • Simple. Doesn't meet the follow-up when most values are different.
Time O(n log n) Space O(n)

10⁵ numbers, about 20,000 different values, average of 30 runs: Python 9.6 ms, Java 5.0 ms, C++ 2.7 ms. The fastest of the three in Python, because sorted runs in C.

Approach 2: Size-k Min-Heap

After counting, push each value into a min-heap keyed by count. When the heap holds more than k, pop the top: it's the least frequent of them. The k left are the answer.

  • Good when k is small. Also works on a stream of counts.
Time O(n log k) Space O(n) for the counts, O(k) for the heap

Same input, k = 10: Python 12 ms, Java 4.0 ms, C++ 2.6 ms. With k = 4689: Python 18.5 ms, Java 8.3 ms, C++ 4.0 ms, the slowest of the three.

Approach 3: Bucket by Count Optimal

A count is between 1 and n. Make n + 1 buckets and put each value in bucket[count]. Walk the buckets from n down, taking values until you have k.

  • No comparisons between counts at all.
Time O(n) Space O(n)

Same input: Java 3.2 ms and C++ 2.6 ms, the fastest for both ks (in C++ only just: counting takes most of the time). Python 17 ms, behind Approach 1: building 10⁵ + 1 lists in Python costs more than a sort in C.

In practice Built-ins

Python's Counter(nums).most_common(k) counts in C and then uses heapq.nlargest, which is Approach 2. C++ and Java have no one-liner; use Approach 3.

Time O(n log k) Space O(n)

Should pass on LeetCode. Same input: 5.1 ms with k = 10, the fastest Python here. 10.9 ms with k = 4689, a bit behind Approach 1.
