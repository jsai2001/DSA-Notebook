97. Interleaving String Medium String Dynamic Programming
Key idea: After using i letters of s1 and j of s2, the next letter of s3 is s3[i + j], and it must come from s1 or from s2. So dp[i][j] = (s1's i-th letter matches and dp[i − 1][j]) or (s2's j-th letter matches and dp[i][j − 1]). Check the lengths first. One row of the table is enough: O(m · n) time, O(n) space.

Problem View on LeetCode (opens in a new tab) ↗

Given s1, s2 and s3, return true if s3 can be made by interleaving s1 and s2: using all the letters of both, each in its own order, mixed together in any way.

  • 0 <= s1.length, s2.length <= 100 and 0 <= s3.length <= 200.
  • All three are lowercase English letters.
  • Follow-up: use only O(s2.length) extra memory.

Examples: "aabcc", "dbbca", "aadbbcbcac" → true; "aabcc", "dbbca", "aadbbbaccc" → false; "", "", "" → true.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"", "", "" true Nothing from nothing: dp[0][0] must start as true.
"", "abc", "abc" true One string is empty: s3 must simply equal the other.
"ab", "c", "abcd" false s3 has a letter left over. Without the length check first, the table never looks at the "d" and says true.
"a", "b", "ba" true s2's letters can come first.
"a", "b", "aa" false The lengths add up, but s1's one "a" can't be used twice.
"aa", "ab", "aaba" true Both strings can give the next "a". Greedily taking it from s1 whenever it matches says false; the right choice needs looking ahead.
"abc", "def", "abdfce" false The same letters, but "f" comes before "e" while s2 has "e" first: each string's order must be kept.
100 a's, 100 a's, 199 a's then "b" false Every split looks possible until the last letter. Plain recursion tries them all: about 4 times slower for each letter added to both strings.

Approach 1: Plain Recursion

can(i, j) asks: can the rest of s3, from i + j, be made from s1[i:] and s2[j:]? The next letter of s3 must equal s1[i] (then ask can(i + 1, j)) or s2[j] (then can(i, j + 1)).

  • Done when both are used up: i == len(s1) and j == len(s2).
  • The length check up front makes sure s3 runs out at the same moment.
Time O(2^(m + n)) in the worst case Space O(m + n) stack

The same (i, j) is reached by many different paths and answered again each time: 1.24 s in Python with just 12 + 12 letters.

Approach 2: 2D DP Table

There are only (m + 1)(n + 1) different questions, so answer each once, from the front. dp[i][j]: can the first i letters of s1 and the first j of s2 make the first i + j of s3?

  • dp[0][0] = True.
  • dp[i][j] is true if the last letter, s3[i + j − 1], came from s1 (s1[i − 1] equals it and dp[i − 1][j]) or from s2 (s2[j − 1] and dp[i][j − 1]).
Time O(m · n) Space O(m · n)

1.6 ms in Python at the limit (100 + 100). The table is like a grid: a true path from the top-left to the bottom-right, moving down for an s1 letter and right for an s2 letter, is an interleaving.

Approach 3: One Row Optimal

The follow-up: row i only uses row i − 1 and itself, so keep one row, dp[j], and overwrite it left to right.

  • Before dp[j] is overwritten it still holds the row above: that's dp[i − 1][j].
  • dp[j − 1] was just written, so it's already this row: dp[i][j − 1].
Time O(m · n) Space O(n)

The same work as Approach 2 (1.7 ms) with one row instead of a whole table. The same one-row trick works for Unique Paths (62) and Edit Distance (72).

In practice Built-ins

In Python, @functools.cache on Approach 1 remembers each can(i, j), which turns it into O(m · n) with no other change. C++ and Java have nothing like it: write the table.

Time O(m · n) Space O(m · n) for the cache

4.1 ms at the limit. The recursion goes at most 200 deep, well under Python's default limit of 1000.

Comparison

Approach Technique Time Space Notes
Plain Recursion Next letter from s1 or s2 O(2^(m + n)) O(m + n) Too slow from about 12 + 12
2D Table dp[i][j] from above and from the left O(m · n) O(m · n) Easy to check by hand
One Row Overwrite dp[j] left to right O(m · n) O(n) The follow-up's answer
