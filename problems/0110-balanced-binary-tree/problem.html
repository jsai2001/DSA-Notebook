110. Balanced Binary Tree Easy Tree DFS
Key idea: A tree is balanced when at every node the two subtree heights differ by at most 1. Compute the heights bottom-up in one walk, and return -1 as soon as a node fails, so the answer travels up without more work. O(n), instead of recomputing heights for every node.

Problem View on LeetCode (opens in a new tab) ↗

Given a binary tree, return true if it is height-balanced: for every node, the heights of its left and right subtrees differ by no more than 1.

  • 0 to 5000 nodes (the tree can be empty).
  • -10⁴ <= Node.val <= 10⁴.

Examples: [3,9,20,null,null,15,7] → true; [1,2,2,3,3,null,null,4,4] → false; [] → true.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[] true An empty tree has nothing out of balance.
[1,2] true Heights 1 and 0: a difference of 1 is allowed.
[1,2,null,3] false At the root, the sides are 2 and 0. It has only one leaf, so the rule "all leaves within one level of each other" wrongly says true.
[1,2,2,3,null,null,3,4,null,null,4] false The root's two sides are both height 3, so checking only the root says true. The 2's below it are unbalanced: every node must pass.
[1,2,2,3,3,null,null,4,4] false The left side is height 3, the right 1: the problem is at the root.
5000 nodes in one line false It fails near the bottom, but the recursion has to go 5000 deep to get there, past Python's default limit of 1000. The stack version is fine.

Approach 1: Check Every Node from the Top

Follow the definition: at the root, compute the height of each side and compare them. Then check the left and right subtrees the same way.

  • height(node) = 1 + max(height(left), height(right)), with an empty tree at 0.
  • The root passing is not enough: recurse into both children too.
Time O(n · h): each height is recomputed for every node above it Space O(h) call stack

Correct, and close to the definition, but it repeats work: 9.6 ms for a balanced tree of 5000 nodes, 12 times slower than Approach 2.

Approach 2: Bottom-Up with −1 for "Not Balanced" Optimal

Compute each subtree's height once, children first, and check the node at the same moment. One function can return both answers: the height if the subtree is balanced, or -1 if it isn't.

  • If either child returns -1, return -1 right away: there's no need to look further.
  • Otherwise compare the two heights, then return 1 + max(left, right).
Time O(n) Space O(h) call stack

The answer interviewers expect: each node is visited once (0.8 ms for 5000 balanced nodes). It's Maximum Depth (104) with one check added.

Approach 3: Post-Order with a Stack

The same bottom-up check without recursion. Each node goes on the stack twice: the first time, push it back marked "children done", then its children; the second time, both children's heights are already stored, so check and store its own.

  • Keep the heights in a map from node to height; a missing child counts as 0.
Time O(n) Space O(n) for the map

A little slower than Approach 2 (1.4 ms), but safe on a 5000-deep tree (0.7 ms), where both recursive versions passed Python's limit.

In practice No shortcut

Nothing in Python, C++ or Java checks a tree's balance. Self-balancing trees (like std::map or Java's TreeMap, both red-black trees) keep themselves balanced, but use a looser rule than this one.

Write Approach 2. Check every node, not just the root, and allow a difference of exactly 1.
