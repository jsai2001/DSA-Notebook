25. Reverse Nodes in k-Group Hard Linked List Recursion
Key idea: Keep before, the node just in front of the next group (start it on a dummy). Walk k nodes to find the group's end; if you fall off the list, stop. Otherwise reverse the group with the usual prev/cur flip, starting prev at the node after the group, then set before.next = end and before = first. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given the head of a linked list, reverse its nodes k at a time and return the new head. If the number of nodes left at the end is less than k, they stay as they are.

  • The list has n nodes, 1 <= k <= n <= 5000.
  • 0 <= Node.val <= 1000.
  • Change the nodes themselves, not the values inside them.
  • Follow-up: can you do it with O(1) extra memory?

Examples: [1,2,3,4,5], k = 2 → [2,1,4,3,5]; [1,2,3,4,5], k = 3 → [3,2,1,4,5].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1], k = 1 [1] The smallest input: one group of one node.
[1,2,3,4,5], k = 1 [1,2,3,4,5] Groups of one: nothing changes, but the code still has to run every group without breaking links.
[1,2], k = 2 [2,1] The whole list is one group, so the head changes. A dummy node handles that without a special case.
[1,2,3,4,5], k = 3 [3,2,1,4,5] The last 2 nodes are a short group and must not be reversed. Check that k nodes exist before flipping any.
[1,2,3,4,5,6], k = 3 [3,2,1,6,5,4] n is a multiple of k: no leftover, and the last group's old first node must end up pointing to null.
[1,2,3,4,5], k = 2 [2,1,4,3,5] Linking groups together: the first group's new last node (1) must point to the second group's new first node (4), not to 3.
[1,2,3,4,5], k = 5 [5,4,3,2,1] k = n: the whole list is reversed.
[7,7,7,7], k = 2 [7,7,7,7] The values look unchanged, but the nodes must still be reordered. Swapping values instead of nodes isn't allowed.
5,000 nodes, k = 1 Unchanged The most groups: a recursive solution goes 5,001 calls deep, which is over Python's default limit of 1,000.

Approach 1: Array of Nodes

Reversing parts of a linked list is fiddly; reversing parts of an array is easy. Put the nodes in an array, reverse each full block of k in the array, then link the nodes in the array's order.

  • Blocks start at 0, k, 2k, … as long as a whole block fits; a shorter last block is skipped.
  • It moves the nodes (their next pointers), not the values, so it follows the rules.
Time O(n) Space O(n)

Simple and hard to get wrong, but the array costs O(n) extra memory, which the follow-up asks you to avoid.

Approach 2: Recursion

Check that the first k nodes exist. If they do, the rest of the list is the same problem: solve it first, then reverse this group so that its old first node points to the rest's answer.

  • Fewer than k nodes: return head unchanged (this also covers null).
  • Reversing with prev starting at the rest's answer means the group is linked to the rest for free when the flip is done.
  • The group's old last node is its new first: that's what the call returns.
Time O(n) Space O(n / k) call stack

Clear, but one call per group. With Python's default recursion limit (1,000) it raised RecursionError here at n = 5,000 for every k ≤ 5. C++ and Java handled 5,001 calls fine.

Approach 3: In Place with a Dummy Node Optimal

The same steps as the recursion, but front to back in a loop, keeping before, the node just in front of the current group.

  • From before, walk k steps to end. Hitting null means fewer than k nodes are left: return dummy.next.
  • Remember first = before.next and after = end.next. Reverse with prev = after and cur = first until cur reaches after; first ends up pointing to after.
  • Reconnect: before.next = end (the new first), then before = first (the new last) for the next group.
Time O(n) Space O(1)

Each node is visited twice (once to find the group, once to flip it) and only pointers change. This is the answer to the follow-up, and it builds on Reverse Linked List (206) and the dummy node from Remove Nth Node From End of List (19).

In practice No shortcut

LeetCode's ListNode is a bare class, so there's no library call to reverse part of it. std::reverse, Collections.reverse and slicing only help once the nodes are in an array, which is Approach 1.

Write Approach 3. The pattern to remember: keep the node before the part you're changing, and start prev at the node after it, so the reversed part is already connected on both sides.

Comparison

Approach Technique Time Space Notes
Array of Nodes Reverse blocks in an array, relink O(n) O(n) Simplest; not O(1) memory
Recursion Solve the rest, reverse this group onto it O(n) O(n / k) Too deep for Python's default limit when k is small
In Place with a Dummy Node before / first / end / after, flip, reconnect O(n) O(1) Answer to the follow-up
