416. Partition Equal Subset Sum Medium Dynamic Programming Knapsack
Key idea: Two equal halves means some subset adds up to total / 2. That's 0/1 knapsack: dp[s] says whether sum s is reachable, and each number updates it with dp[s] |= dp[s − x], going down from the top so the number is used once. O(n · sum).

Problem View on LeetCode (opens in a new tab) ↗

Can nums be split into two groups with the same sum?

  • 1 <= nums.length <= 200, 1 <= nums[i] <= 100

Example: [1,5,11,5] → true ([1,5,5] and [11]). [1,2,3,5] → false.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[9,1] false Filling dp upwards lets 1 be used again and again (1, 2, 3, 4, 5), so it said true. That was wrong on 642 of 3,007 tests.
[1] false An odd total can never split evenly: check it first.
200 even numbers whose half is odd false Even sums only, so the odd half is never reached and nothing stops early: the whole table gets filled.

Approach 1: Take or Skip, Recursively

For each number, try taking it into the half and try skipping it, until the half is filled exactly, overshot, or the numbers run out.

  • The same (i, left) question gets asked again and again: nothing is remembered.
Time O(2ⁿ) Space O(n) call stack

[2] * n with n odd (the half is odd, so no answer): in Python n = 21 took 0.25 s, 23 took 0.99 s, 25 took 3.9 s, 4 times longer per two more numbers. At n = 21: Java 2.3 ms, C++ 4.1 ms.

Approach 2: Set of Reachable Sums

Start with {0}. For each number x, add s + x for every sum s already in the set (up to the half). Stop as soon as the half shows up.

  • The set never holds more than half + 1 sums.
  • Fast when few different sums appear, like many equal numbers.
Time O(n · sum) Space O(sum)

200 even numbers with an odd half (5065), average of 10 runs: Python 23 ms, Java 5.9 ms, C++ 2.2 ms. Faster than Approach 3 in Python, slower in Java and C++: hashing costs more than an array.

Approach 3: 1-D Knapsack DP Optimal

dp[s]: some of the numbers so far add up to s. For each x, for s from the half down to x, dp[s] |= dp[s − x]. Going down means dp[s − x] still describes the numbers before x.

  • The 2-D table dp[i][s] folded into one row.
Time O(n · sum) Space O(sum)

Same input: Python 32 ms, Java 0.81 ms, C++ 0.56 ms.

In practice Built-ins

Store the whole dp row as bits of one number: bits |= bits << x adds x to every reachable sum at once. Python's big ints (30 bits per digit in CPython) and C++'s std::bitset (64 bits per word) shift many sums per step.

Time O(n · sum / w), w = bits per word Space O(sum) bits

Should pass on LeetCode. Same input: Python 0.063 ms, 500 times faster than Approach 3. C++ 0.068 ms, 8 times faster.
