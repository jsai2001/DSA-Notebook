567. Permutation in String Medium Hash Table String Sliding Window
Key idea: A permutation of s1 is any string with the same letter counts. Slide a window of length len(s1) over s2: each step adds one letter and removes one, so only two counts change. Track how many of the 26 letters agree; the answer is true as soon as all 26 do. O(n) time, O(1) space.

Problem View on LeetCode (opens in a new tab) ↗

Given two strings s1 and s2, return true if s2 contains a permutation of s1: some substring of s2 uses exactly the letters of s1, in any order.

  • 1 <= s1.length, s2.length <= 10⁴.
  • Both strings are lowercase English letters only.

Examples: s1 = "ab", s2 = "eidbaooo" → true ("ba"); s1 = "ab", s2 = "eidboaoo" → false.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"ab", "a" false s1 is longer than s2: there's no window. Code that fills the first window from s2 without checking runs off its end.
"abc", "abc" true Equal lengths: there's exactly one window. Looping range(len(s2) − m) (one short) checks none.
"ab", "xxab" true The match is the last window. A sliding loop checks before each slide, so the last window has to be checked after the loop.
"ab", "baxx" true The match is the first window. Checking only after each slide skips it.
"aab", "xabb" false "abb" has the same set of letters as "aab" but not the same counts. Comparing sets says true.
"abc", "ccccbbbbaaaa" false Every letter of s1 is in s2, but never all three side by side.
"adc", "dcda" true "cda" at the end. The letters can be in any order, and a letter (d) can be outside the window too.
"a", "bcb" false Approach 3 only: if zeros isn't decreased when a letter stops agreeing, it climbs to 26 by mistake and says true.

Approach 1: Sort Every Window

Two strings are permutations of each other exactly when they sort to the same string. Sort s1 once, then sort every window of s2 with the same length and compare.

  • There are n − m + 1 windows (n = len(s2), m = len(s1)), so loop to n − m inclusive.
Time O((n − m) · m log m) Space O(m)

Simple, but every window is sorted from scratch. With random letters, m = 5000 and n = 10⁴, it took 2.0 s in Python here (0.16 s in C++).

Approach 2: Sliding Window of Counts

Compare letter counts instead of sorted strings. Count s1 into need and the first window into have. Sliding the window one step right adds s2[i] and removes s2[i − m]: two updates, not a recount.

  • Check have == need before each slide, and once more after the loop for the last window.
  • Lowercase letters only, so two arrays of 26 are enough.
Time O(26 · n) Space O(1)

Each comparison looks at all 26 counts, but that's a fixed cost: it ran as fast as Approach 3 here (about 1.3 ms in Python on 10⁴ letters). A perfectly good interview answer.

Approach 3: Sliding Window, Count the Matches Optimal

Skip the 26-way comparison. Keep one array, diff[c] = count in the window − count in s1, and zeros, how many letters have diff 0. The window is a permutation of s1 exactly when zeros == 26.

  • When a letter comes in or goes out, only its diff changes.
  • Before changing it: if it was 0, zeros −= 1. After: if it's now 0, zeros += 1.
  • As in Approach 2, check before each slide and once after the loop.
Time O(n) Space O(1)

Constant work per step, whatever the alphabet size. The same "how many counts agree" trick works for Find All Anagrams in a String (438) and Minimum Window Substring (76).

In practice Built-ins

In Python, collections.Counter is the count array: Approach 2 with any characters, not just a–z. C++ has std::is_permutation, but it's for one pair of ranges and can take O(m²) per window, so it doesn't help here. Java has nothing built in.

Time O(n · k), k = distinct letters Space O(k)

Passes every test here, about 3–7 ms on 10⁴ letters. A count can drop to 0 and stay in the Counter; == treats it as missing in Python 3.10 and later.
