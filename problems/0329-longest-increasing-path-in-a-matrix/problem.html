329. Longest Increasing Path in a Matrix Hard Dynamic Programming Memoization Topological Sort
Key idea: Moving only to strictly bigger neighbours can never loop back, so the grid is a DAG and the longest path from a cell never changes. Remember it: longest(r, c) = 1 + max over bigger neighbours, worked out once per cell with a DFS. O(m·n). Without the memo the same paths are walked again and again, which is exponential.

Problem View on LeetCode (opens in a new tab) ↗

Return the length of the longest path of cells in which each value is strictly bigger than the one before. You can move up, down, left or right, not diagonally or off the grid.

  • 1 <= m, n <= 200, 0 <= matrix[i][j] <= 2³¹ − 1

Example: [[9,9,4],[6,6,8],[2,1,1]] → 4 (1 → 2 → 6 → 9). [[3,4,5],[3,2,6],[2,2,1]] → 4 (3 → 4 → 5 → 6).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
12 × 12 with matrix[r][c] = r + c 23 Very many increasing paths overlap. The DFS without a memo took 5.9 s in Python; with the memo, 0.1 ms.
200 × 200 snake: 0, 1, 2, … back and forth 40000 One path through every cell: the memoized DFS goes 40,000 calls deep. It worked here with Python's limit raised, and with Java's and C++'s default stacks.
[[7,7],[7,7]] 1 Equal values don't count as increasing.

Approach 1: DFS From Every Cell, No Memo

From each cell, try every bigger neighbour and keep the longest result. Nothing is remembered, so a cell's answer is worked out again every time a path reaches it.

  • Correct, and fine on small or random grids.
  • Exponential when many increasing paths overlap.
Time exponential at worst Space O(m·n) call stack

The r + c grid in Python: 10 × 10 took 0.42 s, 11 × 11 1.5 s, 12 × 12 5.9 s, about 4 times longer per extra row and column.

Approach 2: Peel Layers (Topological Sort)

Count each cell's bigger neighbours. Cells with none are peaks (every path ends at one): that's the first layer. Peel it; each smaller neighbour loses a bigger neighbour, and those that reach 0 form the next layer. The number of layers is the answer.

  • Kahn's algorithm on the grid. No recursion at all.
Time O(m·n) Space O(m·n)

200 × 200 random: Python 80 ms, Java 2.7 ms, C++ 1.4 ms, 1.2 to 2.2 times the time of Approach 3.

Approach 3: DFS + Memo Optimal

The same DFS as Approach 1, but store longest(r, c) the first time it's worked out. Because values strictly increase along a path, a call can never come back to a cell that's still being worked out.

  • No visited set is needed: the "strictly bigger" rule already rules out loops.
Time O(m·n) Space O(m·n)

200 × 200 random: Python 36 ms, Java 1.6 ms, C++ 1.2 ms, the fastest in every language.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write; Approach 2 if deep recursion is a worry.
