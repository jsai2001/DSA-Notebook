50. Pow(x, n) Medium Math Recursion
Key idea: Don't multiply n times. Read n in binary: keep squaring x (x, x², x⁴, x⁸, …) and multiply it into the result whenever the current bit of n is 1. That's one round per bit: O(log n), at most 32 rounds. For negative n, use 1/x and −n, and keep −n in a 64-bit integer, because −(−2³¹) doesn't fit in an int.

Problem View on LeetCode (opens in a new tab) ↗

Implement pow(x, n): x raised to the power n.

  • -100.0 < x < 100.0, and n is a 32-bit integer (-2³¹ <= n <= 2³¹ − 1).
  • Either x isn't 0 or n is positive, and -10⁴ <= xⁿ <= 10⁴.

Examples: x = 2.00000, n = 10 → 1024.00000; x = 2.10000, n = 3 → 9.26100; x = 2.00000, n = -2 → 0.25000.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
x = 5, n = 0 1 Anything to the power 0 is 1: the loop must not run, and the result must start at 1, not x.
x = 2, n = -2 0.25 Negative n means 1 / x^|n|. Forgetting it, or using integer division, gives 4 or 0.
x = -2, n = 3 / n = 2 -8 / 4 A negative base: the sign depends on whether n is odd.
x = 0, n = 5 0 A zero base with positive n is allowed (0 with n ≤ 0 isn't).
x = 2, n = -2147483648 0 −n = 2³¹ doesn't fit in an int. In Java it stays −2³¹, the loop is skipped and you get 1.0; in C++ it's undefined behaviour (the checker here stops with "negation of -2147483648 cannot be represented"). Use long.
x = 1, n = -2147483648 1 The same −2³¹, where a wrong answer of 1.0 happens to be right: test with x = 2 as well.
x = -1, n = 2147483647 -1 The largest n: multiplying one at a time is 2.1 billion multiplications.
x = 0.00001, n = 2147483647 0 The true value is far below the smallest double, so the answer rounds to 0. Squaring underflows to 0 early and stays there; that's fine.

Approach 1: Multiply n Times

The definition: start at 1 and multiply by x, |n| times. For negative n, first turn x into 1/x.

  • Negate n into a 64-bit integer, so n = −2³¹ works.
Time O(|n|) Space O(1)

Correct but far too slow for a 32-bit n: one call with n = 2³¹ − 1 took 2.8 s in optimised C++ here, and about a minute in Python.

Approach 2: Recursive Halving

x^n = (x^(n/2))² when n is even, and (x^(n/2))² × x when n is odd. So work out the half once, square it, and the exponent halves at every level.

  • Base case: x^0 = 1.
  • Store the half in a variable. Calling power(x, n / 2) twice brings back O(n): for n = 2²⁰ it made 4,194,303 calls here instead of 22.
Time O(log n) Space O(log n) call stack

At most 33 levels deep, so the recursion is never a problem. The same idea as merge sort's "solve half, combine".

Approach 3: Binary Exponentiation Optimal

Write n in binary, for example 13 = 1101₂ = 8 + 4 + 1, so x¹³ = x⁸ · x⁴ · x¹. Walk the bits from the lowest: keep squaring x so it is x^(2^k) at bit k, and multiply it into the result when that bit is 1.

  • if n & 1: result *= x, then x *= x and n >>= 1.
  • No recursion: the same O(log n) work in a loop with O(1) memory.
  • Rounding: each squaring's tiny error gets raised to the remaining power. With |x| within about 10⁻⁸ of 1 and n near 2³¹, the answer was off by up to 2.3 × 10⁻⁷ (relative) here. The library pow stayed within 2 × 10⁻¹⁶. On 105,334 ordinary inputs (|n| ≤ 60) the worst error was 1 × 10⁻¹⁴.
Time O(log n) Space O(1)

The expected answer. The same loop computes powers modulo a number (a^b mod m), which shows up in many other problems.

In practice Built-ins

Every language has it: Python's x ** n (or pow), C++'s std::pow, Java's Math.pow. They handle negative exponents and n = −2³¹ on their own, because n is converted to a floating-point number.

Time O(1) Space O(1)

The most accurate option: within 2 × 10⁻¹⁶ of the exact value on all 4,168 test cases here. But the problem asks you to implement pow, so in an interview write Approach 3.
