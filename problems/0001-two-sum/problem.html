1. Two Sum Easy Array Hash Map
Key idea: For each number, look up its complement target - num in a hash map of values already seen. One pass, O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target.

  • Exactly one valid answer exists.
  • You can't use the same element twice.
  • Return the answer in any order.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
nums = [2, 7], target = 9 [0, 1] Smallest input: only two numbers, so the answer is both.
nums = [3, 2, 4], target = 6 [1, 2] 3 + 3 = 6, but there's only one 3. Don't pair an element with itself.
nums = [3, 3], target = 6 [0, 1] The same value twice is fine. With a hash map, check for the complement before storing the current number.
nums = [-3, 4, 3, 90], target = 0 [0, 2] Negative numbers and a target of 0.
nums = [0, 4, 3, 0], target = 0 [0, 3] Zeros: the answer is two equal values at the far ends.
nums = [5, 1, 2, 3, 9], target = 14 [0, 4] The pair is the first and last element: don't stop early.
nums = [-10⁹, 999999999, 1], target = 10⁹ [1, 2] Largest values: target - nums[0] is 2×10⁹. That still fits in a 32-bit int (max 2,147,483,647), so no overflow.

Approach 1: Brute Force

Check every possible pair (i, j) with j > i and return the first pair whose sum equals the target.

Time O(n²) Space O(1)

Outer loop runs n times, inner loop about n/2 on average, so it's quadratic and can hit Time Limit Exceeded on large inputs. No extra data structures.

Approach 2: One-Pass Hash Map Optimal

Instead of rescanning earlier elements, remember them in a hash map of {value: index}. At each index i, compute complement = target - nums[i].

  • If the complement is already in the map, return [map[complement], i].
  • Otherwise, store nums[i] → i and keep going.
Time O(n) Space O(n)

Single pass, and hash map lookups and inserts are O(1) on average. In the worst case (pair at the very end) the map holds up to n elements.

In practice No shortcut

No language has a built-in for "find two numbers that add up to a target". The closest is Python's itertools.combinations(range(len(nums)), 2), but that's just the brute force in disguise: up to about 5 × 10⁷ pairs at n = 10⁴, so it can time out.

The one-pass hash map (Approach 2) is already what you'd write day to day: a dict and a loop.
