647. Palindromic Substrings Medium String Dynamic Programming Two Pointers
Key idea: Every palindrome has a middle: a letter, or the gap between two letters. Try all 2n − 1 middles and grow outward while the two ends match. Each step outward is one more palindrome. O(n²) time, O(1) memory.

Problem View on LeetCode (opens in a new tab) ↗

Count the substrings of s that are palindromes. A substring is a run of letters next to each other. Substrings at different positions count separately, even if they're the same text.

  • 1 <= s.length <= 1000
  • s is lowercase English letters

Example: "abc" → 3 (a, b, c). "aaa" → 6 (a, a, a, aa, aa, aaa).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"aaa" 6 Same text at different positions counts twice ("a" three times, "aa" twice). Growing only from letters (odd lengths) missed the two "aa": said 4.
"abba" 6 The longest palindrome has even length, centered on a gap. Odd centers only said 4.
"abba" 6 In the table, pal[i][j] needs pal[i + 1][j - 1] first. Filling i from 0 upward read cells that weren't filled yet: said 5.
"a" 1 Every single letter is a palindrome, so the answer is at least n.
"abcdefgh" 8 All different: only the single letters.
"a" × 1000 500500 Every substring counts: n(n + 1) / 2, the largest answer. It still fits in a 32-bit int. Checking each substring with two pointers took 4.3 s in Python here.

Approach 1: Check Every Substring

For every pair i ≤ j, check s[i..j] with two pointers moving inward, and count the palindromes.

  • n(n + 1) / 2 substrings; each check is up to n / 2 comparisons.
  • On text with few repeats, most checks stop at the first pair, so it's much faster than the worst case.
Time O(n³) Space O(1)

On "a" × 1000 (worst case): Python 4.3 s, Java 0.1 s, C++ 49 ms. On random a–z letters, Python took only 26 ms: the checks end early.

Approach 2: Palindrome Table (DP)

pal[i][j] is true when s[i] == s[j] and the inside s[i+1..j-1] is a palindrome (or has 0–1 letters). Fill i from the end backwards so the inside is always ready, and count the true cells.

  • Each cell is O(1), so no substring is checked letter by letter.
  • The same table as Longest Palindromic Substring (5) and Palindrome Partitioning (131).
Time O(n²) Space O(n²)

A million cells at n = 1000. Python 54 ms, Java 7.5 ms, C++ 1.3 ms on "a" × 1000. Same speed on any text, since every cell is filled.

Approach 3: Expand Around Each Center Optimal

Take each of the 2n − 1 centers: the n letters (odd lengths) and the n − 1 gaps (even lengths). Grow lo left and hi right while s[lo] == s[hi], adding one to the count at each step.

  • lo = center // 2, hi = lo + center % 2 covers both kinds of center in one loop.
  • Stops as soon as the ends differ, so it does work only where palindromes are.
Time O(n²) Space O(1)

On "a" × 1000: Python 38 ms, Java 8.9 ms, C++ 0.27 ms. On random text it's under 1 ms even in Python. The expected answer. Manacher's algorithm does this in O(n), but it's rarely asked for.

In practice No shortcut

No standard library function counts palindromes. In Python, p == p[::-1] checks one substring, but using it for every substring is Approach 1 with extra copying.

Approach 3 is what you'd write: about eight lines and no extra memory.
