1143. Longest Common Subsequence Medium String Dynamic Programming
Key idea: Compare the last letters of the two prefixes. If they match, they're part of the answer: dp[i][j] = dp[i−1][j−1] + 1. If not, one of them is left out: dp[i][j] = max(dp[i−1][j], dp[i][j−1]). Fill the table row by row; each row needs only the row above, so one row of memory is enough.

Problem View on LeetCode (opens in a new tab) ↗

Return the length of the longest sequence of letters that appears in both texts in the same order (not necessarily side by side), or 0 if they share none.

  • 1 <= text1.length, text2.length <= 1000
  • Lowercase English letters only

Example: "abcde", "ace" → 3 ("ace"). "abc", "abc" → 3. "abc", "def" → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
"aca", "ca" 2 Greedy "match each letter of text1 at its first spot in text2" grabs the first a too early: it said 1. Wrong on 471 of 3006 tests.
"b", "bc" 1 On a mismatch, copying the diagonal (dp[i−1][j−1]) instead of the best of up and left forgets the match: it said 0.
"abc", "def" 0 Nothing in common.
two random 1000-letter texts - 10⁶ subproblems. The memoized recursion took 0.49 s in Python and goes up to 2000 calls deep.

Approach 1: Recursion with Memo

lcs(i, j) is the answer for text1[i:] and text2[j:]. Same first letter: 1 + lcs(i+1, j+1). Otherwise: max(lcs(i+1, j), lcs(i, j+1)). Remember each result.

  • Without the memo, the calls grow exponentially.
  • Only the pairs actually reached are worked out: when the texts are equal, it walks straight down the diagonal.
Time O(m·n) Space O(m·n) memo + O(m + n) call stack

Two random 1000-letter texts: Python 485 ms, Java 6.6 ms, C++ 9.9 ms. Two equal texts: Python 0.34 ms, because only 1000 pairs are reached.

Approach 2: DP Table

dp[i][j] is the LCS of the first i letters of text1 and the first j of text2. Row 0 and column 0 are 0. Each cell looks at the cell diagonally up-left (on a match) or the cells above and to the left.

  • No recursion; every cell is filled exactly once.
  • The table also lets you walk back from dp[m][n] to spell out the subsequence itself.
Time O(m·n) Space O(m·n)

Two random 1000-letter texts: Python 129 ms, Java 1.6 ms, C++ 3.2 ms.

Approach 3: One Row at a Time Optimal

Row i only needs row i − 1. Keep prev and build cur: diagonal is prev[j], up is prev[j + 1], left is cur[j]. Make the shorter text the row so it's as small as possible.

  • Same work as Approach 2, with 1001 numbers instead of a million.
  • You can't rebuild the subsequence itself from one row; use Approach 2 for that.
Time O(m·n) Space O(min(m, n))

Two random 1000-letter texts: Python 85 ms, Java 1.0 ms, C++ 2.5 ms, the fastest in every language (less memory to touch).

In practice No shortcut

Python's difflib.SequenceMatcher finds matching blocks, but it's a heuristic for diffs, not an exact LCS. No standard library computes the LCS length, so Approach 3 is what you'd write.
