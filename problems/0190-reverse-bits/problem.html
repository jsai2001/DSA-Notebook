190. Reverse Bits Easy Bit Manipulation Divide and Conquer
Key idea: Move bits one at a time: 32 times, take n & 1, push it onto res with res = (res << 1) | bit, and shift n right. Always do all 32 rounds, even after n is 0, because the leading zeros of n become the trailing zeros of the answer.

Problem View on LeetCode (opens in a new tab) ↗

Reverse the 32 bits of the integer n: bit 0 becomes bit 31, bit 1 becomes bit 30, and so on. Return the new number.

  • 0 <= n <= 2³¹ − 2, and n is even
  • Even means bit 0 is 0, so the answer's top bit is 0 and it fits in an int.

Example: 43261596 → 964176192. 2147483644 → 1073741822.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
2 1073741824 A loop that stops while n is non-zero runs only 2 rounds: it said 1. Wrong on all 10,004 inputs tried.
43261596 964176192 Reversing bin(n) without padding to 32 digits drops the leading zeros: it said 15065253.
0 0 No 1 bits at all.
2147483646 2147483646 31 ones then a 0: reversed, it's the same pattern. The biggest input.

Approach 1: Binary String, Reversed

Write n as exactly 32 binary digits, reverse the text, and parse it back in base 2.

  • The width 32 matters: the leading zeros are the bits that end up at the bottom.
  • It builds two 32-character strings each call.
Time O(1) (32 characters) Space O(1)

Average per call over 20,007 inputs: Python 0.47 µs (the fastest in Python, because the work happens inside C), C++ 0.28 µs, Java 0.65 µs, 6 to 13 times slower than the bit versions in C++ and Java.

Approach 2: Bit by Bit

32 rounds. Each round, n & 1 is the lowest bit of n. Shift res left and put that bit at its right end, then shift n right. The first bit taken ends up at the top after 31 more shifts.

  • Never stop early: the rounds after n becomes 0 are what move the bits up.
  • In Java use >>>, and in C++ an unsigned, so a shift never copies a sign bit.
Time O(1) (32 rounds) Space O(1)

Average per call: Python 2.6 µs (32 trips through the interpreter), Java 0.05 µs, C++ 0.05 µs. The answer most interviewers expect.

Approach 3: Swap Blocks With Masks Optimal

Reversing 32 bits is the same as swapping the two 16-bit halves and then reversing each half. Keep going: swap the bytes in each half, the 4-bit pieces in each byte, the pairs, and finally neighbouring bits. Each swap is one line: shift one way, shift the other, and keep the right blocks with a mask.

  • The masks are patterns: 0x55555555 is 0101…, 0x33333333 is 0011…, and so on.
  • 5 lines instead of 32 rounds: log₂ 32 = 5.
  • For the follow-up ("called many times"), a 256-entry table of reversed bytes is the other common answer.
Time O(1) (5 steps) Space O(1)

Average per call: Python 0.76 µs, Java 0.045 µs, C++ 0.04 µs, about the same as Approach 2 in C++ and Java. At this size the timer itself is a big part of what's measured.

In practice Built-ins

Java has Integer.reverse(n), which does the mask swaps of Approach 3 for you.

Time O(1) Space O(1)

Should pass on LeetCode (0.05 µs per call here). Python and C++ have no bit-reverse function. In Python, Approach 1 is the short way.

Comparison

Approach Technique Time Space Notes
