98. Validate Binary Search Tree Medium Tree DFS Binary Search Tree
Key idea: Checking each node against its own children is not enough: a node must be smaller than every ancestor it sits to the left of, and bigger than every one it sits to the right of. Pass those limits down: going left, the node's value becomes the new upper limit; going right, the new lower limit. Every value must be strictly inside its limits. O(n).

Problem View on LeetCode (opens in a new tab) ↗

Given the root of a binary tree, return true if it is a valid binary search tree (BST): for every node, all values in its left subtree are strictly smaller and all values in its right subtree are strictly bigger, and both subtrees are BSTs too.

  • 1 to 10⁴ nodes.
  • -2³¹ <= Node.val <= 2³¹ − 1: the full 32-bit int range.

Examples: [2,1,3] → true; [5,1,4,null,null,3,6] → false (4 is on the right of 5 but smaller than it).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[5,4,6,null,null,3,7] false Each node is fine next to its own children, but 3 sits on the right of 5 and is smaller. Checking only children says true.
[2,2,2], [1,null,1] false Equal values aren't allowed. Using <= instead of < says true.
[2147483647] true The biggest int is a fine value. Starting the upper limit at INT_MAX rejects it; start past it (a long, or infinity).
[-2147483648] true The smallest int. For the in-order check, starting prev at INT_MIN rejects it: use "no value yet" instead.
[1] true One node is always a BST.
[0,null,-1] false A right child smaller than its parent: the plainest failure.
10⁴ nodes in one line (each the right child of the last) true The tree is 10⁴ deep. Recursion goes 10⁴ calls deep, past Python's default limit of 1000; the iterative in-order walk doesn't recurse.

Approach 1: Check Each Node Against Its Whole Subtrees

Use the definition as it's written: for every node, collect every value in its left subtree and every value in its right subtree, and check they're all smaller or all bigger. Then check the subtrees the same way.

  • Correct, because it's exactly the rule.
  • But each value is collected again for every ancestor above it.
Time O(n²) on a tall tree (O(n log n) on a balanced one) Space O(n)

On a one-line tree it took 0.34 s in Python at 1000 nodes and 2.1 s at 2000; the Python version also copies lists, so it grows even faster. Too slow for 10⁴.

Approach 2: In-Order Walk, Values Must Go Up

An in-order walk (left subtree, node, right subtree) visits a BST's values in sorted order. So walk it and check that each value is bigger than the one before. The first time it isn't, the tree is not a BST.

  • Use a stack instead of recursion: push nodes while going left, pop one, check it, then go to its right child.
  • Keep only the previous value, and start with "none yet" (not INT_MIN, which is a real value here).
Time O(n) Space O(h) for the stack (h = height)

1.1 ms in Python for 10⁴ nodes, even in one line, and it stops at the first value out of order. No recursion, so no depth limit to worry about.

Approach 3: Recursion with Limits Optimal

Pass down the range each node must fit in. The root can be anything. Its left child must be below the root; that child's right child must be below the root and above the child; and so on.

  • check(node, low, high): fail if node.val isn't strictly between them.
  • Recurse left with (low, node.val) and right with (node.val, high).
  • In C++ and Java, use long limits so they can sit past the int range.
Time O(n) Space O(h) call stack

The answer interviewers expect: each node is checked once (1.5 ms for 10⁴ in Python), and the limits say exactly what the rule means. On a 10⁴-deep tree, Python needs sys.setrecursionlimit raised (LeetCode does this for you), or use Approach 2.

In practice No shortcut

No library checks a tree like this. Python, C++ and Java all need the walk written out.

Write Approach 3, and mention Approach 2 when the tree can be very deep. The three traps: check against all ancestors (not just children), use strict <, and keep the limits outside the int range.
