152. Maximum Product Subarray Medium Array Dynamic Programming
Key idea: Like Kadane's algorithm, but keep two numbers: the largest and the smallest product of a subarray ending here. A negative number turns the smallest (most negative) into the largest, so swap them before multiplying. Either can also start fresh at the current number. O(n), O(1).

Problem View on LeetCode (opens in a new tab) ↗

Find the contiguous, non-empty subarray of nums with the largest product, and return that product.

  • 1 <= nums.length <= 2 × 10⁴
  • -10 <= nums[i] <= 10
  • The product of any subarray fits in a 32-bit integer

Example: [2,3,-2,4] → 6 ([2,3]). [-2,0,-1] → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[-2,3,-4] 24 Two negatives make a positive. Keeping only the largest product (plain Kadane) said 3.
[-2] -2 The answer can be negative. Starting best at 0 said 0.
[-1,-4,-1,2,0] 8 Updating lo with the new hi instead of the old one said 32: bigger than any real product.
[-3,0,-3,2,-2,1,-2] 12 A zero splits the array. Prefix and suffix products that don't restart after it stay 0: said 8.
[-2,0,-1] 0 The best "product" is the zero itself.
2 × 10⁴ numbers - Checking every subarray is 2 × 10⁸ products: 0.2 s in C++; Python took 1.7 s for just 8,000.

Approach 1: Every Subarray

For each start i, extend the end j one step at a time, keeping a running product, and track the largest.

  • The running product avoids recomputing each subarray from scratch.
  • Start best at nums[0], not 0.
Time O(n²) Space O(1)

Python: 0.11 s at 2,000, 0.42 s at 4,000, 1.7 s at 8,000 (quadrupling each time). At n = 2 × 10⁴: C++ 0.2 s, Java 0.2 s. Too slow in Python.

Approach 2: Prefix and Suffix Products

Between zeros, if the count of negatives is even, the whole stretch is best. If it's odd, drop everything up to the first negative, or everything from the last one: the best is a prefix or a suffix. So scan products from the left and from the right, restarting after each zero, and take the largest seen.

  • left = (left or 1) * nums[i]: a 0 restarts the product at the next number.
  • Both directions in one loop.
Time O(n) Space O(1)

At 2 × 10⁴: Python 2.6 ms, Java 1.4 ms, C++ 0.04 ms. A neat trick, but it needs the "prefix or suffix" argument to be convincing.

Approach 3: Largest and Smallest Ending Here Optimal

For each x: if it's negative, swap hi and lo. Then hi = max(x, hi * x) and lo = min(x, lo * x): extend the best (or worst) subarray ending at the previous index, or start fresh at x. Keep the largest hi.

  • The swap is what makes both lines use the old values; otherwise save hi in a temporary first.
  • A zero makes both 0; the next number restarts them.
Time O(n) Space O(1)

At 2 × 10⁴: Python 2.3 ms, Java 1.6 ms, C++ 0.07 ms. The expected answer: the DP idea from Maximum Subarray (53), with one more value to carry.

In practice No shortcut

No standard library function finds the best subarray product. math.prod multiplies one subarray, but calling it on every subarray is O(n³).

Approach 3 is what you'd write: a loop and three variables.
