124. Binary Tree Maximum Path Sum Hard Tree DFS Dynamic Programming
Key idea: Every path has one highest node, where it bends. For each node, ask each child for its best path going down one side, dropping a side that's negative (max(0, …)). The path bending here is val + left + right: compare it with the best so far. Return only val + max(left, right) to the parent, since a path can't fork. O(n).

Problem View on LeetCode (opens in a new tab) ↗

A path is a chain of nodes, each joined to the next by an edge, with no node used twice. It doesn't have to go through the root. Return the biggest sum of values along any non-empty path.

  • 1 to 3 × 10⁴ nodes; -1000 <= Node.val <= 1000.
  • A path can be a single node.

Examples: [1,2,3] → 6 (2 → 1 → 3); [-10,9,20,null,null,15,7] → 42 (15 → 20 → 7).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[-3] -3 The path can't be empty. Starting the best at 0 says 0; start it at the root's value.
[-1,-2,-3] -1 Every value is negative: the answer is the single biggest node.
[1,-2,3] 4 Skip the −2 side: 1 → 3. Keeping negative sides (no max(0, …)) says 3.
[1,2,3,4,5] 11 4 → 2 → 5 bends at 2, then can't also go up to 1. Returning both sides to the parent says 15, a "path" that forks.
[-10,9,20,null,null,15,7] 42 The best path doesn't touch the root.
[10,9,-100,null,null,1,1] 19 9 → 10, leaving out a whole side whose best is −99.

Approach 1: Try Every Node as the Bend

For each node, imagine the path bends there. Its best value is the node plus the best way down on the left plus the best way down on the right (each at least 0). down(node) works out a way down from scratch.

  • down(node) = val + max(0, down(left), down(right)): a way down may stop at node.
  • Visit every node and keep the biggest.
Time O(n · h): every node's subtrees are measured again Space O(h)

94 ms on 3 × 10⁴ random nodes, but on a long line it's O(n²): 1.3 s at 4000 nodes, so roughly a minute at 3 × 10⁴.

Approach 2: One Walk, Best Gain Up Optimal

Do it all in one post-order walk. gain(node) returns the best path starting at node and going down one side. On the way, the node checks the path that bends at it, using both children's gains.

  • left = max(0, gain(left)), the same for right.
  • Update best with val + left + right.
  • Return val + max(left, right): the parent can extend only one side.
Time O(n) Space O(h) call stack

The answer interviewers expect (10 ms for 3 × 10⁴ nodes). The same "check here, return one side up" shape as Diameter of Binary Tree (543).

Approach 3: Post-Order with a Stack

The same work without recursion: each node goes on the stack twice. The second time, both children's gains are already stored, so check the bend and store its own gain.

  • A missing child has gain 0.
Time O(n) Space O(n) for the gains

16 ms for 3 × 10⁴ nodes. A tree that's one long line of 3 × 10⁴ nodes is 3 × 10⁴ deep, past Python's default recursion limit; this version doesn't care.

In practice No shortcut

No library finds paths in a tree like this, in Python, C++ or Java.

Write Approach 2. The three traps: start best at the root's value (not 0), drop negative sides, and send only one side up.
