217. Contains Duplicate Easy Array Hash Table Sorting
Key idea: Walk the array once with a hash set of the values seen so far. If the next value is already in the set, it's a repeat. O(n) time, O(n) space. Sorting first (repeats end up side by side) uses less memory but costs O(n log n).

Problem View on LeetCode (opens in a new tab) ↗

Return true if any value appears at least twice in nums, and false if every value is different.

  • 1 <= nums.length <= 10⁵
  • -10⁹ <= nums[i] <= 10⁹

Example: [1,2,3,1] → true. [1,2,3,4] → false.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[5] false One value: nothing to compare with.
10⁵ different values false No early exit. Comparing every pair is about 5 × 10⁹ checks: 1.4 s in Python for just 10⁴ values.
[-1,1] false Same size, different sign. A trick like an array indexed by abs(x) would say true.
values up to 10⁹ - Too big for a "seen" array indexed by value; use a hash set.

Approach 1: Compare Every Pair

For each i, compare nums[i] with every later value. Return true on the first match.

  • No extra memory, and the array isn't changed.
  • n(n − 1) / 2 comparisons when there's no repeat.
Time O(n²) Space O(1)

10⁴ different values: Python 1.4 s, Java 15 ms, C++ 16 ms. At 10⁵ it's 100 times more work: too slow for LeetCode.

Approach 2: Sort, Then Compare Neighbours

After sorting, equal values are next to each other. One pass checks each value against the one before it.

  • No hash set. The C++ and Java versions sort nums in place, so the caller's array changes.
Time O(n log n) Space O(1) extra in place (O(n) for Python's sorted)

10⁵ different values: Python 18 ms, Java 4.8 ms, C++ 1.9 ms. In C++ this beat the hash set (4.1 ms): sorting ints is fast, and the set allocates a node per value.

Approach 3: Hash Set Optimal

Keep a set of the values seen so far. For each value: if it's in the set, return true; otherwise add it. In C++ and Java, insert/add already says whether the value was new, so it's one call.

  • Stops at the first repeat.
  • Reserving room up front avoids rehashing as the set grows.
Time O(n) Space O(n)

10⁵ different values: Python 6.2 ms, Java 1.5 ms, C++ 4.1 ms. The fastest in Python and Java.

In practice Built-ins

Build a set of all the values and compare sizes: if the set is smaller, something repeated. In Java, Arrays.stream(nums).distinct().count() does the same.

Time O(n) Space O(n)

Should pass on LeetCode. Python's one-liner took 3.4 ms on 10⁵ values, faster than Approach 3, though it never stops early. Java's stream took 6.0 ms, slower than a plain HashSet loop.
