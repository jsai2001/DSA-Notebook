703. Kth Largest Element in a Stream Easy Heap (Priority Queue) Design Data Stream
Key idea: Only the k biggest values ever matter. Keep them in a min-heap of size k: push each new value, and if the heap has more than k, pop the smallest. The top is the k-th biggest. O(log k) per add, O(k) memory.

Problem View on LeetCode (opens in a new tab) ↗

Build KthLargest(k, nums). Each add(val) adds a value to the stream and returns the k-th largest value so far (counting repeats).

  • 0 <= nums.length <= 10⁴, 1 <= k <= nums.length + 1
  • At most 10⁴ calls to add; values are in [-10⁴, 10⁴]

Example: k = 3, nums = [4,5,8,2], then add 3, 5, 10, 9, 4 → 4, 5, 5, 8, 8.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
k = 1, nums = [], add 8140, 2362 8140, 8140 A min-heap that never trims back to k returns the smallest value instead: 8140, 2362. Wrong on 1944 of 2004 tests.
k = 1, nums = [] - The stream starts empty; the first add brings it to k values.
k = 4, nums = [7,7,7,7,8,3], add 2 7 Repeats count: the top four are 8, 7, 7, 7.

Approach 1: Sort on Every Add

Keep every value. On each add, append it, sort everything biggest first, and return position k − 1.

  • Memory keeps growing with the stream.
  • Python's sort (Timsort) finds the already-sorted run, so re-sorting after one append took 51 µs for 20,000 values, against 1.8 ms for a random list.
Time O(n log n) per add (less with Timsort) Space O(n)

10⁴ starting values, then 10⁴ adds, k = 5000: Python 450 ms, Java 197 ms, C++ 206 ms.

Approach 2: Sorted List, Binary Insert

Sort the starting values once. For each add, binary search for where the value goes and insert it there. The answer is the k-th value from the end.

  • The search is O(log n), but inserting shifts everything after it: O(n).
Time O(n) per add Space O(n)

Same test: Python 43 ms, Java 12 ms, C++ 9.4 ms.

Approach 3: Min-Heap of Size k Optimal

Push each value (starting ones too) into a min-heap, and pop whenever it holds more than k. What stays is the k biggest; the top is the smallest of them, which is the answer.

  • Values that are popped can never come back into the top k, so throwing them away is safe.
Time O(log k) per add Space O(k)

Same test: Python 6.9 ms, Java 3.6 ms, C++ 1.8 ms, the fastest in every language. With k = 1: C++ 0.15 ms.

In practice No shortcut

Approach 3 already uses the built-in heaps (heapq, priority_queue, PriorityQueue). That's what you'd write.
