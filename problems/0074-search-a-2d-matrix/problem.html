74. Search a 2D Matrix Medium Array Binary Search Matrix
Key idea: Each row is sorted and starts above the previous row's end, so read row by row, the matrix is one sorted list of m·n numbers. Binary search positions 0 … m·n − 1, and turn a position p into the cell (p // n, p % n), dividing by the row length n. O(log(m·n)).

Problem View on LeetCode (opens in a new tab) ↗

You're given an m × n integer matrix where each row is sorted in non-decreasing order, and the first number of each row is greater than the last number of the row before it. Return true if target is in the matrix. Aim for O(log(m·n)) time.

  • 1 <= m, n <= 100 and -10⁴ <= matrix[i][j], target <= 10⁴.
  • Values can repeat inside a row (non-decreasing), but never across rows.

Examples: [[1,3,5,7],[10,11,16,20],[23,30,34,60]] with target = 3 → true; with target = 13 → false.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[1]], 1 true One cell: lo = hi = 0. With while lo < hi the loop never runs and you return false.
[[1,3,5]], 5 true A single row. Turning a position into a cell with the number of rows (p // m) instead of the row length (p // n) reads row 1 on the first step, and there's only row 0: IndexError.
[[1,3]], 9 false Bigger than everything. With hi = m·n instead of m·n − 1, the search reads one past the end (IndexError).
[[1,3],[5,7]], 3 true The staircase walk must start at the top-right (or bottom-left). From the top-left, both moves make the value bigger, so there's no way to choose: it misses 3.
[[1,3],[5,7]], 5 true The target is a row's first value. Picking the row with "first value < target" (bisect_left) chooses the row before it and says false.
[[1,3,5]], 0 / [[1,3,5]], 4 false / false Smaller than everything, and between two values: the search has to end with nothing left, not a wrong neighbour.
[[1,1,1],[2,2,2]], 2 true Repeats inside a row are allowed; the flattened list is still sorted, so binary search still works.

Approach 1: Check Every Cell

Look at every value, row by row, and return true when one matches.

  • Correct for any matrix, sorted or not, because it doesn't rely on the order at all.
Time O(m·n) Space O(1)

At most 10⁴ cells, so it passes, but it ignores everything the problem tells you. About 0.2 ms per call on a full 100 × 100 in Python here, against about 0.003 ms for binary search.

Approach 2: Staircase from the Top-Right

At the top-right corner, everything to the left is smaller and everything below is bigger. If the value is too big, the rest of its column is bigger still: move left. If it's too small, the rest of its row is smaller still: move down. Each step drops a row or a column.

  • At most m + n − 1 steps before you walk off the matrix.
  • It only needs each row and each column sorted, so it also solves Search a 2D Matrix II (240), where binary search on the flattened list doesn't work.
Time O(m + n) Space O(1)

Easy to get right, and the version to remember for 240. Here it uses less than the problem gives you: it never needs "each row starts above the previous one".

Approach 3: Binary Search the Flattened Matrix Optimal

Number the cells row by row: position p is row p // n, column p % n. Because each row starts above the previous row's end, the values in that order are sorted, so an ordinary binary search over positions 0 … m·n − 1 works, without building the list.

  • Divide by n, the number of columns (the row length), not by m.
  • The usual binary search details: hi = m·n − 1, and loop while lo <= hi.
Time O(log(m·n)) Space O(1)

The expected answer: at most 14 cells looked at for a 100 × 100 matrix. Two binary searches (first the row, then inside it) cost the same, O(log m + log n) = O(log(m·n)); that's the built-in version below.

In practice Built-ins

Two library binary searches: find the last row whose first value is <= target, then search that row. Python's bisect_right takes a key since 3.10; C++ has std::upper_bound and std::binary_search; Java's Arrays.binarySearch searches the row, but the row itself has to be found with a short loop.

Time O(log m + log n) Space O(1)

All three pass every test here. Use bisect_right (first value <= target), not bisect_left: the target can be the first value of a row.
