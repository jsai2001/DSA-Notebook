202. Happy Number Easy Math Hash Table Two Pointers
Key idea: Replacing a number by the sum of the squares of its digits quickly gives small numbers, so the sequence must either reach 1 or repeat. Detect the repeat like a cycle in a linked list: slow takes one step, fast takes two, and they meet inside any loop. O(1) memory.

Problem View on LeetCode (opens in a new tab) ↗

Start with n and keep replacing it with the sum of the squares of its digits. n is happy if this reaches 1. Return whether it's happy.

  • 1 <= n <= 2³¹ − 1

Example: 19 → true (1² + 9² = 82 → 68 → 100 → 1). 2 → false (2 → 4 → 16 → … → 4 again).

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
2 false A loop that only stops at 1 never ends: it goes 4, 16, 37, 58, 89, 145, 42, 20, 4, …
19 true Floyd's check with slow = fast = n at the start stops before moving and says false. Wrong on 441 of n = 1 to 2999.
7 true A one-digit number other than 1 can still be happy: 7 → 49 → 97 → 130 → 10 → 1. "Stop at one digit" was wrong for 7, 1112, 1121, …
1 true Already 1, no steps needed.

Approach 1: Hash Set

Remember every number you meet. If you reach 1, it's happy. If you meet a number a second time, the sequence is in a loop that doesn't contain 1.

  • Why it always ends: a number with d ≥ 4 digits goes to at most 81·d, which is smaller. So it soon drops below 1000, and then it has to repeat or hit 1.
Time O(log n) per step, few steps Space O(number of steps)

Average over 23,007 inputs: Python 5.7 µs, C++ 0.80 µs, Java 0.32 µs. In C++ the set costs more than the digit work.

Approach 2: Stop at 4

There is only one loop: 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4. Every unhappy number falls into it, so loop until the number is 1 or 4.

  • Checked here: every n from 1 to 999 ends at 1 or in that loop, and bigger numbers always drop below 1000 first.
  • Fastest, but you have to know (or prove) the fact.
Time O(log n) per step Space O(1)

Average: Python 4.2 µs, C++ 0.10 µs, Java 0.15 µs, the fastest in every language.

Approach 3: Slow and Fast Pointers Optimal

Treat next(x) as a link, like a linked list. Start slow = n and fast = next(n). Each round, slow moves one step and fast two. If fast reaches 1, it's happy. If they meet, there's a loop without 1.

  • Start fast one step ahead (or move before checking), or the loop never runs.
  • No set and no special number: works without knowing the 4-loop fact.
Time O(log n) per step Space O(1)

Average: Python 6.1 µs, C++ 0.17 µs, Java 0.20 µs. Three next calls per round instead of one, and no memory.

In practice No shortcut

Nothing built in. Approach 1 is the easiest to explain; Approach 3 is the one interviewers usually look for.
