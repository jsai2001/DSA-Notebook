199. Binary Tree Right Side View Medium Tree Breadth-First Search Depth-First Search
Key idea: From the right you see the last node of each level, and it isn't always a right child: a left child shows when nothing is to its right. Either take the last node of each BFS level, or DFS right child first and keep the first node reached at each new depth.

Problem View on LeetCode (opens in a new tab) ↗

Standing on the right side of a binary tree, return the values you can see from top to bottom.

  • The number of nodes is in [0, 100]
  • -100 <= Node.val <= 100

Example: [1,2,3,null,5,null,4] → [1,3,4]. [1,2,3,4,null,null,null,5] → [1,3,4,5]. [] → [].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[1,2,3,4] [1,3,4] 4 is a left child but nothing is to its right. Walking only .right from the root said [1,3]; it was wrong on 2496 of 3307 tests.
[82,70,92] [82,92] The DFS visiting left before right gives the left side view: it said [82,70].
[] [] An empty tree: don't put None in the queue.
100 nodes, all left children all 100 values Every node is the only one on its level, so all of them show.

Approach 1: Store Every Level

Build the levels one after another: the next level is the children of this one, left to right. Keep all the values, then take the last one from each level.

  • Simple and correct, but it stores every value just to use one per level.
Time O(n) Space O(n)

Average over 3307 trees (up to 100 nodes): Python 3.0 µs, C++ 2.1 µs, Java 1.0 µs. The slowest in each language: it builds a new list per level.

Approach 2: BFS, Last of Each Level

Use a queue. At the start of each round it holds exactly one level, so note its size and pop that many nodes, pushing their children. The node popped at k == size − 1 is the rightmost.

  • Saving size first matters: the queue grows while you pop.
Time O(n) Space O(width)

Average: Python 2.0 µs, C++ 0.47 µs, Java 0.63 µs.

Approach 3: DFS, Right Child First Optimal

Walk the tree depth first, visiting the right child before the left, and carry the depth. The first node reached at a new depth (depth == len(res)) is the rightmost one there, because everything to its right was visited earlier.

  • len(res) is the number of depths seen so far, so no set is needed.
  • The calls go as deep as the tree: 100 at most here.
Time O(n) Space O(height)

Average: Python 2.6 µs, C++ 0.30 µs, Java 0.32 µs, the fastest in C++ and Java. In Python, function calls make it a bit slower than Approach 2.

In practice No shortcut

There's no built-in tree type to ask. Approach 2 or 3 is what you'd write; both are about ten lines.

Comparison

Approach Technique Time Space Notes
Store Every Level All levels, then the last of each O(n) O(n) Stores more than it needs
BFS, Last of Each Level Pop size nodes, keep the last O(n) O(width) Fastest in Python
DFS, Right Child First First node at each new depth O(n) O(height) Shortest code
