417. Pacific Atlantic Water Flow Medium Graph BFS DFS Grid
Key idea: Don't follow the water down from every cell. Go backwards: start at each ocean's edge cells and climb to neighbours that are equal or higher. Every cell reached can drain into that ocean. Two searches, then keep the cells both reached. O(m·n).

Problem View on LeetCode (opens in a new tab) ↗

heights is an island. The Pacific touches the top and left edges, the Atlantic the bottom and right edges. Rain flows from a cell to a neighbour (up, down, left, right) whose height is less than or equal, and from an edge cell into the ocean next to it. Return every [r, c] whose water can reach both oceans, in any order.

  • 1 <= m, n <= 200, 0 <= heights[r][c] <= 10⁵

Example: [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]] → [[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]. [[1]] → [[0,0]].

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
200 × 200, every height equal all 40,000 cells Water moves to equal heights too, so one search runs through every cell. The recursive DFS goes thousands of calls deep: in Java it threw StackOverflowError here with the default stack.
[[1,2,3]] all three cells One row touches all four edges: every cell is on both oceans.
A flat 5 area walled by 9s on the bottom and right only the wall cells The flat water reaches the Pacific but never climbs to the Atlantic, so a search from each cell walks the whole flat area every time.

Approach 1: Search Downhill From Every Cell

For each cell, spread to equal or lower neighbours and note whether the water touches a Pacific edge and an Atlantic edge. Stop early once it touches both.

  • The same cells are searched again for every start: nothing is shared.
Time O((m·n)²) Space O(m·n)

The walled flat grid: Python 4.5 s at 50 × 50 and 78 s at 100 × 100. At 200 × 200: C++ 9.0 s, Java 17 s.

Approach 2: Climb From the Oceans, DFS

Run a DFS from every Pacific edge cell, climbing to neighbours at least as high, into one shared visited set. Do the same for the Atlantic. The answer is the cells in both sets.

  • Each cell is visited at most once per ocean.
  • Recursion depth can reach m·n. Python here needs a raised limit.
Time O(m·n) Space O(m·n), including the call stack

200 × 200 random heights: Python 3.2 ms, Java 0.16 ms, C++ 0.09 ms. All equal: Python 99 ms, C++ 2.5 ms, Java crashed (stack overflow). Python 3.14 handled a 40,000-deep snake with the limit at 50,000.

Approach 3: Climb From the Oceans, BFS Optimal

The same reverse search with a queue: put all of an ocean's edge cells in at once (multi-source BFS) and climb outwards. Two BFS runs, then keep the cells both reached.

  • No recursion, so no stack limit to hit.
Time O(m·n) Space O(m·n)

200 × 200 random: Python 2.2 ms, Java 0.31 ms, C++ 0.07 ms. All equal: Python 48 ms, Java 1.8 ms, C++ 1.1 ms. The walled grid that took Approach 1 seconds: C++ 0.22 ms.

In practice No shortcut

Nothing built in. Approach 3 is what you'd write.
