138. Copy List with Random Pointer Medium Linked List Hash Table
Key idea: The hard part is random: it can point to a node whose copy doesn't exist yet. Either keep a map from each original node to its copy, or put each copy right after its original (A → A′ → B → B′), so the copy of X is always X.next. Then A′.random = A.random.next, and you split the two lists apart at the end.

Problem View on LeetCode (opens in a new tab) ↗

Each node of a linked list has next and also random, which points to any node in the list or to null. Return a deep copy: new nodes with the same values, where every next and random points to the matching new node.

  • 0 <= n <= 1000
  • -10⁴ <= Node.val <= 10⁴
  • The input is written as [val, random_index] per node, with null for no random pointer

Example: [[7,null],[13,0],[11,4],[10,2],[1,0]] → a new list written the same way.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[] [] An empty list: return null.
[[7,null],[13,0],[11,4],[10,2],[1,0]] same shape Copying random straight across (copy.random = node.random) makes the copies point at original nodes: not a deep copy.
[[7,null],[13,0]] same shape In the woven version, random can be null: node.random.next without a check raised AttributeError.
[[1,1],[2,1]] same shape A random pointer can point to the node itself (node 1 here).
[[3,null],[3,0],[3,null]] same shape Values repeat, so they can't identify nodes. Map nodes, not values.
any list, woven version original unchanged Splitting out only the copies leaves the original's next pointers aimed at copies. Put each node.next back during the split.

Approach 1: Map, Two Passes

Pass 1: make a copy of every node and store copies[original] = copy, without linking anything. Pass 2: link each copy, copy.next = copies[node.next] and copy.random = copies[node.random].

  • Making all the copies first means every random target already has a copy when it's linked.
  • Mapping None to None removes the null checks.
Time O(n) Space O(n) for the map

The clearest version. At n = 1000 here: Python 0.23 ms, Java 1.2 ms, C++ 0.11 ms.

Approach 2: Map, One Pass

Walk the list once. A helper copy_of(node) returns the node's copy, making it the first time it's asked for. For each node, set next and random of its copy through the helper.

  • A copy may be made early (a random pointing ahead) or reused (pointing behind); the map handles both.
  • Same idea as Clone Graph (133): record the copy as soon as it's made.
Time O(n) Space O(n) for the map

One pass, but more map lookups per node, so not faster: at n = 1000, Python 0.4–0.7 ms, Java 4.7–5.6 ms, C++ 0.09 ms.

Approach 3: Weave the Copies In Optimal

Three passes, no map. (1) Insert each copy right after its original: A → A′ → B → B′. (2) For each original X, set X′.random = X.random.next, since the copy of any node is the node right after it. (3) Unweave: point each original back at the next original, and each copy at the next copy.

  • The list itself stands in for the map: "copy of X" is just X.next.
  • Check X.random for null in step 2, and restore the original's next pointers in step 3.
Time O(n) Space O(1) besides the copy

Fastest here, since there's no hashing: at n = 1000, Python 0.2 ms, Java 0.4 ms, C++ 0.02 ms. The usual follow-up after the map version: "can you do it without extra memory?"

In practice Built-ins

Python's copy.deepcopy(head) copies the nodes and keeps random pointing at the right copies, since it keeps its own map from old object to copy. C++ and Java have no deep copy for linked objects.

It copied all 500 test lists correctly here, but it recurses along next: 200 nodes were fine, while 300 raised RecursionError, well under this problem's limit of 1,000. Write Approach 1 or 3.
