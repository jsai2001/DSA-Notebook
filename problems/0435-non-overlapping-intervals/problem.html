435. Non-overlapping Intervals Medium Intervals Greedy Sorting
Key idea: Removing the fewest means keeping the most. Sort by end and keep every interval that starts at or after the last kept end. The one that ends first always leaves the most room for the rest. O(n log n).

Problem View on LeetCode (opens in a new tab) ↗

Return the minimum number of intervals to remove so the rest don't overlap. Intervals that only touch, like [1,2] and [2,3], don't overlap.

  • 1 <= intervals.length <= 10⁵, -5·10⁴ <= start < end <= 5·10⁴

Example: [[1,2],[2,3],[3,4],[1,3]] → 1 (remove [1,3]). [[1,2],[1,2],[1,2]] → 2. [[1,2],[2,3]] → 0.

Edge cases

Try these against your solution before reading the approaches.

Input Expected Why it's tricky
[[-815,51],[-709,-254],[-218,487]] 1 Sorted by start, always keeping the earlier interval keeps the long [-815,51] and removes both others (2). Keeping the one that ends first is the fix. That bug was wrong on 416 of 2,506 tests.
[[1,2],[2,3]] 0 Touching ends are fine: compare with >=.
[[1,2],[1,2],[1,2]] 2 Equal intervals all overlap each other.

Approach 1: DP Over Sorted Intervals

Sort by start. keep[i] is the most intervals that fit together, ending with interval i: 1 plus the best keep[j] among earlier intervals that end by i's start. Remove everything else.

  • Like 300. Longest Increasing Subsequence, with "ends before it starts" as the order.
Time O(n²) Space O(n)

5,000 random intervals: Python 1.2 s, Java 44 ms, C++ 32 ms. LeetCode allows 10⁵.

Approach 2: Sort by Start, Drop the Later End

Sort by start and remember the end of the last interval kept. When the next one overlaps it, one of them has to go: drop the one that ends later, since it blocks more of what's to come.

  • Correct, but the reason is less direct than Approach 3's.
Time O(n log n) Space O(n) for the sort

10⁵ random intervals, average of 15 runs: Python 33 ms, Java 13 ms, C++ 6.0 ms. In Python, sort with key=lambda x: x[0]: plain sorted compares whole lists and took 73 ms.

Approach 3: Sort by End, Keep What Fits Optimal

Sort by end. Walk through and keep an interval whenever it starts at or after the end of the last one kept. The kept interval always ends as early as possible, which leaves the most room. Answer: n − kept.

  • The classic activity selection (interval scheduling) greedy.
Time O(n log n) Space O(n) for the sort

Same input: Python 24 ms, Java 13 ms, C++ 5.8 ms. The sort is most of the time, so Approaches 2 and 3 are close; this one is a little faster in Python.

In practice No shortcut

Nothing built in beyond the sort. Approach 3 is what you'd write.
